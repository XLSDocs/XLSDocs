RANK.EQ and RANK.AVG compute identical results on data with no
duplicate values — which is exactly why the difference between them
goes unnoticed for so long. The moment two scores tie, they stop
agreeing, and whichever one is already in the spreadsheet quietly
decides how that tie gets handled.

## No ties, no difference

<ExcelCode>{`=RANK.EQ(88, {95, 91, 88, 79, 72}) → 3
=RANK.AVG(88, {95, 91, 88, 79, 72}) → 3`}</ExcelCode>

On a list with five distinct scores, both functions rank 88 in 3rd
place, and every other value the same way. There's genuinely no
reason to prefer one over the other here — this is the case that
makes them look interchangeable.

## Then a tie happens

<ExcelCode>{`Scores: 95, 95, 88, 79, 72
=RANK.EQ(95, scores)  → 1
=RANK.AVG(95, scores) → 1.5`}</ExcelCode>

With two scores tied at 95, RANK.EQ gives **both** of them rank 1 —
the standard "competition ranking" every sports league uses, where
tied competitors share the better position and the next distinct
value skips ahead to account for it (88 becomes rank 3, not rank 2).
RANK.AVG instead gives both tied values **1.5**, the average of the
two positions (1 and 2) they'd occupy if you had to pick an order.

<Callout type="warn">
  RANK.AVG can introduce a decimal into what looks like — and is
  usually expected to be — a whole-number ranking column. If that
  rank number feeds into something expecting an integer (a lookup by
  position, an INDEX call), a silent `1.5` where `1` or `2` was
  assumed can produce a subtly wrong result further downstream.
</Callout>

## Which convention is actually "right"?

Neither — they're both valid, just built for different conventions.
RANK.EQ matches how almost every visible leaderboard works: two
runners tied for first both get a gold medal, and the next runner is
officially third, not second. RANK.AVG matches a convention more
common in statistics — some percentile-rank and grading calculations
specifically want tied values to split the difference rather than
both claim the better spot.

## The legacy function always matches RANK.EQ

Plain `RANK` (no suffix) predates both `.EQ` and `.AVG`, introduced
in Excel 2010 to make the tie-handling explicit in the function name
itself. `RANK` always computes the same result as `RANK.EQ` — never
`RANK.AVG` — so a spreadsheet built before 2010 that already uses
`RANK` doesn't need to change to get competition-style tie handling;
it's already doing that.
