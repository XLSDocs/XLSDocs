## Return value

The number of points in one repeating cycle of `values` — for
example, `4` for a clear quarterly-within-year pattern, or `1` if no
reliable seasonal pattern is found.

## Description

FORECAST.ETS.SEASONALITY looks for the shortest repeating pattern
length that best explains the up-and-down shape in `values`, after
accounting for any overall trend. This is a genuinely useful
diagnostic on its own — separate from actually forecasting anything —
for confirming a dataset really does have the seasonal shape it's
assumed to have, or for discovering a pattern length that wasn't
obvious just from eyeballing the numbers.

<Callout type="idea">
  `FORECAST.ETS.SEASONALITY(values, timeline)` is exactly the value
  `FORECAST.ETS` uses internally when its own `seasonality` argument
  is left at its default (auto-detect). Calling this function
  directly is a way to see that detected length explicitly, or to
  reuse it as the explicit `seasonality` argument in a separate
  `FORECAST.ETS` call.
</Callout>

## Common errors

### #N/A — timeline values aren't evenly spaced

<ExcelCode>{`FORECAST.ETS.SEASONALITY(values, timeline) → #N/A if timeline skips or doubles up an interval`}</ExcelCode>

`timeline` needs a consistent step size throughout, with at most one
missing point tolerated (interpolated per `data_completion`).

### Expecting a calendar unit instead of a period count

<ExcelCode>{`FORECAST.ETS.SEASONALITY(values, timeline) → 4, meaning every 4th data point, not "every 4 months" unless the data itself is monthly`}</ExcelCode>

The returned number counts data points in `values`, not any specific
calendar unit — a return value of 12 means "repeats every 12 rows,"
which is a yearly cycle if the data is monthly, but would mean
something entirely different on daily or quarterly data.
