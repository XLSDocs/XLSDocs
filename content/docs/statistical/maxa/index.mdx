Find the largest value in a list — but unlike plain `MAX`, text
counts as `0` and `TRUE` counts as `1` instead of being skipped
entirely.

## Return value

The largest value across everything included, where text counts as
`0` and `TRUE`/`FALSE` count as `1`/`0` — unlike `MAX`, which ignores
text and logical values entirely.

## Description

MAXA rarely differs from plain `MAX` in practice, since text always
counts as `0` and `TRUE` only counts as `1` — both are usually
smaller than whatever genuine numbers are already in the range. The
one case where it matters: a range of entirely small or negative
numbers, where a stray `TRUE` (counted as `1`) could actually become
the largest value MAXA reports, something MAX would never do since
it ignores `TRUE` altogether.

<Callout type="idea">
  MAXA and MAX return the same result far more often than not — the
  difference only shows up when a logical `TRUE` happens to be larger
  than every genuine number in the range, which is uncommon outside
  of small or negative-number datasets.
</Callout>

With the 5th value at `-3`, MAXA still returns `9` — the largest
genuine number in the set beats both `TRUE` (counted as `1`) and
`"Pass"` (counted as `0`). Raising the 5th value to `15` makes it the
new largest value.

## Common errors

### Expecting MAXA and MAX to always match

<ExcelCode>{`MAXA(-5, -3, TRUE) → 1, vs. MAX(-5, -3, TRUE) → -3`}</ExcelCode>

These diverge specifically when `TRUE` (counted as `1` in MAXA) is
larger than every genuine number in the range — a small or
all-negative dataset is where this is most likely to surface
unexpectedly.

### A text entry doesn't affect the result

Text always counts as `0` in MAXA, so it only changes the result if
every other value is negative — otherwise a text entry is silently
harmless to the final answer.
