Find where a number stands within a list, with a genuinely different
tie-handling rule than `RANK`/`RANK.EQ`: tied values share the
**average** of the ranks they'd otherwise occupy, instead of all
claiming the higher one.

## Return value

`number`'s position within `ref` once ranked. Tied values return the
**average** of the ranks they'd occupy — for example, two values tied
for 2nd place both return `2.5` (the average of 2 and 3), not `2`.

## Description

RANK.AVG answers the same "where does this stand" question as
`RANK.EQ`, but resolves ties differently: instead of giving every
tied value the better rank and skipping ahead afterward, it splits
the difference. Two values tied for 2nd place both get `2.5` — the
average of the 2nd and 3rd positions they're jointly occupying. On
data with no ties, RANK.AVG and RANK.EQ always agree; the difference
only shows up when values repeat.

<Callout type="warn">
  RANK.AVG can return a **decimal** rank whenever there's a tie —
  something RANK.EQ never does. If downstream logic expects a whole
  number (like indexing into a fixed set of positions), RANK.EQ is
  usually the safer choice.
</Callout>

## Common errors

### #N/A — number isn't actually in ref

<ExcelCode>{`RANK.AVG(999, {10,20,30}) → #N/A`}</ExcelCode>

`number` must be one of the values genuinely present in `ref`.

### Expecting a whole number

<ExcelCode>{`RANK.AVG(A2, B2:B10) → 2.5 when A2 is tied for 2nd place`}</ExcelCode>

Not an error, but a common surprise — unlike RANK.EQ, RANK.AVG
returns fractional ranks whenever ties exist. Round or switch to
RANK.EQ if a whole number is required.
