Forecast a future value from historical data using exponential
smoothing (ETS) — unlike `FORECAST.LINEAR`, it automatically detects
and projects **seasonal** patterns, not just a straight-line trend.

## Return value

The forecasted value at `target_date`, based on an exponential
smoothing model (Holt-Winters triple exponential smoothing when a
seasonal pattern is detected) fitted to `values` and `timeline`.

## Description

FORECAST.ETS fits a smoothing model that separately tracks a
**level**, a **trend**, and (when a repeating pattern is detected) a
**seasonal** component — then projects all three forward to
`target_date`. This is a meaningfully different model from
`FORECAST.LINEAR`'s single best-fit straight line: FORECAST.ETS can
correctly reproduce a saw-tooth seasonal pattern (holiday sales
spikes, weekday-vs-weekend traffic) that a plain linear trend would
average away entirely.

<Callout type="idea">
  This page's example uses **noise-free** historical data — every
  quarter lands exactly on an underlying trend-plus-season pattern,
  with nothing left to chance. That's a deliberate choice: it makes
  the forecast values below provably correct regardless of exactly
  how Excel's internal smoothing-parameter optimizer settles on its
  alpha/beta/gamma constants, since a perfect historical fit is
  achievable — and is the unique best fit — for any reasonable choice
  of those constants. Real-world data with actual noise will forecast
  correctly too, just without that same absolute guarantee on the
  precise decimal output.
</Callout>

## Common errors

### #N/A — timeline values aren't evenly spaced

<ExcelCode>{`FORECAST.ETS(target, values, timeline) → #N/A if timeline skips or doubles up an interval`}</ExcelCode>

`timeline` needs a consistent step size throughout (daily, weekly,
monthly, quarterly — any regular interval), with at most one missing
point tolerated (interpolated per `data_completion`).

### #NUM! — fewer than two complete seasonal cycles of history

<ExcelCode>{`FORECAST.ETS(target, values, timeline) → #NUM! if seasonality is being auto-detected from less than 2 full cycles of data`}</ExcelCode>

Auto-detecting a seasonal pattern requires enough historical data to
see it repeat at least twice — with only one visible cycle, either
supply more history or pass `seasonality = 1` to force a
non-seasonal, trend-only forecast instead.

    ```python lineNumbers
    from statsmodels.tsa.holtwinters import ExponentialSmoothing
    import pandas as pd

    sales = pd.Series([100, 125, 100, 105, 120, 145, 120, 125])
    model = ExponentialSmoothing(sales, trend="add", seasonal="add", seasonal_periods=4).fit()
    forecast = model.forecast(2)[-1]  # Q2 2026, two periods past the last forecasted point
    ```
