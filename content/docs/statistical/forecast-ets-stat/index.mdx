measure of forecast accuracy — from the exponential smoothing model
`FORECAST.ETS` builds internally.

## Return value

The requested statistic from the exponential smoothing model fitted
to `values` and `timeline` — its meaning depends entirely on
`statistic_type`.

## Description

FORECAST.ETS.STAT is a diagnostic window into the same model
`FORECAST.ETS` fits to produce a forecast, without needing a
`target_date` at all. `statistic_type` 1 through 3 return the model's
fitted smoothing constants (how heavily it weights recent data over
older data, for the level, trend, and seasonal components
respectively); 4 through 7 measure how well the fitted model actually
explains the historical data it was trained on, in four different
common error-measurement conventions; 8 returns the same seasonal
pattern length `FORECAST.ETS.SEASONALITY` detects directly.

<Callout type="warn">
  This page's `statistic_type` 4-7 examples use the same noise-free
  historical data as `FORECAST.ETS`'s own page — a dataset engineered
  so the fitted model reproduces every historical point exactly, with
  zero error. That's genuinely why every error statistic below reads
  0.0000, regardless of which smoothing constants Excel's optimizer
  actually settles on. The fitted alpha/beta/gamma constants
  themselves (`statistic_type` 1-3) aren't shown here: with a
  perfect historical fit, *any* smoothing constants achieve the same
  zero error, so there's no single "correct" value those types would
  return for this specific dataset — real, noisy data doesn't have
  this ambiguity.
</Callout>

MASE (type 4), MAE (type 6), and RMSE (type 7) all read exactly
0.0000 on this dataset — three different error-measurement conventions
unanimously agreeing the model's historical fit is perfect, which it
genuinely is for this deliberately noise-free example. Type 8, the
detected seasonality length, returns 4 — the same quarterly pattern
`FORECAST.ETS.SEASONALITY` finds directly. Real sales data never fits
as cleanly as the error stats show here; seeing them converge to zero
is really a demonstration of what a perfect fit looks like, not a
typical result.

## Common errors

### #N/A — timeline values aren't evenly spaced

<ExcelCode>{`FORECAST.ETS.STAT(values, timeline, 4) → #N/A if timeline skips or doubles up an interval`}</ExcelCode>

`timeline` needs a consistent step size throughout, with at most one
missing point tolerated (interpolated per `data_completion`).

### #NUM! — statistic_type is outside the 1-8 range

<ExcelCode>{`FORECAST.ETS.STAT(values, timeline, 9) → #NUM!`}</ExcelCode>

`statistic_type` only accepts whole numbers from 1 to 8.
