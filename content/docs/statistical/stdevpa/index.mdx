Calculate the population standard deviation across a list of values
— but unlike `STDEV.P`, text counts as `0` and `TRUE`/`FALSE` count
as `1`/`0` instead of being skipped entirely.

## Return value

The population standard deviation across everything included, where
text counts as `0` and `TRUE`/`FALSE` count as `1`/`0` — unlike
`STDEV.P`, which ignores text and logical values entirely.

## Description

STDEVPA is `VARPA`'s square root — it measures spread in the same
units as the original data, treating the values as a **complete
population** rather than a sample, while still applying the same
text-as-`0`, logical-as-`1`/`0` treatment.

<Callout type="idea">
  STDEVPA always comes out **smaller than or equal to** `STDEVA` on
  the same data, since it's built from VARPA (dividing by `n`) rather
  than VARA (dividing by `n − 1`) — the same relationship `STDEV.P`
  has to `STDEV.S`.
</Callout>

With the 5th value at `7`, STDEVPA returns `3.7417` — smaller than
`STDEVA`'s `4.1833` on the identical data, the square-root version of
the same `n` vs. `n − 1` gap that separates `VARPA` from `VARA`.

## Common errors

### Confusing STDEVPA's result with STDEVA's

<ExcelCode>{`STDEVPA("Pass",8,9,TRUE,7) → 3.7417, vs. STDEVA of the same range → 4.1833`}</ExcelCode>

These aren't meant to match — the two functions are built from
differently-divided variances, so they diverge on the same data.

### Using STDEVPA when the data is actually a sample

If the values represent a sample meant to estimate a larger
population, `STDEVA` is the statistically appropriate choice instead.

        if isinstance(v, bool): return 1 if v else 0
        if isinstance(v, (int, float)): return v
        if v is None: return None
        return 0

    values = [v for v in (to_a_value(v) for v in ["Pass", 8, 9, True, 7]) if v is not None]
