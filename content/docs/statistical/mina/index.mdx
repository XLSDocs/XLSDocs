Find the smallest value in a list — but unlike plain `MIN`, text
counts as `0` and `FALSE` counts as `0` instead of being skipped
entirely.

## Return value

The smallest value across everything included, where text counts as
`0` and `TRUE`/`FALSE` count as `1`/`0` — unlike `MIN`, which ignores
text and logical values entirely.

## Description

Because text and `FALSE` both count as `0` in MINA, a stray text
entry or logical value in an otherwise all-positive range often
becomes the new minimum — something MIN would never report, since it
skips both entirely. This is the opposite risk from MAXA: rather than
rarely mattering, MINA's text-as-`0` rule frequently changes the
result whenever every genuine number in the range happens to be
positive.

<Callout type="warn">
  A single stray text entry (a label, a typo, a placeholder like
  `"N/A"`) in an all-positive numeric range silently becomes MINA's
  result — `0` — which can look like a plausible-but-wrong answer
  rather than an obvious error.
</Callout>

With the 5th value at `7` or `15`, MINA still returns `0` — from
`"Pass"`, not from any genuine number, since every real value here is
positive. Only when the 5th value actually drops below `0` (to `-3`)
does a real number become the new minimum.

## Common errors

### The minimum is unexpectedly 0

Check the range for a stray text entry — it counts as `0` in MINA,
which becomes the reported minimum whenever every actual number in
the range is positive. If text should be excluded entirely instead,
`MIN` is the correct function.

### Expecting MINA and MIN to always match

<ExcelCode>{`MINA(5, 10, "N/A") → 0, vs. MIN(5, 10, "N/A") → 5`}</ExcelCode>

These diverge as soon as any text or `FALSE` value is present in an
all-positive range — check which function was actually intended
before trusting a suspiciously round `0`.
