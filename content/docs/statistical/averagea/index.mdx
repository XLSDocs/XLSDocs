Average a list of values — but unlike plain `AVERAGE`, text counts as
`0` and logical values count as `1` (`TRUE`) or `0` (`FALSE`) instead
of being skipped entirely.

## Return value

The average across every included value, where text counts as `0`
and `TRUE`/`FALSE` count as `1`/`0` — unlike `AVERAGE`, which skips
text and logical values entirely rather than counting them as
anything.

## Description

Plain `AVERAGE` ignores any cell that isn't a genuine number — a
text entry or a `TRUE`/`FALSE` doesn't affect the average at all,
and doesn't count toward the denominator either. AVERAGEA treats
every non-blank cell as participating: text becomes `0`, `TRUE`
becomes `1`, `FALSE` becomes `0`, and all of them count toward the
average's denominator, which usually pulls the result down compared
to AVERAGE on the identical range.

<Callout type="warn">
  AVERAGEA counting text as `0` means a stray label, comment, or
  typo'd entry in a numeric column can silently drag the average
  down — often the opposite of what's actually wanted. AVERAGE is
  usually the safer default unless logical values specifically need
  to count as 1/0.
</Callout>

`"Pass"` counts as `0` and `TRUE` counts as `1`. With the 5th value
at `7`, AVERAGEA returns `(0 + 8 + 9 + 1 + 7) / 5 = 5`. Plain
`AVERAGE` on the same range would ignore both non-numeric entries
entirely and return `(8 + 9 + 7) / 3 ≈ 8` — a very different result.

## Common errors

### The average is much lower than expected

Check the range for stray text entries — every one of them counts as
`0` in AVERAGEA, silently pulling the average down. If those cells
should be excluded entirely instead, `AVERAGE` is the correct
function.

### Confusing AVERAGEA's result with AVERAGE's

<ExcelCode>{`AVERAGEA({"Pass",8,9,TRUE,7}) → 5, vs. AVERAGE of the same range (ignoring "Pass" and TRUE) → 8`}</ExcelCode>

These treat non-numeric values completely differently and aren't
interchangeable on a range that contains any.
