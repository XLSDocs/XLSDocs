Find where a number stands within a list — the modern, explicitly-named
version of `RANK`, distinguished from `RANK.AVG` by how it handles
ties: tied values share the same (best) rank rather than an averaged
one.

## Return value

`number`'s position within `ref` once ranked. Ties receive the same
rank, and the rank after a tie skips ahead to account for it — the
"EQ" (equal) tie-handling behavior.

## Description

RANK.EQ computes exactly the same result as the older `RANK` — the
`.EQ` suffix was added in Excel 2010 alongside `RANK.AVG`, which
handles ties differently (averaging the tied positions instead of
giving them all the best one). On data with no ties, RANK, RANK.EQ,
and RANK.AVG all agree; they only diverge when two or more values are
identical.

<Callout type="info">
  RANK.EQ and RANK always return the same number on the same data.
  Reach for `RANK.AVG` instead when tied values should split the
  difference between the ranks they'd otherwise occupy, rather than
  all claiming the higher one.
</Callout>

## Common errors

### #N/A — number isn't actually in ref

<ExcelCode>{`RANK.EQ(999, {10,20,30}) → #N/A`}</ExcelCode>

`number` must be one of the values genuinely present in `ref`.

### Forgetting to lock ref when copying down

<ExcelCode>{`RANK.EQ(A2, B2:B10) → wrong ranks in every row after the first`}</ExcelCode>

Lock the reference so every row ranks against the same fixed list:

<ExcelCode>{`RANK.EQ(A2, $B$2:$B$10)`}</ExcelCode>
