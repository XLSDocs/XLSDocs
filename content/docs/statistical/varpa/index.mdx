Calculate the population variance across a list of values — but
unlike `VAR.P`, text counts as `0` and `TRUE`/`FALSE` count as
`1`/`0` instead of being skipped entirely.

## Return value

The population variance across everything included, where text
counts as `0` and `TRUE`/`FALSE` count as `1`/`0` — unlike `VAR.P`,
which ignores text and logical values entirely.

## Description

VARPA shares `VAR.P`'s population-variance formula (dividing by the
full count `n`), but folds text and logical values into the
calculation as `0`/`1`/`0` instead of excluding them. It's the
population counterpart to `VARA`, appropriate only when the values
being measured genuinely are the entire population, with nothing
left out.

<Callout type="idea">
  VARPA always comes out **smaller** than `VARA` on the same data,
  since dividing by `n` instead of `n − 1` produces a smaller result
  — the same relationship `VAR.P` has to `VAR.S`.
</Callout>

## Common errors

### Confusing VARPA's result with VARA's

<ExcelCode>{`VARPA("Pass",8,9,TRUE,7) → 14, vs. VARA of the same range → 17.5`}</ExcelCode>

These aren't meant to match — the two functions divide by different
denominators, so they diverge on the same data (more noticeably with
smaller datasets).

### Using VARPA when the data is actually a sample

If the values represent a sample meant to estimate a larger
population, `VARA` (dividing by `n − 1`) is the statistically
appropriate choice instead.

        if isinstance(v, bool): return 1 if v else 0
        if isinstance(v, (int, float)): return v
        if v is None: return None
        return 0

    values = [v for v in (to_a_value(v) for v in ["Pass", 8, 9, True, 7]) if v is not None]
