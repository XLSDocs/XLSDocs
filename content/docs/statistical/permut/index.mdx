Count how many different **ordered** arrangements are possible when
choosing a fixed number of items from a larger group — `COMBIN`'s
counterpart when the order of selection actually matters.

## Return value

The number of ways to choose and arrange `number_chosen` items from a
group of `number`, where order matters — mathematically, `number! /
(number − number_chosen)!`.

## Description

PERMUT answers "how many different ways can 1st, 2nd, and 3rd place
be awarded from a field of 5 runners?" style questions — situations
where both *which* items are chosen and the *order* they come in
matter. If order doesn't matter (just "which 3 runners," not their
finishing order), `COMBIN` is the function built for that instead.

<Callout type="warn">
  PERMUT counts **permutations**, not **combinations** — choosing 2
  items from a group of 3 has 3 combinations (`COMBIN(3,2)`) but 6
  permutations (`PERMUT(3,2)`), since {'{A, B}'} and {'{B, A}'} count
  as two separate outcomes here.
</Callout>

Arranging all 5 items in order has 120 possible sequences —
`PERMUT(5, 5)` equals `FACT(5)`, since every item has to be placed
somewhere and none are left out.

## Common errors

### #NUM! — number_chosen is negative or greater than number

<ExcelCode>{`PERMUT(5, 7) → #NUM!`}</ExcelCode>

`number_chosen` can't exceed `number` — there's no way to arrange 7
items when only 5 exist.

### Confusing PERMUT with COMBIN

<ExcelCode>{`PERMUT(3, 2) → 6, not 3`}</ExcelCode>

If the order of selection doesn't actually matter (just "which
items," not their sequence), `COMBIN` is the correct function —
`COMBIN(3,2)` returns `3`.
