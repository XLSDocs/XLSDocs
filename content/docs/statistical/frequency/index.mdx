Count how many values from a dataset fall into each of several
ranges ("bins") — the calculation behind a histogram, returning every
bin's count at once as a spilled array.

## Return value

An array of counts, one longer than `bins_array` — each element is
the number of `data_array` values falling into that bin, with the
final element counting everything above the last boundary.

## Description

Given bin boundaries like `{59, 69, 79, 89}`, FREQUENCY produces 5
counts: values `≤ 59`, values `60–69`, values `70–79`, values
`80–89`, and values `> 89` — always one more bin than there are
boundaries, since the boundaries only define where each bin *ends*,
leaving an open-ended final bin for everything above the last one.

<Callout type="warn">
  FREQUENCY always spills **one more value** than the number of bin
  boundaries supplied — a 4-boundary `bins_array` produces 5 counts,
  not 4. Selecting too few cells for the array (in older, pre-spill
  Excel versions entered with Ctrl+Shift+Enter) silently cuts off that
  last "everything above" bin.
</Callout>

## Common errors

### The last bin's count looks missing

<ExcelCode>{`FREQUENCY(scores, {59;69;79;89}) → spills 5 values, not 4`}</ExcelCode>

If only as many cells as there are boundaries were selected (a common
habit carried over from other array formulas), the final
"everything above the last boundary" count gets cut off. Select — or
let it spill into — one more cell than the number of boundaries.

### Counts don't add up to the total number of values

Double-check that `bins_array` is sorted in ascending order — an
out-of-order `bins_array` produces miscounted, overlapping-looking
bins rather than an error.

### #N/A from a legacy array-entry mistake

In pre-365/2021 Excel, FREQUENCY must be entered with
**Ctrl+Shift+Enter** into a pre-selected range of the correct size —
entering it as a normal formula returns only the first bin's count
instead of the full array.
