Estimate the sample variance across a list of values — but unlike
`VAR.S`, text counts as `0` and `TRUE`/`FALSE` count as `1`/`0`
instead of being skipped entirely.

## Return value

The sample variance across everything included, where text counts as
`0` and `TRUE`/`FALSE` count as `1`/`0` — unlike `VAR.S`, which
ignores text and logical values entirely.

## Description

VARA shares `VAR.S`'s sample-variance formula (dividing by `n − 1`),
but folds text and logical values into the calculation as `0`/`1`/`0`
instead of excluding them — both from the average it measures spread
around, and from the count of values contributing to that spread.
Mixing genuine numbers with text or logicals usually inflates VARA's
result compared to VAR.S on the identical range, since those
substituted values often sit far from the real data's own spread.

<Callout type="warn">
  Adding a text entry to an otherwise tightly-clustered positive
  numeric range can dramatically inflate VARA compared to VAR.S,
  since the text's substituted `0` often sits far outside where the
  real values cluster — check whether that inflation is actually
  intended before trusting a surprisingly large VARA result.
</Callout>

spread among the treated values, more variance.

## Common errors

### #DIV/0! — fewer than 2 non-blank values

VARA's formula divides by `n − 1`, which is zero with only 1
non-blank value (blank cells don't count toward `n`, but text and
logical values do).

### The result is much larger than VAR.S on the same range

Check for a text entry — VARA folds it in as `0`, which can pull the
calculated spread up substantially if the rest of the range's real
numbers are clustered elsewhere. `VAR.S` would exclude that same text
entry entirely.

        if isinstance(v, bool): return 1 if v else 0
        if isinstance(v, (int, float)): return v
        if v is None: return None
        return 0

    values = [v for v in (to_a_value(v) for v in ["Pass", 8, 9, True, 7]) if v is not None]
    result = np.var(values, ddof=1)  # sample variance
