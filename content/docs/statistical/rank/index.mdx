Find where a number stands within a list — 1st, 2nd, 3rd, and so
on — without manually sorting anything. The function behind
leaderboards, sales rankings, and "top performer" reports.

## Return value

`number`'s position within `ref` once ranked — `1` for the top
value (by default, the largest), `2` for the next, and so on. Ties
receive the same rank, and the rank after a tie skips ahead to
account for it.

## Description

RANK is a straightforward "where does this value stand" lookup — no
sorting required, since it computes the rank directly from the
unsorted list. It's most often copied down a whole column so every
row shows its own rank relative to the same fixed list. RANK is the
older name for what's now formally
[RANK.EQ](/docs/statistical/rank-eq).

<Callout type="warn">
  Ties share the same rank, and the **next** rank skips ahead to
  account for it — with two values tied for 2nd place, the next
  distinct value is ranked 4th, not 3rd. This matches how sports
  standings usually work, but surprises anyone expecting consecutive
  rank numbers.
</Callout>

just stated.

## Common errors

### #N/A — number isn't actually in ref

<ExcelCode>{`RANK(999, {10,20,30}) → #N/A`}</ExcelCode>

`number` must be one of the values genuinely present in `ref` — it
can't rank a value that isn't part of the list being ranked against.

### Forgetting to lock ref when copying down

<ExcelCode>{`RANK(A2, B2:B10) → wrong ranks in every row after the first`}</ExcelCode>

Without absolute references, `ref` shifts down along with `number`
as the formula is copied — lock it so every row ranks against the
same fixed list:

<ExcelCode>{`RANK(A2, $B$2:$B$10)`}</ExcelCode>

- [SMALL](/docs/math/small) — same idea as LARGE, for the low end
