Count how many columns a range or array spans — the horizontal
counterpart to ROWS, and the sizing half of COLUMN's position.

## Return value

The number of columns in `array`, as a single number — never an
array, regardless of how many columns the input has.

## Description

COLUMNS is ROWS turned sideways — instead of counting how tall a
range is, it counts how wide it is. It's used to validate that ranges
being combined (with HSTACK, for instance) share a compatible width,
or to check how many fields a table actually has without hardcoding
a number that goes stale as columns are added or removed.

<Callout type="warn">
  COLUMNS and COLUMN are easy to mix up by name alone, the same way
  ROWS and ROW are. `COLUMN(A1:C1)` answers "what column is this?"
  (position); `COLUMNS(A1:C1)` answers "how many columns is this?"
  (count, always `3` here).
</Callout>

## Common errors

### Confusing COLUMNS with COLUMN

<ExcelCode>{`COLUMNS(A1:C1) → 3, not a column position`}</ExcelCode>

If a column **number** was actually wanted instead of a count, COLUMN
is the right function:

<ExcelCode>{`COLUMN(A1) → 1`}</ExcelCode>

### Expecting COLUMNS to count only non-blank columns

COLUMNS counts every column within the reference's dimensions,
regardless of whether those columns actually contain any data — it
has no concept of "blank" the way COUNTA does for cells.

### Passing a value instead of a range

<ExcelCode>{`COLUMNS(5) → 1`}</ExcelCode>

A single value is treated as a 1-row, 1-column array, so COLUMNS
always returns `1` for it — not an error, but rarely the intended
input.
