Return the row number of a specific cell, or — with no argument at
all — the row number of the cell the formula itself is sitting in.
The building block behind self-numbering lists and dragged-down
sequential formulas.

## Return value

The row number of `reference` (or the formula's own cell, if
omitted) as a plain number — `1` for row 1, `2` for row 2, and so on.
Given a multi-row reference in a dynamic-array version of Excel, it
returns a spilled array of every row number in that range.

## Description

ROW without an argument is a self-aware trick: it returns whichever
row the formula is currently sitting in, which makes it useful for
generating a sequential number that survives being dragged, copied,
or moved (unlike typing `1`, `2`, `3` manually, which doesn't adjust
if a row gets inserted above). Paired with a fixed anchor
(`ROW()-ROW($A$1)+1`), it produces a counter that always starts at 1
regardless of which row the formula actually lives on.

<Callout type="info">
  `ROW(A1:A10)` behaves differently depending on the Excel version:
  in a dynamic-array version (365), it automatically spills the full
  array `{1;2;3;...;10}`. In a legacy, pre-dynamic-array version, the
  same formula (without being entered as an old-style Ctrl+Shift+Enter
  array formula) returns just `1` — the row of the first cell only.
</Callout>

## Common errors

### Expecting an array without Excel 365's dynamic arrays

<ExcelCode>{`ROW(A1:A10) → 1 (in a legacy, non-dynamic-array version of Excel)`}</ExcelCode>

Older Excel versions need this entered as a Ctrl+Shift+Enter array
formula to spill every row number — in 365, the same formula spills
automatically with no special entry required.

### Using ROW() alone as a counter, then having it break when sorted

<ExcelCode>{`ROW()-ROW($A$1)+1 → breaks if the anchor cell moves during a sort`}</ExcelCode>

Sorting a range can move the anchor cell along with the data,
throwing off the counter. For a sort-safe sequence, SEQUENCE is
usually a more robust choice than a ROW()-based counter.

### Confusing ROW (position) with ROWS (count)

`ROW(A1:A10)` in a legacy formula returns `1` — the position of the
first row. To find out **how many** rows are in a range instead, use
`ROWS(A1:A10)`, which returns `10`. The similar names are a common
source of mix-ups.
