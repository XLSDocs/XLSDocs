Search a range for a value and return its **position** within that
range, not the value itself. The complement to INDEX (which does the
reverse — position to value): together they form one of Excel's most
flexible lookup patterns.

<FunctionNav />

## Syntax

<ExcelCode>{`=MATCH(lookup_value, lookup_array, [match_type])`}</ExcelCode>

## Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `lookup_value` | any | Required | The value to search for. |
| `lookup_array` | range | Required | A single row or column to search — MATCH doesn't work across a 2D range. |
| `match_type` | number | Optional | `1` (default) largest value ≤ `lookup_value`, requires `lookup_array` sorted ascending · `0` exact match, any order · `-1` smallest value ≥ `lookup_value`, requires descending sort. |

## Return value

The 1-based position of `lookup_value` within `lookup_array` — a
number, not the matching value. Returns `#N/A` if no match is found.

## Description

MATCH searches `lookup_array` and returns where `lookup_value` sits,
counting from 1. On its own that position number isn't usually
useful — it becomes powerful wrapped inside INDEX, which turns "where
is it" into "what's there", or inside functions like VLOOKUP's
`col_index_num` to look up a column by header name instead of a
hardcoded number.

<Callout type="warn">
  `match_type` defaults to `1` (approximate match, requires ascending
  sort) if omitted — the same kind of default-argument trap as
  VLOOKUP's `range_lookup`. Most uses of MATCH want an exact match:
  pass `0` explicitly unless you specifically need a sorted,
  tiered lookup.
</Callout>

## Common errors

<ExcelCode>{`// #N/A – lookup_value isn't found in lookup_array
MATCH("Zzz", A1:A10, 0) → #N/A

// Wrong position, no error – match_type omitted or 1 on unsorted data
MATCH(85, A1:A10) → returns a plausible-looking but incorrect position

// Fix: pass 0 explicitly for an exact match
MATCH(85, A1:A10, 0)

// #N/A – lookup_array is a 2D range, not a single row or column
MATCH("Widget", A1:C10, 0) → #N/A`}</ExcelCode>

<Callout type="info">
  MATCH only searches a single row or a single column at a time. To
  search a full 2D table, use two MATCH calls — one for the row, one
  for the column — inside INDEX.
</Callout>

## Related functions

- [INDEX](/docs/lookup/index) — turns the position MATCH finds back
  into an actual value; almost always used together.
- [XLOOKUP](/docs/lookup/xlookup) — combines searching and returning
  into one function, largely replacing INDEX/MATCH in modern Excel.
- [VLOOKUP](/docs/lookup/vlookup) — a common place to nest MATCH,
  looking up `col_index_num` by header name instead of a fixed
  number.
- [IFERROR](/docs/logical/iferror) — wraps MATCH (or INDEX/MATCH
  together) to catch `#N/A` from a failed search.
