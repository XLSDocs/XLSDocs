Return the number of separate **areas** in a reference — where an
area is one contiguous block of cells. A single cell or range is
always one area; a reference deliberately built from several
disconnected pieces can have more.

## Return value

The number of contiguous blocks (areas) `reference` is made of —
`1` for an ordinary single range, more for a reference deliberately
built from several disconnected pieces separated by commas.

## Description

Most references in everyday Excel use are a single contiguous
block, so AREAS almost always returns `1`. It only becomes
interesting with a *union* reference — several separate ranges
combined into one, written with commas and wrapped in an extra pair
of parentheses so Excel doesn't read the comma as an argument
separator: `AREAS((B2:D4, E5, F6:I9))` returns `3`.

<Callout type="warn">
  **The extra parentheses are required for a multi-area reference.**
  `AREAS(B2:D4, E5)` (without the outer pair) is read as *two
  separate arguments*, not one two-area reference, and doesn't
  behave the way AREAS is meant to — it needs
  `AREAS((B2:D4, E5))` instead.
</Callout>

## Common errors

### Forgetting the extra parentheses for a multi-area reference

<ExcelCode>{`AREAS(B2:D4, E5) → wrong — this is two arguments, not one 2-area reference`}</ExcelCode>

Wrap the whole union in its own parentheses:
`AREAS((B2:D4, E5))` — now it's correctly read as a single,
two-area reference.

### Expecting AREAS to count cells, not areas

<ExcelCode>{`AREAS(A1:D10) → 1, not 40 — it counts contiguous blocks, not individual cells`}</ExcelCode>

For counting cells, use [COUNTA](/docs/math/counta) or
[COUNT](/docs/math/count) instead — AREAS only ever counts how many
separate blocks a reference is made of.
