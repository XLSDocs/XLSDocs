Return a reference to a range that's shifted a given number of rows
and columns from a starting point, optionally resized. Powerful for
building dynamic ranges, but volatile — it recalculates on every
sheet change, which can slow down a large workbook.

## Return value

A reference to a range `rows` rows and `cols` columns away from
`reference`, resized to `height` × `width` if those are supplied.
Since it returns a reference (not a plain value), OFFSET can be
wrapped in SUM, AVERAGE, or any function that expects a range.

## Description

OFFSET is most often used to build a range that shifts or grows
based on other cells — a rolling 12-month total that moves forward
each month, or a dynamic chart range. Modern alternatives (Excel
Tables, dynamic arrays) handle many of the same needs without
OFFSET's volatility cost, so it's worth checking whether one of
those fits before reaching for OFFSET in a new workbook.

<Callout type="warn">
  OFFSET is a **volatile function** — it recalculates every time
  *anything* changes anywhere in the workbook, not just when its own
  inputs change. A worksheet with many OFFSET formulas can become
  noticeably slower to edit as the workbook grows. INDEX is a
  non-volatile alternative for many of the same dynamic-range needs.
</Callout>

## Common errors

### #REF! — offsetting past the edge of the sheet

<ExcelCode>{`OFFSET(A1, -5, 0) → #REF! (there's no row above row 1)`}</ExcelCode>

Shifting beyond row 1 or column A (or past the last row/column)
throws `#REF!` — check the offset amount against the actual sheet
boundaries.

### Unexpected slowdown in a large workbook

Not an error, but a real performance issue — many OFFSET formulas
scattered through a large workbook force a full recalculation on
every edit. Consider INDEX-based alternatives if this becomes
noticeable.

## Related functions

- [INDEX](/docs/lookup/index) — returns a reference too, without
  OFFSET's volatility cost, for many of the same dynamic-range needs.
- [INDIRECT](/docs/lookup/indirect) — also builds a reference
  dynamically, but from a text string rather than a row/column shift.
- [MATCH](/docs/lookup/match) — often paired with INDEX/OFFSET to
  find the shift amount instead of hardcoding it.
