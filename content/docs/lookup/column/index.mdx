Return the column number of a specific cell — as a **number**, not
the letter shown on the column header — or, with no argument, the
column number of the cell the formula itself is sitting in.

## Return value

The column number of `reference` (or the formula's own cell, if
omitted) as a plain number — `1` for column A, `2` for column B, and
so on. Given a multi-column reference in a dynamic-array version of
Excel, it returns a spilled array of every column number in that
range.

## Description

COLUMN is ROW turned sideways — the same self-aware "which position
am I in" trick, just across columns instead of down rows. It's the
standard way to generate a horizontal sequence (`1, 2, 3...` across a
row) that survives being dragged or copied, and it's commonly paired
with CHOOSE or INDEX to pick a value based on which column a formula
happens to be sitting in.

<Callout type="warn">
  `COLUMN(A1)` returns `1`, not the letter `"A"` — expecting the
  actual column letter back is the single most common surprise with
  this function. Getting a letter requires wrapping the result (for
  example, `SUBSTITUTE(ADDRESS(1,COLUMN(A1),4),"1","")`), not a
  built-in option of COLUMN itself.
</Callout>

## Common errors

### Expecting a letter instead of a number

<ExcelCode>{`COLUMN(A1) → 1, not "A"`}</ExcelCode>

COLUMN always returns a number. To get the letter, use ADDRESS
combined with SUBSTITUTE, or a small LET-based helper formula.

### Confusing COLUMN (position) with COLUMNS (count)

`COLUMN(A1:C1)` in a legacy formula returns `1` — the position of
the first column. To find out **how many** columns are in a range
instead, use `COLUMNS(A1:C1)`, which returns `3`.

### Relying on COLUMN() for a counter that survives inserted columns

<ExcelCode>{`COLUMN()-COLUMN($A$1)+1`}</ExcelCode>

This anchored pattern is generally safe, but inserting a new column
between the anchor and the formula shifts both references together —
double-check the anchor is genuinely fixed with `$` if a column gets
inserted nearby.
