Count how many rows a range or array spans — not which row something
is on, but how many rows there are in total. The sizing half of
building a dynamic range, paired with ROW for position.

## Return value

The number of rows in `array`, as a single number — never an array,
regardless of how many rows the input has.

## Description

ROWS answers "how many rows" instead of "which row" — the count
behind sizing a dynamic named range, checking whether two ranges are
compatible sizes before combining them, or figuring out how far down
a table actually extends without hardcoding a row count that goes
stale as data is added.

<Callout type="warn">
  ROWS and ROW are easy to mix up by name alone. `ROW(A1:A10)`
  answers "what row is this?" (position); `ROWS(A1:A10)` answers "how
  many rows is this?" (count, always `10` here). Reaching for the
  wrong one produces a plausible-looking number that's actually
  answering the wrong question.
</Callout>

## Common errors

### Confusing ROWS with ROW

<ExcelCode>{`ROWS(A1:A10) → 10, not a row position`}</ExcelCode>

If a row **number** was actually wanted instead of a count, ROW is
the right function:

<ExcelCode>{`ROW(A1) → 1`}</ExcelCode>

### Expecting ROWS to count only non-blank rows

<ExcelCode>{`ROWS(A1:A100) → 100, even if most rows are empty`}</ExcelCode>

ROWS counts every row in the reference's dimensions, blank or not —
it isn't aware of which cells actually contain data. Use COUNTA for
a count of non-blank cells instead.

### Passing a value instead of a range

<ExcelCode>{`ROWS(5) → 1`}</ExcelCode>

A single value (not a range reference) is treated as a 1-row, 1-column
array, so ROWS always returns `1` for it — not an error, but rarely
the intended input.
