Pad `array` out to a larger, fixed size — adding extra rows,
columns, or both, filled with `pad_with` (`#N/A` by default). The
opposite of trimming: EXPAND only ever makes an array *bigger*,
never smaller.

## Return value

`array`, resized to exactly `rows` × `columns`, with every new cell
filled by `pad_with`. The original values keep their same relative
positions in the top-left corner of the result.

## Description

EXPAND is useful whenever a formula needs every output to be a
*fixed, predictable size*, even though the source array's size might
vary — padding a short list out to match a template's row count, for
instance, so downstream formulas referencing fixed cell positions
don't break when the source data shrinks.

<ExcelCode>{`=EXPAND(A1:B2, 4, 3) → the 2x2 range becomes 4 rows x 3 columns, with #N/A filling every new cell`}</ExcelCode>

<ExcelCode>{`=EXPAND(A1:B2, 4, 3, 0) → the same expansion, but new cells are filled with 0 instead of #N/A`}</ExcelCode>

<Callout type="warn">
  **EXPAND only grows — it never shrinks.** Passing a `rows` or
  `columns` value *smaller* than `array`'s own size returns
  `#VALUE!`, rather than truncating the array down to that size. For
  trimming an array smaller, [TAKE](/docs/arrays/take) or
  [TRIMRANGE](/docs/lookup/trimrange) do that instead.
</Callout>

## Common errors

### #VALUE! — a target size smaller than the source array

<ExcelCode>{`EXPAND(A1:D1, 1, 2) → #VALUE! (A1:D1 already has 4 columns; EXPAND can't shrink it to 2)`}</ExcelCode>

EXPAND's `rows`/`columns` must each be at least as large as
`array`'s own matching dimension.

### #NUM! — a target size that's too large

<ExcelCode>{`EXPAND(A1:B2, 1000000, 1000000) → #NUM! (exceeds Excel's worksheet size limits)`}</ExcelCode>

A `rows`/`columns` combination larger than the worksheet itself can
accommodate returns `#NUM!` instead of attempting the expansion.
