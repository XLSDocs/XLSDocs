Pull one specific summarized number out of a PivotTable by naming the
data field and the row/column items that identify it — instead of a
plain cell reference, which breaks the moment the PivotTable's layout
changes.

## Return value

The summarized value from `data_field` for the record matching every
`field`/`item` pair given. Returns `#REF!` if no such combination
exists in the current PivotTable.

## Description

Unlike a plain cell reference into a PivotTable (which points at a
fixed grid position), GETPIVOTDATA identifies data by name — the
field and the specific items being summarized. That means it keeps
returning the right number even after the PivotTable is resorted,
re-filtered, collapsed, or refreshed with new source data, as long as
the named field/item combination still exists somewhere in it.

<Callout type="warn">
  Excel often inserts GETPIVOTDATA **automatically**: typing `=` in a
  cell, then clicking a cell inside a PivotTable, produces a
  GETPIVOTDATA formula instead of a plain reference like `C5`. This
  surprises people expecting a normal reference. Turn it off via
  **Excel Options → Formulas → uncheck "Use GetPivotData functions
  for PivotTable references"** if a plain reference is what's wanted
  instead.
</Callout>

## Common errors

### #REF! — the field or item name doesn't match

<ExcelCode>{`GETPIVOTDATA("Sum of Sales", A3, "Region", "Wset") → #REF!`}</ExcelCode>

Field and item names must match the PivotTable's own labels exactly,
including spelling and capitalization of the summary label itself
(e.g. `"Sum of Sales"`, not `"Sales"`).

### #REF! — the item has been filtered or collapsed out of view

If a PivotTable filter currently hides the item being referenced (or
a row group is collapsed), GETPIVOTDATA can't find it and returns
`#REF!` even though the underlying data still technically exists.

### Formula breaks after the PivotTable is deleted or moved to a new sheet

`pivot_table` needs to keep pointing at a cell that's still inside the
actual PivotTable range. Deleting the PivotTable, or moving it far
enough that the reference no longer falls inside it, breaks the
formula.
