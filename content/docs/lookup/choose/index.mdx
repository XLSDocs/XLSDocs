Pick one value out of a fixed list based on its position — the 1st,
2nd, 3rd, and so on. A simple alternative to nested IF statements
when there's a small, known set of options tied to a number.

## Return value

The value at position `index_num` in the list. Returns `#VALUE!` if
`index_num` is less than 1 or greater than the number of values
supplied.

## Description

CHOOSE picks from a fixed, small list of options by position — a
day-of-week name from a weekday number, a tier label from a rank, or
a discount rate from a category code. For more than a handful of
options, or when the values come from a table rather than being
typed inline, IFS or a lookup function is usually a better fit.

<Callout type="info">
  `index_num` is **1-based** — `CHOOSE(1, "A", "B", "C")` returns
  `"A"`, not `"B"`. This trips up anyone used to 0-based indexing
  from a programming language.
</Callout>

## Common errors

### #VALUE! — index_num out of range

<ExcelCode>{`CHOOSE(5, "A", "B", "C") → #VALUE! (only 3 values exist)`}</ExcelCode>

`index_num` can't exceed the number of values actually supplied.

### Off-by-one from 0-based thinking

<ExcelCode>{`CHOOSE(0, "A", "B", "C") → #VALUE!`}</ExcelCode>

`index_num` starts at `1`, not `0` — there's no "zeroth" value to
return.

## Related functions

- [IFS](/docs/logical/ifs) — branches on conditions instead of a
  fixed numeric position.
- [SWITCH](/docs/logical/switch) — compares one value against a list
  of exact matches, closer to CHOOSE's shape but keyed by value
  rather than position.
- [INDEX](/docs/lookup/index) — looks up a value by position within
  a range, rather than a hardcoded list of literals.
- [LAMBDA](/docs/custom-functions/lambda) — CHOOSE is a common
  building block inside a LAMBDA's calculation, e.g. converting a
  month number into a quarter label.
