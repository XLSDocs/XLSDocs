Evaluate a formula, and if — and only if — it returns `#N/A`, return
a fallback value instead. The narrower sibling of IFERROR: it leaves
every other error type (`#VALUE!`, `#REF!`, `#DIV/0!`) to surface
normally.

## Return value

The result of `value` if it isn't `#N/A`, otherwise `value_if_na`.
Any other error type (`#VALUE!`, `#REF!`, `#DIV/0!`, etc.) passes
through unchanged.

## Description

IFNA checks specifically for `#N/A` — the error VLOOKUP, XLOOKUP,
and MATCH return on a missing match — and replaces only that with a
fallback. Unlike IFERROR, it won't swallow an unrelated mistake
elsewhere in the formula, since anything other than `#N/A` still
surfaces as-is.

<Callout type="info">
  Use IFNA when a missing lookup is the *only* failure you expect and
  want to handle. Use IFERROR when any error type should fall back to
  the same value, accepting that it may also hide a genuine bug.
</Callout>

## Common errors

### Expecting IFNA to catch every error

<ExcelCode>{`IFNA(A2/B2, 0) → still shows #DIV/0! when B2 is 0`}</ExcelCode>

IFNA only catches `#N/A` — a `#DIV/0!` from a plain division error
passes straight through. Use IFERROR if you want every error type
caught.

### Missing the second argument

<ExcelCode>{`IFNA(VLOOKUP(A2, B:C, 2, FALSE)) → #VALUE! (wrong number of arguments)`}</ExcelCode>

Both arguments are required — always provide `value_if_na`, even if
it's just `""`.

## Related functions

- [IFERROR](/docs/logical/iferror) — the broader version, catching
  every error type instead of just `#N/A`.
- [XLOOKUP](/docs/lookup/xlookup) — its `if_not_found` argument covers
  the same missing-lookup case natively, without a separate wrapper.
- [VLOOKUP](/docs/lookup/vlookup) and [MATCH](/docs/lookup/match) —
  the most common sources of the `#N/A` that IFNA catches.
- [ISNA](/docs/info/isna) — the plain TRUE/FALSE test IFNA replaces
  for the "look this up, fall back if not found" pattern.
