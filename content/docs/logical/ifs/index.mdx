Check up to 127 conditions in order, and return the result for the
first one that's true — no nesting required. A flatter, more
readable alternative to a long chain of nested IF calls.

## Return value

`value_if_trueN` for the first `logical_testN` that evaluates to
`TRUE`, checked left to right. Returns `#N/A` if **none** of the
conditions are true.

## Description

IFS evaluates each condition in order and stops at the first one
that's true, returning its paired result. Unlike a nested IF chain,
there's no nesting to keep track of — each condition/result pair
sits at the same level, which stays readable even with several
conditions.

<Callout type="warn">
  Unlike nested IF, **IFS has no implicit "else"**. If none of the
  conditions match, it returns `#N/A` instead of a default value. Add
  a final `TRUE, "default"` pair at the end if you want a catch-all —
  `TRUE` always evaluates true, so it only fires when nothing earlier
  matched.
</Callout>

## Common errors

### #N/A — no condition matched

<ExcelCode>{`IFS(A2>90, "A", A2>80, "B") → #N/A (when A2 is 75)`}</ExcelCode>

None of the conditions were true, and there's no catch-all. Add a
final `TRUE, "default"` pair:

<ExcelCode>{`IFS(A2>90, "A", A2>80, "B", TRUE, "C or below")`}</ExcelCode>

### Wrong result from condition order

<ExcelCode>{`IFS(A2>60, "Pass", A2>90, "Pass with distinction") → "Pass" even when A2 is 95`}</ExcelCode>

Conditions are checked in order, and the first `TRUE` wins. Put the
more specific/restrictive condition first:

<ExcelCode>{`IFS(A2>90, "Pass with distinction", A2>60, "Pass")`}</ExcelCode>

<Callout type="idea">
  IFS checks conditions **in order** and stops at the first match —
  put the most specific condition first, the same way you'd order a
  nested IF chain. A broad condition placed too early will shadow
  every more specific one that follows it.
</Callout>

## Related functions

- [IF](/docs/logical/if) — the building block IFS replaces once
  nesting gets past 2-3 levels deep.
- [SWITCH](/docs/logical/switch) — compares one value against a
  fixed list of exact matches, shorter than IFS for that specific
  case.
- [IFERROR](/docs/logical/iferror) — catches a formula *error*;
  IFS branches on *conditions* instead, and needs an explicit
  `TRUE` default to avoid returning `#N/A`.

  orders of 100 or more ship free, since nothing above matched.
</ExampleCard>

<ExampleCard number="05" label="No default — deliberately returning #N/A" formula={`=IFS(A2="Yes", "Approved", A2="No", "Rejected")`}>
  Leaving out the final `TRUE` pair is sometimes intentional — here,
  any value other than "Yes"/"No" surfaces as `#N/A`, flagging bad
  input instead of silently guessing a default.
</ExampleCard>
