Return one value if a condition is true, and a different value (or
nothing) if it's false. The most fundamental branching function in
Excel, and the building block behind most "if this, then that" logic.

## Syntax

<ExcelCode>{`=IF(logical_test, value_if_true, [value_if_false])`}</ExcelCode>

## Return value

`value_if_true` or `value_if_false`, depending on `logical_test`. If
`value_if_false` is omitted and the condition is false, IF returns the
literal boolean `FALSE` — not an empty string.

## Description

IF evaluates `logical_test` and branches on the result. It can be
nested inside `value_if_true` or `value_if_false` to handle more than
two outcomes, though beyond two or three levels a nested IF chain
becomes hard to read — IFS or SWITCH are usually clearer at that point.

<Callout type="info">
  IF has no version requirement — it's available in every version of
  Excel, including very old ones, unlike newer functions like IFS or
  XLOOKUP.
</Callout>

## Common errors

### Returns FALSE unexpectedly

<ExcelCode>{`IF(A2>100, "High") → FALSE (when A2 is not greater than 100)`}</ExcelCode>

`value_if_false` was omitted. Always provide it, even if it's just
`""`:

<ExcelCode>{`IF(A2>100, "High", "")`}</ExcelCode>

### #NAME? — unquoted text condition

<ExcelCode>{`IF(A2=Yes, "OK", "No") → #NAME?`}</ExcelCode>

Text values being compared need quotes:

<ExcelCode>{`IF(A2="Yes", "OK", "No")`}</ExcelCode>

### Deeply nested IF chains

<ExcelCode>{`IF(A2>=90,"A",IF(A2>=80,"B",IF(A2>=70,"C",IF(A2>=60,"D","F"))))`}</ExcelCode>

Technically correct, but hard to read and maintain past 2-3 levels.

<Callout type="info">
  A nested IF chain with more than 2–3 levels is a sign to switch to
  IFS (one condition/result pair per argument, no nesting) or SWITCH
  (for matching against a fixed list of exact values).
</Callout>

## Related functions

- [IFS](/docs/logical/ifs) — checks several conditions in order
  without nesting, returning the first true match's result.
- [SWITCH](/docs/logical/switch) — compares one value against a list
  of exact matches, similar to a switch statement in code.
- [IFERROR](/docs/logical/iferror) — returns a fallback value when a
  formula errors, instead of branching on a true/false condition.
- [AND](/docs/logical/and) — often nested inside IF's condition to
  require more than one thing to be true at once.
- [OR](/docs/logical/or) — often nested inside IF's condition to
  match any one of several acceptable values.
- [XLOOKUP](/docs/lookup/xlookup) — its `if_not_found` argument covers
  a common IF+IFERROR use case (missing-lookup fallback) natively.
