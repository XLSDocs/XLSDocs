Compare a single value against a list of exact matches, and return the
result for the first one that fits — no repeated comparisons against
the same expression like a nested IF chain needs.

## Return value

`resultN` for the first `valueN` that exactly matches `expression`, or
`default` if none match. Returns `#N/A` if nothing matches and no
`default` was provided.

## Description

SWITCH evaluates `expression` once, then compares it against each
`valueN` in order for an exact match. It's a shorter alternative to
IFS or nested IF specifically when every branch compares the *same*
value against a fixed list of exact options — a job IFS can also do,
but SWITCH does with less repetition since `expression` is only
written once.

<Callout type="warn">
  SWITCH only tests for **exact equality** — it can't evaluate a
  comparison like `A2 > 100`. For conditions like that, use IFS
  instead.
</Callout>

## Common errors

### #N/A — no match and no default

<ExcelCode>{`SWITCH(A2, "West","W","East","E") → #N/A (when A2 is "North")`}</ExcelCode>

Add a trailing `default` argument to catch anything that doesn't
match:

<ExcelCode>{`SWITCH(A2, "West","W","East","E","Unknown")`}</ExcelCode>

### Trying to use a comparison instead of a value

<ExcelCode>{`SWITCH(A2, ">100","High") → doesn't work the way you'd expect`}</ExcelCode>

SWITCH tests for exact equality only — `">100"` is compared as
literal text, not evaluated as a condition. Use IFS for range/
comparison conditions.

<Callout type="info">
  SWITCH checks values **in order** and stops at the first exact
  match, the same as IFS does with conditions.
</Callout>

## Related functions

- [IFS](/docs/logical/ifs) — better fit when branches need independent
  conditions rather than exact matches against one value.
- [IF](/docs/logical/if) — the fundamental branching function both IFS
  and SWITCH build on.
- [IFERROR](/docs/logical/iferror) — wraps SWITCH to catch `#N/A` from
  an unmatched value, as an alternative to a trailing `default`.
