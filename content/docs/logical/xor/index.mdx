Return `TRUE` when an **odd number** of the given conditions are
`TRUE`, and `FALSE` when an even number are (including zero) — the
same everyday "either but not both" logic with exactly two arguments,
but a surprising rule once there are three or more.

## Return value

`TRUE` if an odd number of the arguments are `TRUE`; `FALSE`
otherwise (including when none of them are).

## Description

With exactly two arguments, XOR matches everyday intuition: `TRUE`
when exactly one of the two is `TRUE`, `FALSE` when both or neither
are. That intuition breaks down with three or more arguments — XOR
isn't "exactly one is TRUE," it's "an **odd count** is TRUE." Three
TRUE values among five arguments returns `TRUE`; two TRUE values
returns `FALSE`, same as zero.

<Callout type="warn">
  XOR with more than two arguments is **not** "exactly one condition
  is true" — that would need `COUNTIF`/`SUMPRODUCT` counting logic
  instead. `XOR(TRUE, TRUE, TRUE)` returns `TRUE` (three is odd), even
  though three conditions being true isn't "exactly one" by any normal
  reading.
</Callout>

## Common errors

### Expecting "exactly one true" with 3+ arguments

<ExcelCode>{`XOR(TRUE, TRUE, TRUE) → TRUE, not FALSE`}</ExcelCode>

If the real goal is "exactly one of these conditions is true," use
`SUMPRODUCT(--(conditions)) = 1` or a `COUNTIF`-based count instead —
XOR's odd/even rule isn't equivalent once past two arguments.

### #VALUE! — a non-logical argument

<ExcelCode>{`XOR("yes", TRUE) → #VALUE!`}</ExcelCode>

Every argument needs to evaluate to `TRUE`/`FALSE` (or a number,
where any nonzero number counts as `TRUE`) — plain text like `"yes"`
isn't automatically interpreted as a logical value.
