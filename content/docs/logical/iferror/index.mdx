Evaluate a formula, and if it returns *any* error — `#N/A`, `#VALUE!`,
`#REF!`, `#DIV/0!`, or otherwise — return a fallback value instead.
The standard way to wrap a risky lookup or calculation so a broken
input doesn't surface a raw error to whoever reads the sheet.

## Return value

The result of `value` if it isn't an error, otherwise
`value_if_error`.

## Description

IFERROR evaluates `value` once and checks whether the result is an
error. If it is — regardless of which error type — it returns
`value_if_error` instead. This makes it the standard wrapper around
lookups (`VLOOKUP`, `XLOOKUP`, `INDEX`/`MATCH`) and calculations
(division, `IF` chains) that can fail on unexpected input.

<Callout type="info">
  IFERROR catches **every** error type, which also means it can hide a
  genuine formula mistake, not just an expected "no match" case. If
  you only want to catch a missing lookup (`#N/A`) and let other
  errors surface normally, use **IFNA** instead — same shape, narrower
  net.
</Callout>

## Common errors

### Missing the second argument

<ExcelCode>{`IFERROR(VLOOKUP(A2, B:C, 2, FALSE)) → #VALUE! (wrong number of arguments)`}</ExcelCode>

IFERROR needs both arguments — always provide a fallback, even if
it's just `""`:

<ExcelCode>{`IFERROR(VLOOKUP(A2, B:C, 2, FALSE), "")`}</ExcelCode>

### Swallowing a real bug

<ExcelCode>{`IFERROR(A2/B2, 0) → hides both a genuine #DIV/0! and any other formula mistake`}</ExcelCode>

Wrapping too broadly hides more than the intended error. If it
matters which error you're catching, check for it explicitly instead:

<ExcelCode>{`IF(B2=0, 0, A2/B2)`}</ExcelCode>

<Callout type="warn">
  Wrapping a formula in IFERROR too early, before it's working
  correctly, can hide the real problem while you're building it —
  every error just silently becomes `value_if_error`. Get the formula
  working unwrapped first, then add IFERROR once you know what
  failure case it's actually there to catch.
</Callout>

## Related functions

- IFNA — same shape as IFERROR, but only catches `#N/A` specifically,
  leaving other error types to surface normally. Page coming soon
  (Logical category).
- [XLOOKUP](/docs/lookup/xlookup) — its `if_not_found` argument covers
  the most common IFERROR use case (missing lookup) natively, without
  a separate wrapper.
- [VLOOKUP](/docs/lookup/vlookup) and [HLOOKUP](/docs/lookup/hlookup) —
  neither has a built-in fallback, so IFERROR is the standard way to
  handle a missing match.
- IFS — like IFERROR, evaluates a series of things in order and stops
  at the first one that applies, but branches on conditions rather
  than errors. Page coming soon (Logical category).
