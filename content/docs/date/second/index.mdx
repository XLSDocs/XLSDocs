## Return value

The second as a whole number from `0` to `59`.

## Description

SECOND completes the HOUR/MINUTE/SECOND set — the same
extract-a-piece pattern as YEAR/MONTH/DAY, just applied to the time
portion of a serial number instead of the date portion. A time typed
or displayed without an explicit seconds component (like `2:30 PM`)
is stored with `0` seconds, so SECOND returns `0` for it rather than
an error.

<Callout type="info">
  Excel's time precision has real floating-point limits at the
  millisecond level, which can occasionally make SECOND return a
  value one off from what's expected on a time computed through a
  long chain of arithmetic. This is a general floating-point
  representation quirk, not specific to SECOND itself — rounding the
  underlying time value before extracting SECOND avoids it.
</Callout>

## Common errors

### #VALUE! — text Excel doesn't recognize as a time

<ExcelCode>{`SECOND("not a time") → #VALUE!`}</ExcelCode>

The text needs to be something Excel can actually parse as a time.

### Off-by-one results from floating-point time arithmetic

<ExcelCode>{`SECOND(A2) → 29 when 30 was expected, after several chained time calculations`}</ExcelCode>

Not a bug in SECOND itself — times are stored as fractions of a day,
and repeated arithmetic on them can accumulate tiny floating-point
errors. Wrapping the time value in `ROUND(time * 86400, 0) / 86400`
before extracting SECOND resolves it.
