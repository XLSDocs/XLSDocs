Pull the year out of a date as a plain number — the building block
for grouping data by year, calculating someone's age, or comparing
dates across different years.

## Return value

The year as a whole number between 1900 and 9999.

## Description

YEAR reads the year component straight out of a date's underlying
serial number — it doesn't matter how the date is formatted for
display, only that Excel recognizes the cell as an actual date
value. Combined with MONTH and DAY, it's the standard way to break a
date apart into its individual pieces for grouping or comparison.

<Callout type="info">
  `serial_number` needs to be a real date value, not text that merely
  *looks* like one. A cell containing the text `"1/15/2027"` that
  Excel has actually converted to a date works fine; a cell formatted
  as plain text holding those same characters does not, and returns
  `#VALUE!`.
</Callout>

## Common errors

### #VALUE! — text Excel doesn't recognize as a date

<ExcelCode>{`YEAR("not a date") → #VALUE!`}</ExcelCode>

The text needs to be something Excel can actually parse as a date —
check the source data isn't stored as plain, unconverted text.

### Comparing years across a mix of real dates and text

<ExcelCode>{`YEAR(A2) → #VALUE! for some rows, a number for others`}</ExcelCode>

A column that mixes real date values with text-formatted "dates"
(common after importing data) fails inconsistently — fix the whole
column's type first (e.g. with Data → Text to Columns) rather than
patching the formula per row.
