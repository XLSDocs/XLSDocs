second — the time-of-day equivalent of DATE, for assembling a time
from parts instead of a calendar date.

## Return value

A time serial value (a fraction between `0` and `1`, representing a
portion of a 24-hour day) built from `hour`, `minute`, and `second`.

## Description

TIME combines three separate numbers into a single time value, the
same way DATE combines year/month/day into a single date value. All
three arguments overflow into the next unit rather than erroring —
`TIME(0, 90, 0)` becomes `1:30 AM` (90 minutes rolls over into 1 hour
30 minutes), and the same rollover applies to `hour` itself.

<Callout type="warn">
  An `hour` of `24` or more doesn't error or clip — it wraps around
  using the remainder after dividing by 24. `TIME(27, 0, 0)` returns
  the exact same result as `TIME(3, 0, 0)`: `3:00 AM`. This can
  silently produce a "correct-looking" time from a genuinely wrong
  hour value, like an elapsed-hours calculation that should have used
  a different format entirely.
</Callout>

## Common errors

### An hour of 24+ silently wraps instead of erroring

<ExcelCode>{`TIME(27, 0, 0) → 3:00 AM (not an error, and not "27:00")`}</ExcelCode>

If the goal was actually to represent more than 24 elapsed hours
(like a duration, not a clock time), TIME is the wrong tool — a
duration needs to stay as a plain number of hours, or use a custom
`[h]:mm` number format that doesn't wrap at 24.

### Confusing TIME's argument order

<ExcelCode>{`TIME(30, 2, 0) → 6:02 AM, not 2:30 (hour=30 wraps to 6, minute=2)`}</ExcelCode>

The order is always hour, minute, second — swapping hour and minute
(an easy typo when both values happen to be small numbers) builds a
completely different, but still validly-computed, time, with no
error to flag the mistake.
