Count the number of working days between two dates, using a
**customizable weekend** — Friday/Saturday, Sunday-only, or any other
pattern, instead of `NETWORKDAYS`'s fixed Saturday/Sunday.

## Return value

The count of working days between `start_date` and `end_date`,
inclusive of both endpoints, excluding whichever days are marked as
weekend and any dates in `holidays`.

## Description

NETWORKDAYS.INTL solves the same limitation for counting business
days that `WORKDAY.INTL` solves for finding them: a weekend that
isn't always Saturday/Sunday. It uses the identical `weekend`
argument format as WORKDAY.INTL — a preset code or a custom
7-character string — so a workbook using one can reuse the same
weekend definition for the other.

The preset codes:

| Code | Weekend days |
| --- | --- |
| 1 (default) | Saturday, Sunday |
| 2 | Sunday, Monday |
| 3 | Monday, Tuesday |
| 4 | Tuesday, Wednesday |
| 5 | Wednesday, Thursday |
| 6 | Thursday, Friday |
| 7 | Friday, Saturday |
| 11 | Sunday only |
| 12 | Monday only |
| 13 | Tuesday only |
| 14 | Wednesday only |
| 15 | Thursday only |
| 16 | Friday only |
| 17 | Saturday only |

<Callout type="info">
  `weekend` sits **between** `end_date` and `holidays` — different
  argument order than plain NETWORKDAYS, where `holidays` is the
  third argument. Omitting `weekend` falls back to the standard
  Saturday/Sunday weekend.
</Callout>

## Common errors

### #NUM! — invalid weekend code

<ExcelCode>{`NETWORKDAYS.INTL(A2, B2, 9) → #NUM! (9 isn't a valid preset code)`}</ExcelCode>

Only `1`–`7` and `11`–`17` are valid preset codes — anything else
needs to be a 7-character `1`/`0` string instead.

### Off-by-one from expecting an exclusive count

<ExcelCode>{`NETWORKDAYS.INTL(DATE(2027,1,4), DATE(2027,1,8), 1) → 5 (both endpoints included)`}</ExcelCode>

Both `start_date` and `end_date` count if they fall on a working day
under the chosen weekend pattern — same inclusive behavior as plain
NETWORKDAYS.
