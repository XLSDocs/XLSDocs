Return the current date, with no arguments — it recalculates
automatically every time the workbook does, always showing the real
"today" whenever the file is opened or edited.

## Syntax

<ExcelCode>{`=TODAY()`}</ExcelCode>

## Parameters

TODAY takes no arguments — the parentheses are still required, but
always empty.

## Return value

The current date as a serial number, based on your system clock.
Updates automatically whenever the workbook recalculates.

## Description

TODAY is a **volatile** function — it recalculates every time the
workbook does, whether that's from opening the file, editing any
cell, or pressing F9, not on a timer. That makes it ideal for
anything that should always reflect "right now" (deadlines, ages,
days-remaining counters), but the wrong choice if you need to record
a fixed date that shouldn't change tomorrow.

<Callout type="warn">
  If you need to record a fixed "date submitted" or similar snapshot
  that shouldn't change the next day, don't use TODAY() — type the
  date directly, or press <strong>Ctrl+;</strong> to insert the
  current date as a static, unchanging value.
</Callout>

## Common errors

### A recorded "snapshot" date keeps changing

<ExcelCode>{`=TODAY() → shows a different date every day, even for a value meant to be fixed`}</ExcelCode>

TODAY() always reflects the current date — it's not a way to record
a moment in time. Use **Ctrl+;** to insert a static date instead, or
type it directly.

### Workbook feels slow with many TODAY()/NOW() calls

Both are volatile functions that force a recalculation trigger every
time the sheet recalculates. A handful is negligible, but hundreds of
them across a very large workbook can add up — consider whether every
instance genuinely needs to be live.
