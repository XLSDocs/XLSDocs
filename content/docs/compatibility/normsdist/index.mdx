NORMSDIST is the original name for what's now called
[NORM.S.DIST](/docs/statistical/norm-s-dist) — but unlike
[NORMDIST](/docs/compatibility/normdist)'s relationship to
[NORM.DIST](/docs/statistical/norm-dist), this isn't a pure rename.
NORMSDIST always computed the cumulative probability only; NORM.S.DIST
added a **required** `cumulative` argument, letting it also return the
distribution's raw density.

<Callout type="warn">
  `NORMSDIST(z)` is equivalent to `NORM.S.DIST(z, TRUE)` — **not**
  `NORM.S.DIST(z)` on its own, which actually returns `#VALUE!` since
  `cumulative` is required. This is the one function in this
  Compatibility batch where swapping in the modern name isn't a
  drop-in replacement without also adding the second argument.
</Callout>

## Return value

The standard normal distribution's cumulative probability at `z` —
always the cumulative form, with no way to request the density
instead.

## Common errors

### #VALUE! — z is nonnumeric

<ExcelCode>{`NORMSDIST("x") → #VALUE!`}</ExcelCode>

`z` must be an actual number — text that can't be interpreted as one
returns `#VALUE!`.

### Assuming NORM.S.DIST(z) alone works as the direct replacement

<ExcelCode>{`NORM.S.DIST(1.96) → #VALUE! (missing the required cumulative argument) — use NORM.S.DIST(1.96, TRUE) instead`}</ExcelCode>

Every other function in this Compatibility batch is a pure rename, so
it's natural to expect dropping in the new name alone to just work
here too. NORM.S.DIST specifically requires a second `cumulative`
argument that NORMSDIST never had — forgetting to add `TRUE` breaks
the formula instead of fixing it.
