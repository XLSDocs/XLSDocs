NEGBINOMDIST is the original name for what's now called
[NEGBINOM.DIST](/docs/statistical/negbinom-dist) — but like
[NORMSDIST](/docs/compatibility/normsdist), this isn't a pure rename.
NEGBINOMDIST always computed a single exact probability; NEGBINOM.DIST
added a **required** `cumulative` argument, letting it also return the
running total probability.

<Callout type="warn">
  `NEGBINOMDIST(number_f, number_s, probability_s)` is equivalent to
  `NEGBINOM.DIST(number_f, number_s, probability_s, FALSE)` — **not**
  `TRUE`. This is the opposite of
  [NORMSDIST](/docs/compatibility/normsdist)'s relationship to
  `NORM.S.DIST`, where the missing argument defaults to `TRUE`.
  There's no shortcut here — always check which cumulative value a
  legacy function's old behavior actually matches, rather than
  guessing from a different function's pattern.
</Callout>

## Return value

The exact probability of precisely `number_f` failures occurring
before the `number_s`-th success — always the single-point form, with
no way to request the running total instead.

The same "3 successes needed, 50% success rate" scenario used on
[NEGBINOM.DIST](/docs/statistical/negbinom-dist)'s own page, but with
exact (not cumulative) values — `NEGBINOMDIST(2, 3, 0.5)` and
`NEGBINOM.DIST(2, 3, 0.5, FALSE)` both return `0.1875`. Note this
does **not** match that page's own Try-It numbers directly, since
those use `cumulative = TRUE`.

## Common errors

### #NUM! — number_f is negative or number_s is less than 1

<ExcelCode>{`NEGBINOMDIST(-1, 3, 0.5) → #NUM!`}</ExcelCode>

`number_f` must be `0` or greater, and `number_s` must be `1` or
greater — a target of "0 successes needed" doesn't make sense for this
distribution.

### Assuming NEGBINOM.DIST(f, s, p) alone works as the direct replacement

<ExcelCode>{`NEGBINOM.DIST(2, 3, 0.5) → #VALUE! (missing the required cumulative argument) — use NEGBINOM.DIST(2, 3, 0.5, FALSE) instead`}</ExcelCode>

Dropping in the new name alone doesn't work — `cumulative` is
required. And unlike NORMSDIST (which needs `TRUE`), this one
specifically needs `FALSE` to match the legacy behavior.

### Assuming the missing argument defaults to TRUE, by analogy with NORMSDIST

<ExcelCode>{`NEGBINOMDIST(2, 3, 0.5) matches NEGBINOM.DIST(2, 3, 0.5, FALSE) = 0.1875, NOT NEGBINOM.DIST(2, 3, 0.5, TRUE) = 0.5000`}</ExcelCode>

Two different legacy functions in this Compatibility category are both
missing a `cumulative` argument their modern replacement requires —
but they don't default to the same value. Always verify which one
applies with an actual calculation; don't assume consistency across
functions just because the missing-argument shape looks the same.
