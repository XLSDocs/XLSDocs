TDIST is the original name covering what are now two separate
functions: [T.DIST.RT](/docs/statistical/t-dist-rt) and
[T.DIST.2T](/docs/statistical/t-dist-2t). Unlike every other function
in this category, TDIST doesn't map to a single modern replacement —
which one it matches depends entirely on its `tails` argument.

<Callout type="warn">
  `TDIST(x, deg_freedom, 1)` equals `T.DIST.RT(x, deg_freedom)`.
  `TDIST(x, deg_freedom, 2)` equals `T.DIST.2T(x, deg_freedom)`. Same
  legacy function, same two arguments `x` and `deg_freedom` — but
  `tails` silently picks between two genuinely different modern
  functions, not just two modes of one function.
</Callout>

## Return value

With `tails = 1`: the right-tailed probability — the area under the
curve to the right of `x`. With `tails = 2`: the combined two-tailed
probability — the area under both tails beyond `x` and `-x`.

[T.DIST.RT](/docs/statistical/t-dist-rt)'s and
[T.DIST.2T](/docs/statistical/t-dist-2t)'s own pages. Switching
`tails` from `1` to `2` doesn't adjust the result slightly — it
exactly **doubles** it, from `0.0343` to `0.0687`, because it's
routing to an entirely different modern function underneath.

## Common errors

### #NUM! — x is negative

<ExcelCode>{`TDIST(-2, 12, 1) → #NUM!`}</ExcelCode>

TDIST rejects negative `x` for **either** `tails` value — even
`tails = 1`, where the modern `T.DIST.RT` it maps to actually accepts
negative `x` just fine (returning a probability above 0.5). Microsoft's
own documentation gives the workaround:
`TDIST(-x, df, 1)` is equivalent to `1 - TDIST(x, df, 1)`, and
`TDIST(-x, df, 2)` is equivalent to `TDIST(x, df, 2)` — compute it by
hand rather than passing the negative value directly.

### #NUM! — tails is not 1 or 2

<ExcelCode>{`TDIST(2, 12, 3) → #NUM!`}</ExcelCode>

`tails` only accepts `1` or `2` — any other value is invalid.

### #NUM! — deg_freedom is less than 1

<ExcelCode>{`TDIST(2, 0, 1) → #NUM!`}</ExcelCode>

`deg_freedom` must be at least `1`.
