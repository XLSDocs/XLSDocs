Find the smallest value in a numeric column, restricted to the rows
that satisfy conditions listed in a **separate criteria range** —
DMAX's counterpart at the other end of the scale.

## Return value

The smallest value of `field` across every record in `database` that
matches every condition in `criteria`. Returns `0` if no records
match.

## Description

DMIN shares DSUM's criteria-range mechanic exactly — same-row
conditions are AND, separate-row conditions are OR — but returns the
smallest matching value instead of a total. Text and blank cells in
`field` are simply ignored when comparing, the same way they're
ignored by the plain `MIN` function.

<Callout type="idea">
  DMIN returning `0` when nothing matches can be misleading if the
  database's values are all positive but never actually reach `0` —
  it's easy to mistake for a genuinely low real result. If that's a
  concern, check `DCOUNT` first to confirm anything actually matched.
</Callout>

## Common errors

### The result is 0, but matching rows clearly exist

As with DSUM and DMAX, the most common cause is a criteria header
that doesn't exactly match a database header. DMIN silently ignores a
non-matching criteria row rather than erroring, which can produce a 0
that looks like a real result.

### 0 looks like a plausible result, but nothing actually matched

Confirm with `DCOUNT` that at least one record actually matched
before trusting a `0` from DMIN, especially in databases where a
value of exactly `0` is otherwise unlikely to occur naturally.
