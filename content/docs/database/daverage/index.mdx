Average a numeric column across all the rows in a table that satisfy
conditions listed in a **separate criteria range**, instead of
conditions written directly into the formula — DSUM's averaging
counterpart.

## Return value

The average of `field` across every record in `database` that matches
every condition in `criteria`. Returns `#DIV/0!` if no records match.

## Description

DAVERAGE shares DSUM's criteria-range mechanic exactly — same-row
conditions are AND, separate-row conditions are OR — but averages a
column instead of totaling it. It only averages records with a
numeric value in `field`; a blank or text cell in that column is
excluded from both the sum and the count behind the average, the same
way DCOUNT treats non-numeric values.

<Callout type="warn">
  Unlike DSUM (which returns `0` when nothing matches), DAVERAGE
  returns `#DIV/0!` when no record satisfies `criteria` — there's
  nothing to divide by. Wrap it in `IFERROR` if a criteria range might
  ever match zero records.
</Callout>

## Common errors

### #DIV/0! — no records match criteria

<ExcelCode>{`DAVERAGE(A1:D10, "Amount", F1:G2) → #DIV/0!`}</ExcelCode>

DAVERAGE needs at least one matching record to average — with zero
matches, the calculation divides by zero. Check the criteria range's
headers and values against the database.

### The average looks wrong given the visible matching rows

The most common cause is a criteria header that doesn't exactly match
a database header. DAVERAGE doesn't error on a mismatched header — it
silently ignores that row of criteria, which can widen (or narrow)
which records actually get averaged.

### Numbers stored as text are skipped

Like DSUM, DAVERAGE only includes genuine numeric values from
`field`. A column of numbers formatted or entered as text (common
after a CSV import) is excluded from both the sum and the count,
which can shift the average without any visible error.
