Calculate the population variance of a numeric column, restricted to
the rows that satisfy conditions in a **separate criteria range** —
DVAR's counterpart when the matching records ARE the entire
population being measured, not a sample of a larger one.

## Return value

The population variance of `field` across every record in `database`
that matches every condition in `criteria`.

## Description

DVARP shares DSUM's criteria-range mechanic exactly — same-row
conditions are AND, separate-row conditions are OR — but measures how
spread out the matching values are, treating them as a **complete
population** rather than a sample. Unlike `DVAR`, it divides by the
full count of matching records (`n`), not `n - 1`.

<Callout type="idea">
  Because DVARP divides by `n` instead of `n - 1`, it can handle a
  single matching record without error — the result is simply `0`
  (a single value has no spread relative to itself). This is the main
  practical reason to reach for DVARP over DVAR: it never produces
  `#DIV/0!` from a small match.
</Callout>

## Common errors

### The result is much smaller than DVAR on the same data

This is expected, not a bug — DVARP divides by `n` while DVAR divides
by `n - 1`, so DVARP always returns a value less than or equal to
DVAR's on the same matching records. The gap narrows as the number of
matching records grows.

### The result seems too large compared to the data's scale

Like DVAR, variance is expressed in **squared** units. Take the
square root (or use `DSTDEVP` directly) to get a result back in the
original units.
