Multiply every value in a numeric column together, restricted to the
rows that satisfy conditions in a **separate criteria range** —
useful for chaining multipliers, like successive growth or discount
rates, that need to compound rather than add.

## Return value

The product of every value in `field` across the records in
`database` that match every condition in `criteria`. Returns `1` if
no records match — the multiplicative identity, the same reason an
empty `PRODUCT()` also returns `1`.

## Description

DPRODUCT shares DSUM's criteria-range mechanic exactly — same-row
conditions are AND, separate-row conditions are OR — but multiplies
matching values together rather than adding them. It's the natural
fit for chained multipliers: successive growth rates, discount
factors, or conversion ratios that need to compound, not sum.

<Callout type="idea">
  DPRODUCT returns `1` for zero matches, not `0` — multiplying by 1
  leaves a value unchanged, the same reason an empty product is
  defined as 1 in ordinary math (just like an empty sum is defined as
  0, which is why DSUM returns `0`).
</Callout>

## Common errors

### The result is 1, but matching rows clearly exist

As with DSUM's silent-0 case, the most common cause is a criteria
header that doesn't exactly match a database header. DPRODUCT
silently ignores a non-matching criteria row rather than erroring,
which surfaces as an unexpected `1` (the identity result for zero
matches) instead of pointing at the mistake.

### An unexpectedly small or zero result

A single `0` anywhere in the matched `field` values collapses the
entire product to `0`, no matter how many other values were
multiplied in. Check the matched records for a stray `0` if the
result looks wrong.
