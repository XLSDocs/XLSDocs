Calculate the population standard deviation of a numeric column,
restricted to the rows that satisfy conditions in a **separate
criteria range** — DVARP's square root, back in the original units.

## Return value

The population standard deviation of `field` across every record in
`database` that matches every condition in `criteria`.

## Description

DSTDEVP shares DSUM's criteria-range mechanic exactly — same-row
conditions are AND, separate-row conditions are OR — but measures how
spread out the matching values are, in the same units as the original
data, treating the matches as a **complete population**. It's simply
the square root of `DVARP` on the same records.

<Callout type="idea">
  Like DVARP, DSTDEVP can handle a single matching record without
  error — the result is `0`, since a single value has no spread
  relative to itself. DSTDEV, its sample-based counterpart, would
  return `#DIV/0!` on the same single-record match.
</Callout>

## Common errors

### The result is smaller than DSTDEV on the same data

This is expected, not a bug — DSTDEVP is built from DVARP (which
divides by `n`), while DSTDEV is built from DVAR (which divides by
`n - 1`), so DSTDEVP always returns a value less than or equal to
DSTDEV's on the same matching records. The gap narrows as the number
of matching records grows.

### Confusing DSTDEVP's result with DVARP's

DVARP and DSTDEVP measure the same underlying spread, but in
different units — DVARP's result is in squared units, while
DSTDEVP's is in the original units. They aren't interchangeable
numbers even though they describe the same data.
