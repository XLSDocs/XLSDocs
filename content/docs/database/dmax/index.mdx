Find the largest value in a numeric column, restricted to the rows
that satisfy conditions listed in a **separate criteria range** —
DSUM's largest-value counterpart.

## Return value

The largest value of `field` across every record in `database` that
matches every condition in `criteria`. Returns `0` if no records
match.

## Description

DMAX shares DSUM's criteria-range mechanic exactly — same-row
conditions are AND, separate-row conditions are OR — but returns the
largest matching value instead of a total. Text and blank cells in
`field` are simply ignored when comparing, the same way they're
ignored by the plain `MAX` function.

<Callout type="idea">
  DMAX returning `0` when nothing matches can be misleading if the
  database itself contains negative numbers — `0` might look like a
  legitimate (if unusually low) result rather than "no matches." If
  negative values are possible, double-check with `DCOUNT` first to
  confirm anything actually matched.
</Callout>

## Common errors

### The result is 0, but matching rows clearly exist

As with DSUM, the most common cause is a criteria header that doesn't
exactly match a database header. DMAX doesn't error on a
non-matching header — it just ignores that criteria row, which can
silently produce 0 instead of pointing at the typo.

### 0 looks like a plausible result, but nothing actually matched

Since DMAX returns `0` for zero matches, this is easy to
misinterpret when the database contains only positive values close to
zero, or when negative values are expected. Confirm with `DCOUNT`
that at least one record actually matched before trusting a `0`.
