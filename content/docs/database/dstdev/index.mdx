Estimate the sample standard deviation of a numeric column, restricted
to the rows that satisfy conditions in a **separate criteria range** —
DVAR's square root, back in the original units.

## Return value

The sample standard deviation of `field` across every record in
`database` that matches every condition in `criteria`.

## Description

DSTDEV shares DSUM's criteria-range mechanic exactly — same-row
conditions are AND, separate-row conditions are OR — but measures how
spread out the matching values are, in the same units as the original
data. It's simply the square root of `DVAR` on the same records: a
`DVAR` result of `1,053,333.33` (in squared dollars) becomes a DSTDEV
result of about `1,026.32` (in plain dollars).

<Callout type="warn">
  DSTDEV needs **at least 2** matching records — the same `n - 1`
  requirement as DVAR, since DSTDEV is just DVAR's square root. Use
  `DSTDEVP` instead if the matching records should be treated as the
  entire population rather than a sample.
</Callout>

## Common errors

### #DIV/0! — only one record matches criteria

<ExcelCode>{`DSTDEV(A1:D10, "Amount", F1:G2) → #DIV/0!`}</ExcelCode>

DSTDEV inherits DVAR's `n - 1` requirement — with exactly one match,
that's division by zero before the square root is even taken. Either
broaden the criteria to include more records, or switch to `DSTDEVP`
if a single record legitimately represents the entire population.

### Confusing DSTDEV's result with DVAR's

DVAR and DSTDEV measure the same underlying spread, but in different
units — DVAR's result is in squared units (e.g. squared dollars),
while DSTDEV's is in the original units (plain dollars). They aren't
interchangeable numbers even though they describe the same data.
