Count how many records in a table have **any non-blank value** —
text, dates, or numbers — in a given field, restricted to rows that
match conditions in a separate criteria range. DCOUNT's less
restrictive counterpart.

## Return value

The count of records matching `criteria` that also have **any
non-blank value** in `field`. Returns `0` if nothing matches.

## Description

DCOUNTA shares DCOUNT's criteria-range mechanic exactly — same-row
conditions are AND, separate-row conditions are OR — but drops
DCOUNT's numeric-only restriction. Any cell that isn't empty counts,
regardless of whether it holds a number, text, or a date.

<Callout type="idea">
  Use DCOUNTA when the field being checked is naturally text (like a
  "Reviewed by" or "Notes" column) — DCOUNT would return `0` for a
  text-only field every time, since it only recognizes numbers.
</Callout>

## Common errors

### DCOUNTA counts more than expected on a numeric column

If `field` is a column that's supposed to be purely numeric,
DCOUNTA counts stray text entries too — like a typo, a placeholder
string, or a number stored as text — that `DCOUNT` would correctly
exclude. If the field should genuinely only ever hold numbers, DCOUNT
is usually the better choice.

### The result is 0, but matching rows clearly exist

As with DCOUNT, the most common cause is a criteria header that
doesn't exactly match a database header — DCOUNTA silently ignores a
non-matching criteria row instead of erroring.
