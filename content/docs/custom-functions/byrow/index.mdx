Run a calculation across each row of a table and get back one value
per row — a row total, a per-row flag, a weighted average — without
a helper column repeated down the sheet.

## Return value

A single-column spilled array with one row per row of `array`, each
holding whatever `lambda` returned for that row.

## Description

BYROW is MAP's row-at-a-time sibling: instead of calling `lambda`
once per individual element, it calls `lambda` once per **whole
row**, passing the entire row in as a single array argument. That
makes it the natural fit for anything that needs to combine several
columns per row into one number — a row total across quarterly
columns, a weighted score, or a TRUE/FALSE flag based on several
fields in that row at once.

<Callout type="warn">
  `lambda`'s calculation has to reduce the row down to **one value**
  — wrapping the row in `SUM`, `AVERAGE`, an `IF`, or similar. A
  LAMBDA that just returns the row unchanged (like `LAMBDA(row, row)`)
  produces a nested array in each result cell instead of the single
  value BYROW is meant to collapse each row into.
</Callout>

## Common errors

### #VALUE! — lambda takes more than one parameter

<ExcelCode>{`BYROW(A2:C10, LAMBDA(x,y, x+y)) → #VALUE!`}</ExcelCode>

`lambda` must take exactly one parameter representing the whole row.
To combine specific columns within that row, index into the row array
inside the calculation instead of adding more parameters.

### The result shows a spilled array in each row instead of one number

This means `lambda`'s calculation didn't actually reduce the row to a
single value — check that the calculation ends in something like
`SUM(row)` rather than returning `row` (or a slice of it) directly.

### Confusing BYROW with MAP

MAP calls `lambda` once per **element**; BYROW calls it once per
**whole row**. Using BYROW where MAP was needed (or the reverse)
produces either a #VALUE! error or a result shaped completely
differently than expected.
