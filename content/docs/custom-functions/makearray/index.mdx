Generate an entire array from scratch, one calculated cell at a
time — a multiplication table, a distance-from-center grid, or any
array whose values depend on their own row and column position.

## Return value

A spilled array of exactly `rows` × `columns` values, where the value
at each position is whatever `lambda` returned for that row and
column number.

## Description

Every other array-building function (SEQUENCE, VSTACK, HSTACK) starts
from existing values. MAKEARRAY starts from nothing but a size and a
rule — it calls `lambda(row, column)` for every position in the grid,
which makes it the tool for arrays whose values are a function of
their own position, like a multiplication table (`row * column`) or a
grid measuring distance from a center cell.

<Callout type="warn">
  The row and column numbers passed into `lambda` are **1-based** —
  the top-left cell of the result is position `(1, 1)`, not `(0, 0)`.
  Formulas ported from a 0-indexed language (Python, JavaScript)
  often need a `-1` adjustment to line up correctly.
</Callout>

## Common errors

### #VALUE! — lambda doesn't take exactly two parameters

<ExcelCode>{`MAKEARRAY(3, 3, LAMBDA(x, x*2)) → #VALUE!`}</ExcelCode>

`lambda` must take exactly two parameters: row number, then column
number, in that order — a single-parameter LAMBDA built for MAP won't
work here.

### The grid is off by one compared to a 0-indexed version

This usually means a formula was adapted from Python or JavaScript
without accounting for MAKEARRAY's 1-based row/column numbers —
subtract 1 from `row`/`column` inside the calculation if the logic
was originally written assuming a 0-based index.

### #VALUE! — rows or columns isn't a positive whole number

Both size arguments must be positive integers — a fractional or
zero/negative size produces an error rather than an empty or
partial array.
