Run a calculation across each column of a table and get back one
value per column — a column total, a per-column average, a max — the
column-wise counterpart to BYROW.

## Return value

A single-row spilled array with one column per column of `array`,
each holding whatever `lambda` returned for that column.

## Description

BYCOL is BYROW turned sideways: it calls `lambda` once per **whole
column**, passing the entire column in as one array argument, and
spills a single row of results — one per source column. It's the
formula behind a summary row underneath a table (a total, an average,
a count) built without a separate SUM formula in every column.

<Callout type="warn">
  `lambda`'s calculation has to reduce the column down to **one
  value** — wrapping it in `SUM`, `AVERAGE`, `MAX`, or similar. A
  LAMBDA that just returns the column unchanged produces a nested
  array in each result cell instead of the single summary value BYCOL
  is meant to collapse each column into.
</Callout>

## Common errors

### #VALUE! — lambda takes more than one parameter

<ExcelCode>{`BYCOL(A1:C10, LAMBDA(x,y, x+y)) → #VALUE!`}</ExcelCode>

`lambda` must take exactly one parameter representing the whole
column. To combine specific rows within that column, index into the
column array inside the calculation instead of adding more
parameters.

### The result shows a spilled array in each column instead of one number

This means `lambda`'s calculation didn't actually reduce the column
to a single value — check that it ends in something like `SUM(col)`
rather than returning `col` (or a slice of it) directly.

### Confusing BYCOL with BYROW

BYCOL processes one whole **column** at a time and spills a row of
results; BYROW processes one whole **row** at a time and spills a
column of results. Mixing them up produces a result transposed from
what was expected.
