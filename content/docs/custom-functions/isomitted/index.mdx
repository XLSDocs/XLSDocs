Inside a [LAMBDA](/docs/custom-functions/lambda), test whether an
**optional argument was left out** at call time. Pairs with
`[brackets]` around a LAMBDA parameter name, which is how a
parameter is marked optional in the first place.

## Return value

`TRUE` if `argument` was not supplied when the enclosing LAMBDA was
called. `FALSE` if it was supplied — even if the supplied value
happens to be `0`, blank, or anything else that might otherwise look
like "nothing was passed."

## Description

Making a LAMBDA parameter optional means wrapping its name in
`[brackets]` in the LAMBDA's own parameter list — `LAMBDA(a, [b],
...)` makes `b` optional while `a` stays required. ISOMITTED is the
only way to detect, from inside the LAMBDA's own calculation, whether
that optional `b` was actually provided on a given call:

<ExcelCode>{`=LAMBDA(a, [b], IF(ISOMITTED(b), a+10, a+b))(5)    → 15
=LAMBDA(a, [b], IF(ISOMITTED(b), a+10, a+b))(5, 20) → 25`}</ExcelCode>

<Callout type="warn">
  **ISOMITTED checks whether an argument was passed, not whether its
  value is "empty" in some other sense.** `ISOMITTED(b)` is `FALSE`
  if the caller explicitly passed `0`, an empty string, or `FALSE`
  for `b` — only genuinely leaving `b` out of the call makes
  `ISOMITTED(b)` `TRUE`.
</Callout>

## Common errors

### Using ISOMITTED outside a LAMBDA

<ExcelCode>{`=ISOMITTED(A1) → not meaningful outside a LAMBDA's own parameter list`}</ExcelCode>

ISOMITTED is designed specifically to test a LAMBDA's own named
parameter from inside that LAMBDA's calculation — it isn't a
general-purpose "is this blank" test for an ordinary cell reference
(use [ISBLANK](/docs/info/isblank) for that instead).

### Forgetting to mark the parameter optional with brackets

<ExcelCode>{`LAMBDA(a, b, IF(ISOMITTED(b), a+10, a+b)) → calling with just one argument fails before ISOMITTED ever runs`}</ExcelCode>

Without `[b]` in brackets, `b` is a required parameter — omitting it
at call time fails the call itself, and ISOMITTED never gets a
chance to evaluate it.
