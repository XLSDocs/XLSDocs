Like REDUCE, but instead of returning only the final accumulated
value, SCAN spills every intermediate step along the way — the
formula behind a running total column, without a helper column or a
dragged-down formula.

## Return value

A spilled array the same size as `array`, where each position holds
the accumulated value **as of that step** — the last element of the
result matches what REDUCE would return for the same inputs.

## Description

SCAN and REDUCE run the exact same step-by-step accumulation — the
only difference is what each one returns. REDUCE throws away every
intermediate result and keeps just the final value; SCAN keeps all of
them, spilled as an array the same size as the input. That makes SCAN
the direct formula for anything that needs a running value at every
row, not just a single total at the end.

<Callout type="info">
  If `initial_value` is provided, SCAN's result array is the **same
  size** as `array` (one accumulated value per input element, not
  counting the initial value itself as a separate row). Omitting
  `initial_value` uses the first element as the starting accumulator,
  and that first element becomes the first row of the result
  unchanged.
</Callout>

## Common errors

### #VALUE! — lambda doesn't take exactly two parameters

<ExcelCode>{`SCAN(0, A2:A10, LAMBDA(x, x*2)) → #VALUE!`}</ExcelCode>

`lambda` must take exactly two parameters — the accumulator first,
then the current element, same requirement as REDUCE.

### Only the final value is needed, not the whole column

If just the end result matters (not a running value at every row),
REDUCE is the simpler, more direct choice — SCAN's array output is
solving a different problem.

### The running total column doesn't line up with the source rows

This usually means `array`'s range doesn't start on the same row as
where the result is spilling — since SCAN's output is exactly the
same size and row-order as the input, a misaligned starting row will
make the running total look shifted by one or more rows.
