Round a number toward zero — always truncating, even if the value is
much closer to the higher number. The function behind "only count
whole completed units" logic, like age in whole years or fully
completed inventory batches.

## Return value

`number` rounded toward zero to `num_digits` digits — the result is
always at least as small in magnitude as `number`, never larger.

## Description

Unlike ROUND, which picks whichever direction is closer, ROUNDDOWN
always truncates toward zero — `ROUNDDOWN(3.99, 0)` gives `3`, not
`4`, even though `3.99` is much closer to `4`. This is the right
tool whenever "only count whole completed units" is the actual rule —
someone's age in whole years, or how many complete batches came off
a production line.

<Callout type="warn">
  ROUNDDOWN rounds **toward zero** for negative numbers too —
  `ROUNDDOWN(-3.99, 0)` gives `-3`, not `-4`. "Toward zero" means
  smaller in magnitude, regardless of sign.
</Callout>

## Common errors

### Expecting "round down" to mean "round toward negative infinity"

<ExcelCode>{`ROUNDDOWN(-3.99, 0) → -3 (not -4)`}</ExcelCode>

ROUNDDOWN rounds toward zero, not toward negative infinity — for
negative numbers, that means a less negative result. Use FLOOR
instead if rounding toward negative infinity regardless of sign is
what's actually needed.

### Using ROUND when the business rule actually needs ROUNDDOWN

<ExcelCode>{`ROUND(3.99, 0) → 4 (rounds to the closer value, not toward zero)`}</ExcelCode>

If the rule is genuinely "only count whole completed units," ROUND
is the wrong function — it rounds to whichever value is closer,
which usually isn't down.

## Related functions

- [ROUND](/docs/math/round) — rounds to the nearest value, in

- [ROUNDUP](/docs/math/roundup) — always rounds away from zero, the
  opposite direction from ROUNDDOWN.
- [FLOOR](/docs/math/floor) — rounds down to the nearest multiple of
  any value, instead of a number of digits.
