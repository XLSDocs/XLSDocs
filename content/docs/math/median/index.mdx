Find the middle value of a set of numbers — half the values fall
above it, half below. Unlike AVERAGE, a few extreme outliers barely
move it, which makes it the better "typical value" for skewed data
like salaries or home prices.

## Return value

The middle value once every number is sorted. With an odd count of
values, that's the single middle one; with an even count, it's the
average of the two middle values.

## Description

MEDIAN answers "what's typical" in a way AVERAGE can't when the data
is skewed — a handful of very high (or very low) values pull AVERAGE
toward them, while MEDIAN barely moves, since it only cares about
position, not magnitude. Household income and home prices are the
classic real-world examples where MEDIAN is reported instead of the
mean.

<Callout type="warn">
  With an **even** number of values, MEDIAN doesn't return one of the
  actual data points — it averages the two middle ones. `MEDIAN(1, 2,
  3, 4)` returns `2.5`, not `2` or `3`.
</Callout>

## Common errors

### Expecting the average, getting the median

<ExcelCode>{`MEDIAN(1, 2, 100) → 2 (not 34.3, which is the average)`}</ExcelCode>

Not a bug — MEDIAN is deliberately insensitive to the outlier
(`100`) here. Use AVERAGE if the mean is actually what's needed.

### Surprised by a non-data-point result

<ExcelCode>{`MEDIAN(10, 20, 30, 40) → 25 (the average of 20 and 30, not either one)`}</ExcelCode>

With an even count of values, this is expected — MEDIAN averages
the two middle values rather than picking one.
