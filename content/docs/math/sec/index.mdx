Return the **secant** of an angle — the reciprocal of
[COS](/docs/math/cos), equal to `1/COS(number)`. Like every Excel
trig function, the angle must be in **radians**.

## Return value

The secant of `number` — equal to `1/COS(number)`. Since COS never
exceeds `-1` to `1`, SEC never falls between `-1` and `1` — its
result is always `1` or greater, or `-1` or less.

## Description

SEC is one of the three "reciprocal" trig functions (alongside
[CSC](/docs/math/csc) and [COT](/docs/math/cot)), each defined as 1
divided by one of the three core trig functions. SEC specifically
inverts COS: `SEC(x) = 1/COS(x)`. Like COS, it expects `number` in
radians — convert a degree value with [RADIANS](/docs/math/radians)
first.

<Callout type="warn">
  **SEC never returns a result between -1 and 1**, with a visible
  gap right across that range — since COS itself never exceeds `-1`
  to `1`, its reciprocal can never fall inside that band. SEC jumps
  straight from `≥ 1` to `≤ -1` as the angle crosses COS's zero
  points (90°, 270°, and so on), where SEC itself becomes undefined.
</Callout>

The input here is treated as degrees and converted with RADIANS
before SEC sees it. Notice SEC(0°) and SEC(180°) are each at the two
possible minimums (`1` and `-1`) — the closest SEC ever comes to
zero on either side.

## Common errors

### #DIV/0! — an argument where cosine is 0

<ExcelCode>{`SEC(RADIANS(90)) → #DIV/0! (secant is undefined wherever cosine is exactly 0)`}</ExcelCode>

Any `number` whose cosine is exactly zero (90°, 270°, and their
radian equivalents) has no defined secant.

### Expecting a result between -1 and 1

<ExcelCode>{`SEC(0) → 1 (the closest SEC ever gets to 0, never any closer)`}</ExcelCode>

Because SEC is cosine's reciprocal, and cosine itself never exceeds
`-1` to `1`, SEC's result never lands inside that range — only at or
beyond its edges.
