Multiply corresponding elements across one or more arrays, then sum
every product — a single, flexible building block behind weighted
averages, OR-logic totals, and row-by-row array math that SUMIFS
can't express on its own.

## Return value

The sum of the element-by-element products across all supplied
arrays. With a single array, this is just the sum of its values —
equivalent to plain SUM.

## Description

SUMPRODUCT is the general-purpose tool behind several patterns that
SUMIFS/COUNTIFS can't express on their own: weighted totals
(multiplying values by their weights before summing), OR logic
inside a conditional sum (adding boolean arrays instead of ANDing
them), and counting how many cells satisfy a condition by coercing
TRUE/FALSE arrays to 1/0 with a double negative (`--`).

<Callout type="warn">
  Every array passed to SUMPRODUCT must be the **same size and
  shape** — mixing a 10-row range with a 9-row range throws
  `#VALUE!`, the same failure mode as SUMIFS/COUNTIFS with mismatched
  ranges.
</Callout>

## Common errors

### #VALUE! — mismatched array sizes

<ExcelCode>{`SUMPRODUCT(A2:A10, B2:B9) → #VALUE!`}</ExcelCode>

Both arrays must be the same size — here one is 9 rows and the other
is 10.

### Forgetting the double negative when coercing booleans

<ExcelCode>{`SUMPRODUCT(ISERROR(A2:A100)) → #VALUE! (TRUE/FALSE can't be summed directly)`}</ExcelCode>

A boolean array needs to be coerced to numbers first — the double
negative (`--`) turns `TRUE`/`FALSE` into `1`/`0`:

<ExcelCode>{`SUMPRODUCT(--ISERROR(A2:A100))`}</ExcelCode>

### Using * to combine conditions when arrays contain text

<ExcelCode>{`SUMPRODUCT((A2:A10="West")*(B2:B10="Open")) → counts rows matching both`}</ExcelCode>

Not an error — this is the standard pattern for AND logic inside
SUMPRODUCT: multiplying two boolean arrays keeps a row only if both
conditions are true, the same technique used inside FILTER.
