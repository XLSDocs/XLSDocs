Find the smallest value in a range, but only among rows that match
**all** of one or more conditions — the lowest price in a category,
the earliest deadline among open projects, and so on.

## Return value

The smallest value in `min_range` among rows where every criteria
pair matches. Returns `0` if no rows match — not an error, and
genuinely ambiguous with a real zero value if one exists in the data.

## Description

MINIFS extends MIN the same way SUMIFS extends SUM — every condition
must be true for a row to be considered (AND logic), and each
`criteria_range` must be the same size and shape as `min_range`.

<Callout type="warn">
  MINIFS puts `min_range` **first**, matching SUMIFS/COUNTIFS/
  AVERAGEIFS — unlike plain MIN, which takes no range/condition pairs
  at all. Don't confuse this with `SMALL`, which finds the *k*th
  smallest value with no conditional filtering.
</Callout>

## Common errors

### #VALUE! — mismatched range sizes

<ExcelCode>{`MINIFS(A2:A10, B2:B9, "West") → #VALUE!`}</ExcelCode>

`criteria_range` must be the same size as `min_range` — here one is
9 rows and the other is 10.

### Ambiguous 0 — genuine value or no match?

<ExcelCode>{`MINIFS(A2:A10, B2:B10, "Zzz") → 0 (either a real zero, or nothing matched at all)`}</ExcelCode>

Unlike SUMIFS/COUNTIFS (where a `0` result unambiguously means "no
matches"), MINIFS returning `0` can also mean the smallest genuinely
matching value is `0` — check the data directly if this matters.
