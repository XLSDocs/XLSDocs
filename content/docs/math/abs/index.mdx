Return a number's distance from zero, stripping the sign entirely —
`-8` and `8` both return `8`. The building block behind measuring a
difference or an error margin when the direction (over vs. under)
doesn't matter, only the size.

## Return value

`number` with any negative sign removed. Positive numbers and zero
are returned unchanged.

## Description

ABS answers "how far is this from zero," discarding whether it's
above or below. It's most useful whenever a comparison genuinely
shouldn't care about direction — how far off a forecast was from the
actual result, how big a variance is regardless of whether it's over
or under budget, or checking whether two values are "close enough"
by comparing `ABS(a - b)` against a tolerance.

<Callout type="info">
  ABS strips the sign, but it doesn't change how a formula that
  produces the number was computed. `ABS(actual - budget)` and
  `ABS(budget - actual)` always return the same result, even though
  `actual - budget` and `budget - actual` are opposite in sign —
  useful when it genuinely doesn't matter which value was subtracted
  from which.
</Callout>

## Common errors

### Expecting ABS to flip a positive number negative

<ExcelCode>{`ABS(8) → 8 (not -8 — ABS only ever removes a negative sign, never adds one)`}</ExcelCode>

ABS is one-directional — it strips a negative sign if one exists, but
it never makes a positive number negative. To force a value negative
regardless of its current sign, use `-ABS(number)` instead.

### Using ABS when a comparison should still care about direction

<ExcelCode>{`ABS(actual - budget) → same result whether actual is over or under budget`}</ExcelCode>

Not a bug, but a common design mistake — if "over budget" and "under
budget" genuinely need different treatment, wrapping the difference
in ABS throws that distinction away. Compare the raw difference's
sign directly instead when direction matters.
