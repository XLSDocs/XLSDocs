Round `number` down to the nearest integer or multiple of
`significance` — FLOOR's modern successor, with a `mode` argument
that controls which direction negative numbers round, and no
requirement that `number` and `significance` share a sign.

## Return value

`number` rounded down to the nearest multiple of `significance`.
`FLOOR.MATH(24.3, 5)` returns `20`; `FLOOR.MATH(6.7)` returns `6`.

## Description

FLOOR.MATH is the newer, more flexible version of FLOOR: it rounds
down to a multiple of `significance` just like FLOOR, but doesn't
require `number` and `significance` to share a sign, and adds the
`mode` argument for explicit control over negative-number rounding
direction. By default, a negative number rounds away from zero
(`FLOOR.MATH(-8.1, 2)` returns `-10`); a `mode` of 0 or negative
reverses that, rounding toward zero instead
(`FLOOR.MATH(-5.5, 2, -1)` returns `-4`).

<ExcelCode>{`=FLOOR.MATH(24.3, 5) → 20 (the next multiple of 5 at or below 24.3)`}</ExcelCode>

<Callout type="warn">
  **`mode` only matters for negative numbers.** A positive `number`
  always rounds down toward negative infinity regardless of what
  `mode` is set to — it exists purely to pick a direction for
  negative inputs.
</Callout>

## Common errors

### #DIV/0! — significance is zero

<ExcelCode>{`FLOOR.MATH(22, 0) → #DIV/0!`}</ExcelCode>

A zero `significance` has no valid multiple to round to.

### Unexpected sign confusion with mode

<ExcelCode>{`FLOOR.MATH(-5.5, 2) → -6 (away from zero, the default)`}</ExcelCode>
<ExcelCode>{`FLOOR.MATH(-5.5, 2, -1) → -4 (toward zero, with mode set)`}</ExcelCode>

Forgetting to pass `mode` is a common source of surprise when
rounding negative numbers — the default direction is away from
zero, which some expect to be the opposite.
