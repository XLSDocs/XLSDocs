Convert an angle from **radians to degrees** — the companion
function to [RADIANS](/docs/math/radians), used constantly alongside
every trig function to turn their radians-only results into the
units most people actually think in.

## Return value

`angle` converted from radians to degrees — equal to
`angle * 180/PI()`.

## Description

Every one of Excel's trig functions works in radians internally —
[SIN](/docs/math/sin), [COS](/docs/math/cos), and
[TAN](/docs/math/tan) expect a radians input, and their inverses
([ASIN](/docs/math/asin), [ACOS](/docs/math/acos),
[ATAN](/docs/math/atan), [ACOT](/docs/math/acot),
[ATAN2](/docs/math/atan2)) all return a radians result. DEGREES
exists specifically to bridge that gap at the output end — wrap any
of those inverse functions in `DEGREES()` to get the angle in the
unit most spreadsheets actually care about.

<Callout type="idea">
  DEGREES and `angle * 180/PI()` compute exactly the same thing —
  DEGREES just makes the intent obvious to a reader, the same role
  [RADIANS](/docs/math/radians) plays for the opposite conversion.
</Callout>

## Common errors

### Applying DEGREES to a value that's already in degrees

<ExcelCode>{`DEGREES(90) → 5156.62 (90 is read as 90 radians, not 90 degrees already)`}</ExcelCode>

DEGREES assumes its input is in radians — passing an already-degree
value through it converts it a second time, producing a meaningless
result.

### Forgetting DEGREES is needed at all

<ExcelCode>{`ASIN(0.5) → 0.5236 (radians, easy to mistake for a small degree value)`}</ExcelCode>

Every inverse trig function's raw result is in radians. Without
wrapping it in `DEGREES()`, a value like `0.5236` can look like a
plausible (if small) degree measurement when it's actually nothing
of the sort.
