Aggregate a range — sum, count, average, and more — while
automatically excluding rows hidden by a filter, something plain
SUM/AVERAGE/COUNT can't do. The function behind Excel Table and
AutoFilter's built-in totals row.

## Return value

The result of the chosen aggregate function, computed only over rows
that aren't hidden by a filter (and, for codes 101–111, not
manually hidden either).

## Description

`function_num` selects which aggregate to run: `1`=AVERAGE, `2`=COUNT,
`3`=COUNTA, `4`=MAX, `5`=MIN, `6`=PRODUCT, `7`=STDEV, `8`=STDEVP,
`9`=SUM, `10`=VAR, `11`=VARP. Add `100` to any of these (`101`–`111`)
to also exclude rows hidden manually (right-click → Hide Row), not
just ones hidden by an active filter.

<Callout type="warn">
  SUBTOTAL **always** excludes rows hidden by a filter, no matter
  which `function_num` is used — the 1–11 vs 101–111 split only
  controls whether *manually*-hidden rows are also excluded. It also
  ignores any other SUBTOTAL results inside its own range, so nested
  subtotals don't get double-counted.
</Callout>

## Common errors

### Total doesn't change when filtering

<ExcelCode>{`SUM(A2:A100) → same total no matter what's filtered`}</ExcelCode>

Plain SUM always includes every row, filtered or not. Switch to
SUBTOTAL to get a total that updates as the filter changes:

<ExcelCode>{`SUBTOTAL(109, A2:A100)`}</ExcelCode>

### Manually-hidden rows still counted

<ExcelCode>{`SUBTOTAL(9, A2:A100) → still includes rows hidden via right-click → Hide Row`}</ExcelCode>

Codes 1–11 only exclude *filtered* rows, not manually hidden ones —
use the 101–111 range instead if manual hides should also be
excluded:

<ExcelCode>{`SUBTOTAL(109, A2:A100)`}</ExcelCode>
