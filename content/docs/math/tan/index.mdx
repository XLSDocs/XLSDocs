Return the **tangent** of an angle. Like every Excel trig function,
the angle must be supplied in **radians** — a degree value needs
converting first, either with [RADIANS](/docs/math/radians) or by
multiplying by `PI()/180`.

## Return value

The tangent of `number`. Unlike SIN or COS, this isn't bounded to
`-1`–`1` — it can be any number, and grows without limit as the
angle approaches 90° (`PI()/2` radians) plus any multiple of 180°.

## Description

TAN expects its argument in radians. A degree value has to be
converted before it's passed in — wrap it in
[RADIANS](/docs/math/radians), or multiply it by `PI()/180` directly.
Mathematically, tangent is sine divided by cosine, which is why it's
undefined at angles where cosine is zero — Excel doesn't return an
error there, though; see below.

<Callout type="warn">
  Passing a **degree value directly** is the same trap every Excel
  trig function has — `TAN(45)` treats `45` as *45 radians*, not 45
  degrees, and returns `1.619`, nothing like the `1` someone
  expecting degree behavior would want. `TAN(RADIANS(45))` returns
  the expected `1`.
</Callout>

## Common errors

### Wrong result from passing degrees directly

<ExcelCode>{`TAN(45) → 1.619 (45 is read as 45 radians, not 45 degrees)`}</ExcelCode>

Excel has no way to tell a bare number is meant as degrees — it's
always radians. Wrap any degree value in `RADIANS()` first.

### A very large (not an error) result near 90°

<ExcelCode>{`TAN(RADIANS(89.99999)) → 5729577.95 (approaching, but never reaching, an undefined point)`}</ExcelCode>

Mathematically, tangent is undefined at exactly 90°, 270°, and so on
— but floating-point rounding means Excel's `RADIANS(90)` is never
*exactly* `PI()/2`, so `TAN(RADIANS(90))` returns an enormous but
finite number instead of an error.
