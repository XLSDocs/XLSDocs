Convert an angle from **degrees to radians** — the companion
function to [DEGREES](/docs/math/degrees), used constantly alongside
every trig function since Excel's trig functions all expect their
angle input in radians, not degrees.

## Return value

`angle` converted from degrees to radians — equal to
`angle * PI()/180`.

## Description

Every one of Excel's forward trig functions —
[SIN](/docs/math/sin), [COS](/docs/math/cos),
[TAN](/docs/math/tan), [COT](/docs/math/cot),
[SEC](/docs/math/sec), [CSC](/docs/math/csc) — expects its angle
argument in radians, not degrees. RADIANS exists specifically to
bridge that gap at the input end — wrap any degree value in
`RADIANS()` before passing it into one of those functions, instead
of passing the bare degree number directly (which silently computes
something else entirely).

<Callout type="idea">
  RADIANS and `angle * PI()/180` compute exactly the same thing —
  RADIANS just makes the intent obvious to a reader, the same role
  [DEGREES](/docs/math/degrees) plays for the opposite conversion.
</Callout>

## Common errors

### Skipping RADIANS and passing degrees directly into a trig function

<ExcelCode>{`SIN(30) → -0.988, not the 0.5 you'd get from SIN(RADIANS(30))`}</ExcelCode>

This is the single most common trig mistake in Excel — every forward
trig function reads a bare number as radians, not degrees, with no
warning when the units don't match what was intended.

### Applying RADIANS to a value that's already in radians

<ExcelCode>{`RADIANS(3.14159) → 0.0548 (3.14159 is read as 3.14159 degrees, not already-radians PI)`}</ExcelCode>

RADIANS assumes its input is in degrees — passing an already-radians
value through it converts it a second time, producing a meaningless
result.
