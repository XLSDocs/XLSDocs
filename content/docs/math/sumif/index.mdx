Sum a range of values, but only for rows that match **one**
condition — sales in the West region, invoices over $500, and so on.
For more than one condition, use [SUMIFS](/docs/math/sumifs) instead.

## Return value

The sum of `sum_range` (or `range`, if `sum_range` is omitted) values
in rows where `criteria` matches. Returns `0` if no rows match — not
an error.

## Description

SUMIF is the single-condition version of SUMIFS — pass one range and
one condition, and optionally a separate range to sum instead of the
one being tested. Omitting `sum_range` sums `range` itself, which is
useful for a simple threshold total like "sum every amount over
$1,000."

<Callout type="warn">
  SUMIF puts `sum_range` **last and optional**, but its multi-condition
  sibling SUMIFS puts it **first and required**
  (`=SUMIFS(sum_range, criteria_range1, criteria1, ...)`). Switching
  between the two without noticing the argument-order swap is a common
  source of wrong totals.
</Callout>

## Common errors

### #VALUE! — mismatched range sizes

<ExcelCode>{`SUMIF(A2:A10, "West", B2:B9) → #VALUE!`}</ExcelCode>

`sum_range` must be the same size as `range` — here one is 9 rows and
the other is 10.

### Silently wrong total — forgetting sum_range

<ExcelCode>{`SUMIF(Sales[Region], "West", Sales[Region]) → sums Region, not Amount`}</ExcelCode>

This doesn't throw an error — it just sums the wrong column, because
`sum_range` was left out of the third argument by mistake. Always
double-check the third argument is present when you mean to total a
*different* column than the one being tested.

### #NAME? — unquoted criteria

<ExcelCode>{`SUMIF(A:A, West, B:B) → #NAME? (missing quotes around "West")`}</ExcelCode>

Text criteria need quotes around them.

<Callout type="info">
  Comparison operators (`>`, `<`, `>=`, `<=`, `<>`) always need to be a
  quoted string. To compare against a cell's value, concatenate the
  operator with the reference: `">"&D2`, not `>D2`.
</Callout>

## Related functions

- [SUMIFS](/docs/math/sumifs) — the multi-condition version of SUMIF,
  with `sum_range` as the *first, required* argument instead of last
  and optional.
- [COUNTIF](/docs/math/countif) — same single-condition matching, but
  counts matching rows instead of summing a range.
- [AVERAGEIF](/docs/math/averageif) — same idea, but averages the
  matching rows instead of summing them.
- [IFERROR](/docs/logical/iferror) — useful alongside SUMIF when
  dividing a sum by a count that might be zero.
- [SUMPRODUCT](/docs/math/sumproduct) — handles OR logic across
  conditions, which SUMIF can't express directly.
