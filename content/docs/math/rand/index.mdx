Return a random decimal number greater than or equal to `0` and less
than `1`, with no arguments — a new value every time the workbook
recalculates, not a one-time roll.

## Syntax

<ExcelCode>{`=RAND()`}</ExcelCode>

## Parameters

RAND takes no arguments — the parentheses are still required, but
always empty.

## Return value

A random decimal number `n` where `0 ≤ n < 1`. A new value is
generated every time the workbook recalculates.

## Description

RAND is the base building block for random numbers in Excel — every
other random-number need (a random integer in a range, a weighted
pick, a shuffled list) is typically built by scaling or transforming
RAND's `0`–`1` output. `RANDBETWEEN` covers the specific, very common
case of "a random whole number between two bounds" directly.

<Callout type="warn">
  RAND is **volatile** — it recalculates on every single workbook
  recalculation (opening the file, editing any cell, pressing F9), not
  on a timer or only when its own inputs change (it has none). A
  formula referencing `RAND()` will show a *different* value almost
  every time it's viewed — it can't be used to record a fixed random
  choice.
</Callout>

## Common errors

### The value keeps changing every time I look at it

This is RAND's normal, expected behavior — it recalculates on every
recalculation, not once. To freeze a random value permanently, copy
the cell and use **Paste Special → Values** to replace the formula
with its current static result.

### Expecting a whole number, not a decimal

<ExcelCode>{`RAND() → 0.7295... (never a whole number)`}</ExcelCode>

RAND always returns a decimal between 0 and 1. For a random *integer*
within a specific range, use `RANDBETWEEN` instead, or scale RAND's
output manually: `INT(RAND() * (max - min + 1)) + min`.
