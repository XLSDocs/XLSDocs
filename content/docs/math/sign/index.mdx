Return just the sign of a number, discarding its magnitude entirely
— `1` for any positive number, `-1` for any negative number, and `0`
for zero itself, regardless of how large or small the original value
was.

## Return value

`1` if `number` is positive, `-1` if `number` is negative, or `0` if
`number` is exactly zero.

## Description

SIGN is [ABS](/docs/math/abs)'s complement — ABS keeps the magnitude
and drops the sign, SIGN keeps the sign and drops the magnitude.
Multiplying the two back together always reconstructs the original
number: `SIGN(number) * ABS(number)` equals `number` itself. SIGN is
most useful for branching logic based on direction alone — was a
variance positive or negative, did a value increase or decrease —
without needing a full `IF` comparison against zero.

<Callout type="info">
  `SIGN(0)` returns `0`, not an error and not `1` — zero has no
  positive or negative direction, so SIGN treats it as its own
  distinct third case rather than forcing it into either bucket.
</Callout>

## Common errors

### Expecting SIGN(0) to return an error or 1

<ExcelCode>{`SIGN(0) → 0 (not an error, and not defaulting to positive)`}</ExcelCode>

Zero is treated as its own case, distinct from both positive and
negative — a formula branching on SIGN's result needs to explicitly
account for `0` as a possible outcome, not just `1` and `-1`.

### Using SIGN when the actual magnitude is still needed

<ExcelCode>{`SIGN(-8) → -1 (the direction only — the original -8 magnitude is gone)`}</ExcelCode>

SIGN discards magnitude entirely. If both the direction and the size
are needed, keep the original value around separately rather than
trying to recover it from SIGN's result alone.
