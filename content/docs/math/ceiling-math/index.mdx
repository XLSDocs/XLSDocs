Round `number` up to the nearest integer or multiple of
`significance` — CEILING's modern successor, with a `mode` argument
that controls which direction negative numbers round, and no
requirement that `number` and `significance` share a sign.

## Return value

`number` rounded up to the nearest multiple of `significance`.
`CEILING.MATH(24.3, 5)` returns `25`; `CEILING.MATH(6.7)` returns `7`.

## Description

CEILING.MATH is the newer, more flexible version of CEILING: it
rounds up to a multiple of `significance` just like CEILING, but
doesn't require `number` and `significance` to share a sign, and
adds the `mode` argument for explicit control over negative-number
rounding direction. By default, a negative number rounds toward
zero (`CEILING.MATH(-8.1, 2)` returns `-8`); a non-zero `mode`
reverses that, rounding away from zero instead
(`CEILING.MATH(-5.5, 2, -1)` returns `-6`).

<ExcelCode>{`=CEILING.MATH(24.3, 5) → 25 (the next multiple of 5 at or above 24.3)`}</ExcelCode>

<Callout type="warn">
  **`mode` only matters for negative numbers.** A positive `number`
  always rounds up toward positive infinity regardless of what
  `mode` is set to — it exists purely to pick a direction for
  negative inputs.
</Callout>

## Common errors

### #DIV/0! — significance is zero

<ExcelCode>{`CEILING.MATH(22, 0) → #DIV/0!`}</ExcelCode>

A zero `significance` has no valid multiple to round to.

### Unexpected sign confusion with mode

<ExcelCode>{`CEILING.MATH(-5.5, 2) → -4 (toward zero, the default)`}</ExcelCode>
<ExcelCode>{`CEILING.MATH(-5.5, 2, -1) → -6 (away from zero, with mode set)`}</ExcelCode>

Forgetting to pass `mode` is a common source of surprise when
rounding negative numbers — the default direction is toward zero,
which some expect to be the opposite.
