Return the **arctangent of a point's x and y coordinates**, taken
together — the angle from the x-axis to the line through the origin
and that point. Because it sees both coordinates separately (not
just their ratio), ATAN2 can resolve the correct angle in **all four
quadrants**, something [ATAN](/docs/math/atan) can't do.

## Return value

The angle, in radians, between the x-axis and the line from the
origin to `(x_num, y_num)`, between `-π` and `π` (exclusive of `-π`
itself) — covering the full circle, unlike ATAN's half-circle range.
Wrap the result in [DEGREES](/docs/math/degrees) to convert it to
degrees.

## Description

ATAN2 is what ATAN can't be: because it receives the x and y
components of a point separately, rather than collapsing them into a
single ratio first, it can tell which of two opposite quadrants a
point is actually in. `ATAN2(x, y)` and `ATAN(y/x)` agree whenever
`x` is positive, but `ATAN2` also handles `x` being zero or negative
— cases plain division can't represent at all, or represents
ambiguously.

<Callout type="warn">
  **ATAN2's argument order is x first, then y** — `ATAN2(x_num,
  y_num)`. This is the opposite of the `atan2(y, x)` convention used
  by most programming languages (JavaScript's `Math.atan2`, Python's
  `math.atan2`, C's `atan2`), so porting a formula from code into
  Excel (or back) by matching argument *position* instead of
  *meaning* silently swaps the result to its complementary angle.
</Callout>

`x_num` stays fixed at `-1` (negative) while `y_num` varies — exactly
the case a plain ratio can't represent correctly, and where ATAN2's
quadrant-awareness shows: the result swings across `135°`, `180°`,
and `-135°`, well outside the `-90°` to `90°` range ATAN alone could
ever return.

## Common errors

### #DIV/0! — both coordinates are zero

<ExcelCode>{`ATAN2(0, 0) → #DIV/0! (the origin has no defined angle)`}</ExcelCode>

A point at the origin has no direction, so ATAN2 raises `#DIV/0!`
rather than returning an arbitrary angle.

### Swapping the argument order

<ExcelCode>{`ATAN2(1, 0) → 0, but ATAN2(0, 1) → 90 — not the same, despite looking like a simple swap`}</ExcelCode>

`x_num` comes first, `y_num` second — the reverse of the `atan2(y,
x)` order most programming languages use. Double-check argument
order explicitly when translating a formula between Excel and code.
