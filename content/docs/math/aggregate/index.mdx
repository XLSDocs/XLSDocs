Run one of 19 different aggregate calculations — SUM, AVERAGE, MAX,
LARGE, PERCENTILE, and more — with built-in options to ignore errors
and hidden/filtered rows, all through a single function.

## Return value

The result of the chosen aggregate calculation, applied only to the
values that survive whatever `options` excludes.

## Description

`function_num` picks the calculation:

| Code | Function | Code | Function |
|------|----------|------|----------|
| 1 | AVERAGE | 11 | VAR.P |
| 2 | COUNT | 12 | MEDIAN |
| 3 | COUNTA | 13 | MODE.SNGL |
| 4 | MAX | 14 | LARGE |
| 5 | MIN | 15 | SMALL |
| 6 | PRODUCT | 16 | PERCENTILE.INC |
| 7 | STDEV.S | 17 | QUARTILE.INC |
| 8 | STDEV.P | 18 | PERCENTILE.EXC |
| 9 | SUM | 19 | QUARTILE.EXC |
| 10 | VAR.S | | |

`options` picks what to ignore:

| Code | Ignores |
|------|---------|
| 0 | Nested SUBTOTAL/AGGREGATE results only (default) |
| 1 | Hidden rows, plus nested SUBTOTAL/AGGREGATE results |
| 2 | Error values, plus nested SUBTOTAL/AGGREGATE results |
| 3 | Hidden rows and error values, plus nested results |
| 4 | Nothing extra |
| 5 | Hidden rows |
| 6 | Error values |
| 7 | Hidden rows and error values |

<Callout type="warn">
  For `function_num` 14–19, the third argument isn't another range to
  aggregate — it's the extra value that function needs, like `k` for
  LARGE/SMALL or `quart` for QUARTILE.INC/QUARTILE.EXC. Passing a
  plain second range there instead (the way `function_num` 1–13
  work) returns an error.
</Callout>

## Common errors

### #VALUE! — a k/quart argument is missing for function_num 14–19

<ExcelCode>{`AGGREGATE(14, 6, A2:A10) → #VALUE!`}</ExcelCode>

LARGE (14) needs a `k` value as the third argument — without it,
AGGREGATE doesn't know which largest value to return.

### #REF! — function_num or options is out of range

<ExcelCode>{`AGGREGATE(25, 6, A2:A10) → #REF!`}</ExcelCode>

`function_num` only accepts 1–19, and `options` only accepts 0–7 —
anything else has no corresponding calculation or behavior to run.
