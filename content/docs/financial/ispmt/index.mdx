Calculate the **interest portion** of a single period's payment —
for a loan structured with **equal principal** payments each period
(not [PMT](/docs/financial/pmt)'s equal *total* payments), where the
interest portion shrinks every period as the balance goes down.

## Return value

The interest portion of the payment due in period `per`, assuming
`pv` is paid down in equal principal installments over `nper`
periods — equal to `-pv * rate * (1 - per/nper)`.

## Description

ISPMT models a loan where the **principal** payment is the same
every period (`pv/nper` each time), which means the **interest**
portion shrinks steadily as the balance goes down — the opposite
assumption from [PMT](/docs/financial/pmt)/[IPMT](/docs/financial/ipmt),
which hold the *total* payment constant and let the interest/
principal split change instead. The two models are genuinely
different loan structures, not two ways of computing the same thing.

<Callout type="warn">
  **`per` starts at `0` for the first period, not `1`.** This breaks
  the usual 1-based convention most of Excel's other period-indexed
  financial functions use (`per` in [IPMT](/docs/financial/ipmt)/
  [PPMT](/docs/financial/ppmt) runs `1` to `nper`). Passing `per=1`
  into ISPMT expecting the *first* period's interest actually
  returns the *second* period's interest instead.
</Callout>

## Common errors

### Expecting per=1 to mean the first period

<ExcelCode>{`ISPMT(10%, 1, 3, 3000) → -200 (the SECOND period's interest, not the first)`}</ExcelCode>

Use `per=0` for the first period's interest — ISPMT's indexing
starts at zero, unlike most other period-based financial functions.

### Using ISPMT for an equal-total-payment loan

<ExcelCode>{`ISPMT assumes equal PRINCIPAL payments — for a standard equal-payment loan (the far more common structure), use IPMT instead`}</ExcelCode>

Most real-world loans (mortgages, auto loans) use equal *total*
payments with a shifting principal/interest split — that's
[IPMT](/docs/financial/ipmt)'s model, not ISPMT's.
