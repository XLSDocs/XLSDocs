Calculate depreciation for an accounting period under the **French
accounting system**, using a declining-balance method accelerated
by a coefficient based on the asset's useful life. **Microsoft
documents this function as deprecated** — kept only so older
workbooks that already use it keep working.

## Return value

The depreciation amount for `period`, computed by declining-balance
at `rate` multiplied by a coefficient set by the asset's useful
life (`1/rate`):

| Asset life | Coefficient |
| --- | --- |
| 3 to 4 years | 1.5 |
| 5 to 6 years | 2 |
| More than 6 years | 2.5 |

An asset life falling in the gaps between these bands (0-1, 1-2,
2-3, or 4-5 years) returns `#NUM!`.

## Description

AMORDEGRC is built for the French accounting system's accelerated
depreciation method — rather than a fixed declining-balance factor
like [DDB](/docs/financial/ddb)'s default of `2`, the effective rate
is determined by looking up the asset's useful life in the table
above. The first accounting period is prorated for however many
actual days sit between `date_purchased` and `first_period`,
exactly the way a mid-year purchase doesn't earn a full year's
depreciation.

<ExcelCode>{`=AMORDEGRC(2400, "8/19/2008", "12/31/2008", 300, 1, 0.15, 1) → 776 (Microsoft's own documented example)`}</ExcelCode>

<Callout type="warn">
  **Microsoft documents AMORDEGRC as deprecated**, specifically
  because of changes to the French accounting system's own
  depreciation methodology — it's kept in Excel purely so workbooks
  built before that change keep calculating the same way they
  always have. New work shouldn't build on this function.
</Callout>

## Common errors

### #NUM! — an asset life that falls in a gap

<ExcelCode>{`AMORDEGRC(2400, "8/19/2008", "12/31/2008", 300, 1, 0.4) → #NUM! (1/0.4 = 2.5 years, between the "3 to 4" and lower bands — no defined coefficient)`}</ExcelCode>

The coefficient table has deliberate gaps between its bands — an
asset life computed from `1/rate` that lands in one of those gaps
has no defined coefficient and returns `#NUM!`.

### #VALUE! — an invalid date

<ExcelCode>{`AMORDEGRC(2400, "not a date", "12/31/2008", 300, 1, 0.15) → #VALUE!`}</ExcelCode>

Enter dates with `DATE()` or a genuine date value, not free-form
text — the same caution Microsoft gives for every date-based
financial function.
