Calculate the annualized return an investor actually earns on a
bond, given what they paid for it — not the coupon rate printed on
the bond, but the real return once its market price is factored in.
The reverse question from pricing a bond off a target yield.

## Return value

The bond's annualized yield to maturity, as a decimal — the single
constant discount rate that makes the present value of every
remaining coupon payment, plus the redemption value, equal to `pr`.

## Description

A bond's coupon rate is fixed when it's issued, but its market price
moves — and once the price changes, the coupon rate alone no longer
describes the actual return a buyer gets. YIELD solves for that real
return: with more than one coupon period remaining, there's no
closed-form formula, so Excel approximates it iteratively (the same
kind of Newton's-method solve [RATE](/docs/financial/rate) uses), by
testing candidate yields until one produces the given price.

<Callout type="warn">
  `pr` and `redemption` are expressed **per $100 of face value**, a
  standard bond-quoting convention — not the actual price paid or the
  bond's real face value. A $1,050 price on a $1,000 bond is `pr=105`,
  not `1050`.
</Callout>

Priced exactly at par (`pr=100`), this bond yields exactly its 6%
coupon rate — no discount or premium to account for. Pay less than
par (`95`) and the yield rises above the coupon rate; pay more
(`105`) and it falls below — the same inverse price/yield
relationship that drives every bond market.

## Common errors

### Treating pr and redemption as dollar amounts

<ExcelCode>{`YIELD(settlement, maturity, 6%, 1050, 1000, 2) → wrong (1050 and 1000 aren't per-$100 values)`}</ExcelCode>

Both `pr` and `redemption` need to be rescaled to a $100 face value
first — a $1,050 price on a $1,000-par bond is `pr=105`, and
`redemption` is almost always `100`:

<ExcelCode>{`YIELD(settlement, maturity, 6%, 105, 100, 2)`}</ExcelCode>

### #NUM! — the solver failed to converge, or dates are invalid

`settlement` must fall before `maturity`, and — like RATE — some
price/rate/maturity combinations converge slowly or not at all from
the solver's default starting point. Double-check the date order
first; a closer manual guess is the usual fix if the dates are fine.

### Expecting the coupon rate and the yield to match

<ExcelCode>{`YIELD(...) ≠ rate, unless pr is exactly 100`}</ExcelCode>

Not an error — they're only equal when the bond is priced exactly at
par. Any premium or discount to par pulls the yield away from the
stated coupon rate in the opposite direction.

    ```python lineNumbers
    from datetime import date
    from scipy.optimize import brentq

    def days_360(d1, d2):
        # US (NASD) 30/360 day count — Excel's default basis (0).
        # (d2 - d1).days would use real calendar days instead, which
        # can round to a different number of coupon periods.
        day1, day2 = d1.day, d2.day
        if day1 == 31:
            day1 = 30
        if day2 == 31 and day1 == 30:
            day2 = 30
        return (d2.year - d1.year) * 360 + (d2.month - d1.month) * 30 + (day2 - day1)

    def bond_price(yield_rate, settlement, maturity, rate, redemption, frequency):
        periods = round(days_360(settlement, maturity) / (360 / frequency))
        coupon = 100 * rate / frequency
        period_yield = yield_rate / frequency
        price = sum(coupon / (1 + period_yield) ** k for k in range(1, periods + 1))
        price += redemption / (1 + period_yield) ** periods
        return price

    settlement, maturity = date(2026, 1, 1), date(2031, 1, 1)
    yield_to_maturity = brentq(
        lambda y: bond_price(y, settlement, maturity, 0.06, 100, 2) - 95,
        -0.5, 1.0,
    )
    print(yield_to_maturity)
    ```
