Calculate the interest a bond has accumulated since its issue date (or
its first payment date) up to the day it's actually traded — the
amount a buyer owes the seller on top of the quoted price, since
interest keeps accruing between a bond's periodic coupon payments.

## Return value

The interest accrued on the security between `issue` (or
`first_interest`, depending on `calc_method`) and `settlement` — the
amount added on top of the bond's quoted price to compensate the
seller for interest already earned before the trade.

## Description

Bonds typically pay interest on fixed dates (semiannually, most
commonly), but they can trade on any day in between. ACCRINT
calculates the seller's share of the current coupon period — the
interest earned since the last relevant date, which the buyer pays
upfront and then recovers when the next full coupon arrives. For a
settlement date that falls within the bond's very first coupon period
(the common case, and the one demonstrated below), this reduces to a
simple proportion: the coupon amount for that period, scaled by how
much of the period has actually elapsed.

<Callout type="warn">
  `calc_method` changes which date ACCRINT starts counting from —
  `TRUE` (the default) accrues from `issue`, while `FALSE` accrues
  only from `first_interest` onward. For a security purchased during
  its very first coupon period, this is the difference between
  getting some accrued interest and getting none at all.
</Callout>

The full semiannual coupon on this bond is $30 (6% of $1,000, split
across 2 payments a year). Moving settlement halfway through the
180-day period accrues half that coupon — $15 — and the accrued
amount keeps climbing linearly with every day settlement moves later,
right up until the next coupon actually pays.

## Common errors

### Settlement has crossed into a later coupon period

<ExcelCode>{`ACCRINT(issue, first_interest, settlement, ...) → settlement well past first_interest`}</ExcelCode>

Once `settlement` is past one or more coupon dates, ACCRINT sums a
full coupon for every completed period plus a partial one for the
current period — it isn't simply "days since issue divided by the
first period's length" anymore. Excel handles this automatically;
a hand-built version of the formula needs to account for every
elapsed coupon period, not just the first.

### Confusing calc_method's two starting points

<ExcelCode>{`ACCRINT(..., calc_method=FALSE) → 0 if settlement is still within the first coupon period`}</ExcelCode>

With `calc_method` set to `FALSE`, accrual only starts counting from
`first_interest` — a settlement date before that returns `0`, which
looks like an error but is the documented behavior for that setting.

### Mismatched day count basis

Comparing an ACCRINT result computed with one `basis` against a
value computed with another (30/360 vs. actual/365, for example) on
the same dates produces slightly different numbers — not a bug, just
two different day-counting conventions applied to the same period.

    ```python lineNumbers
    from datetime import date

    def days_360(d1, d2):
        # US (NASD) 30/360 day count — Excel's default basis (0), and
        # NOT the same as (d2 - d1).days once a month doesn't have
        # exactly 30 days. Using real calendar days here would silently
        # disagree with Excel by a day or two per coupon period.
        day1, day2 = d1.day, d2.day
        if day1 == 31:
            day1 = 30
        if day2 == 31 and day1 == 30:
            day2 = 30
        return (d2.year - d1.year) * 360 + (d2.month - d1.month) * 30 + (day2 - day1)

    def accrint_simple(issue, first_interest, settlement, rate, par, frequency):
        # Simple case only — settlement within the very first coupon
        # period. A full implementation needs to sum every completed
        # coupon period once settlement crosses first_interest.
        accrued_days = days_360(issue, settlement)
        period_days = days_360(issue, first_interest)
        return par * (rate / frequency) * (accrued_days / period_days)

    accrued = accrint_simple(date(2026, 1, 1), date(2026, 7, 1), date(2026, 4, 1), 0.06, 1000, 2)
    print(accrued)
    ```
