---
title: "#DIV/0!"
description: A formula divides by zero — or by a blank cell, which Excel treats as zero in division.
---

`#DIV/0!` means a formula's divisor evaluated to zero. That includes
a literal `0`, but also a **blank cell** — Excel treats an empty cell
as `0` for the purpose of division, which is the single most common
way this error shows up unexpectedly.

## Common causes

**Direct division by a blank or zero cell** — by far the most common
case, often because a row's data hasn't been filled in yet:

<ExcelCode>{`=B2/C2 → #DIV/0! (C2 is blank)`}</ExcelCode>

**[MOD](/docs/math/mod): a divisor of zero:**

<ExcelCode>{`=MOD(10, 0) → #DIV/0!`}</ExcelCode>

**[AVERAGE](/docs/math/average): no numeric values to average** —
an empty range, or a range of entirely text/blank cells:

<ExcelCode>{`=AVERAGE(A1:A10) → #DIV/0! (no numeric values in the range)`}</ExcelCode>

**[STDEV](/docs/statistical/stdev) and similar: fewer than two
numeric values**, since sample variance is undefined for a single
point:

<ExcelCode>{`=STDEV(5) → #DIV/0!`}</ExcelCode>

**Percent-of-total style formulas where the total is genuinely zero**
— [PERCENTOF](/docs/math/percentof) and anything built on the same
`SUM(subset)/SUM(total)` pattern returns `#DIV/0!` if `data_all`
sums to zero, exactly like any other division.

## How to fix it

1. **Trace why the denominator is zero or blank** before assuming the
   formula itself is wrong — often it means a row's data hasn't been
   entered yet, which is useful information, not a bug to paper over.
2. **Wrap division in `IF(denominator=0, ..., ...)`** when a zero
   denominator is a real, expected possibility rather than a one-off
   data-entry gap — this makes the "what happens when it's zero"
   decision explicit instead of defaulting to IFERROR's generic
   fallback.
3. **For AVERAGE/STDEV-family functions**, confirm the range actually
   contains the numeric values you expect — a range that looks
   populated can still be entirely text if it was pasted from
   somewhere that didn't preserve number formatting.

## Catching it in a formula

[IFERROR](/docs/logical/iferror) suppresses `#DIV/0!` along with
every other error type. [ERROR.TYPE](/docs/info/error-type) returns
`2` for it specifically, while [ISERROR](/docs/info/iserror) returns
`TRUE` for it along with every error type.

## Not the same as #NUM! or #VALUE!

`#NUM!` means a numeric operation produced a result Excel can't
represent — out of range, or mathematically impossible, like a
negative square root. `#DIV/0!` is narrower and more specific: the
operation is division, and the divisor is exactly zero (or blank).
`#VALUE!` is different in kind — a type mismatch, not a numeric
result problem at all.
