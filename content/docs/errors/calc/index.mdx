---
title: "#CALC!"
description: A dynamic-array formula tried to produce an array with nothing in it, or a LAMBDA was entered without being called.
---

`#CALC!` is specific to Excel's dynamic-array engine — it doesn't
exist in older, pre-365 Excel at all. It almost always means a
formula that would otherwise spill an array came up with **nothing to
spill**, or a [LAMBDA](/docs/custom-functions/lambda) was typed into
a cell without ever being called.

## Common causes

**[FILTER](/docs/arrays/filter): no rows match the condition**, and
`if_empty` wasn't supplied to cover that case:

<ExcelCode>{`=FILTER(A2:C10, B2:B10="Zzz") → #CALC!`}</ExcelCode>

**[DROP](/docs/arrays/drop): dropping more rows or columns than the
array actually has.** Unlike [TAKE](/docs/arrays/take), which just
returns whatever's available, DROP errors when there's nothing left:

<ExcelCode>{`=DROP(A1:A5, 10) → #CALC!`}</ExcelCode>

**[SORT](/docs/arrays/sort) / [SORTBY](/docs/arrays/sortby) /
[UNIQUE](/docs/arrays/unique): the array to operate on is empty** —
often because it's fed by a FILTER call upstream that itself matched
nothing, or (for UNIQUE with `exactly_once=TRUE`) every value turned
out to be duplicated at least once.

**[LAMBDA](/docs/custom-functions/lambda) entered without being
called.** A LAMBDA isn't a value by itself — it's a function
definition waiting for arguments:

<ExcelCode>{`=LAMBDA(x, x*2) → #CALC! ("LAMBDA takes 1 argument(s)")`}</ExcelCode>

Either call it directly with its arguments
(`=LAMBDA(x, x*2)(5)`), or save it under a name in Name Manager so it
can be reused like a built-in function.

## How to fix it

1. **For FILTER returning no matches**, supply an explicit `if_empty`
   argument so a genuinely empty result is handled on purpose rather
   than surfacing as an error:
   <ExcelCode>{`=FILTER(A2:C10, B2:B10="Zzz", "No matches")`}</ExcelCode>
2. **For SORT/SORTBY/UNIQUE fed by another dynamic-array formula**,
   trace back to whichever upstream formula is actually producing the
   empty array — the fix usually belongs there, not at the outer
   function.
3. **For a bare LAMBDA**, either call it in place or save it as a
   named function — never leave one sitting uncalled in a cell.

## Catching it in a formula

[IFERROR](/docs/logical/iferror) suppresses `#CALC!` along with every
other error type. [ERROR.TYPE](/docs/info/error-type) has no
dedicated code for it — like `#SPILL!`, it's a dynamic-array-era
error that postdates ERROR.TYPE's original seven-code table.
[ISERROR](/docs/info/iserror) still catches it correctly regardless.

## Not the same as #SPILL! or #N/A

[#SPILL!](/docs/errors/spill) means a formula calculated a real,
non-empty result but couldn't physically write it into blocked cells.
`#CALC!` is closer to the opposite case: the formula has nowhere to
write *because the result itself has nothing in it*. `#N/A` means a
single lookup found no match; `#CALC!` is about an entire array
coming up empty, not one missing value.
