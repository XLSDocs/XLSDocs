`#BUSY!` means Excel is still waiting on something slow to finish —
an external data source, or a heavy calculation — and hasn't given
up on it. Unlike most error values, it's often just a temporary
placeholder that clears on its own once the wait is over.

## Common causes

**[RTD](/docs/lookup/rtd): the add-in server hasn't responded yet.**
A live, push-based data source can take a moment after the workbook
opens or recalculates before its first value arrives:

<ExcelCode>{`=RTD("Vendor.RTDServer", , "LAST", "MSFT") → #BUSY! briefly, then the real value`}</ExcelCode>

**[STOCKHISTORY](/docs/lookup/stockhistory): the historical-data
service is still retrieving the requested range** — a large date
range or a slow connection to Microsoft's financial-data service can
leave the formula showing `#BUSY!` for several seconds:

<ExcelCode>{`=STOCKHISTORY("MSFT", "2000-01-01", TODAY()) → #BUSY! while 25+ years of data is retrieved`}</ExcelCode>

**Python in Excel: a `PY` formula is still calculating.** Microsoft's
own documentation notes this can persist for up to 60 seconds before
it's worth resetting the Python runtime from the Formulas tab.

## How to fix it

1. **Wait, then recalculate (F9)** — in most cases `#BUSY!` simply
   clears once the slow resource responds; it isn't a sign that
   anything is actually broken.
2. **For RTD specifically**, confirm the add-in server itself hasn't
   hung or crashed if the wait never resolves — a server that's
   genuinely stuck looks identical to one that's merely slow.
3. **For a large STOCKHISTORY range**, consider narrowing the date
   range if the wait is consistently long — less data to retrieve
   means a shorter `#BUSY!` window on every recalculation.
4. **For Python in Excel**, reset the Python runtime (Formulas tab)
   if the wait passes roughly 60 seconds without resolving.

## Catching it in a formula

<Callout type="warn">
  Unlike every other error on this site, `#BUSY!` is **not reliably
  caught by [IFERROR](/docs/logical/iferror) or
  [ISERROR](/docs/info/iserror)** — it represents Excel still waiting
  on a result, not a value that has actually failed yet. A formula
  wrapping a busy cell in IFERROR can itself just show the fallback
  value temporarily, or recalculate again once the real result
  arrives, rather than cleanly suppressing it the way IFERROR
  suppresses `#N/A` or `#DIV/0!`.
</Callout>

[ERROR.TYPE](/docs/info/error-type) has no dedicated code for
`#BUSY!` — like `#SPILL!`, `#CALC!`, `#CONNECT!`, `#BLOCKED!`, and
`#FIELD!`, it postdates the original seven-code table.

## Not the same as #CONNECT!

[#CONNECT!](/docs/errors/connect) means a network call has already
*failed* — the service is unreachable. `#BUSY!` means the call is
still *in progress* — Excel hasn't given up on it yet, and it may
still resolve successfully given more time.
