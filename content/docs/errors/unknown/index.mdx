`#UNKNOWN!` means Excel genuinely doesn't recognize a data type used
somewhere in the workbook — not a formula mistake, but a version or
account gap between whoever built the workbook and whoever is
opening it now.

## Common causes

**[STOCKHISTORY](/docs/lookup/stockhistory) / [FIELDVALUE](/docs/lookup/fieldvalue):
opened on a perpetual-license (non-365) Excel.** Both depend on
Linked Data Types, which simply don't exist on Excel 2016/2019/2021 —
opening a workbook built with either function on one of those
versions shows `#UNKNOWN!` instead of a result:

<ExcelCode>{`=STOCKHISTORY("MSFT", "2026-01-01") → #UNKNOWN! on Excel 2019
=FIELDVALUE(A1, "Price") → #UNKNOWN! on Excel 2016`}</ExcelCode>

**Signed out of the Microsoft 365 account**, or connected
experiences disabled — Linked Data Types need an active, signed-in
365 connection even on a version that otherwise supports them.

**A workbook shared to someone without a qualifying subscription** —
the file opens fine, but every Linked-Data-Type-dependent cell shows
`#UNKNOWN!` for that specific person, even though it worked
correctly for whoever built it.

## How to fix it

1. **Confirm a qualifying Microsoft 365 subscription** (Personal,
   Family, Business Standard, or Business Premium) — this is a hard
   requirement for Linked Data Types, not something a setting can
   work around.
2. **Check sign-in status and connected experiences** — File →
   Account, confirm signed in, and that connected experiences are
   enabled under privacy settings.
3. **Rule out network restrictions** — a VPN, proxy, or firewall
   blocking Microsoft's data-type service can produce the same
   result as a missing subscription.
4. **If the file must also open correctly on an older or perpetual-
   license Excel**, run the Compatibility Checker first and convert
   Linked-Data-Type cells to plain text/values before distributing,
   rather than relying on every recipient having a qualifying
   subscription.

## Catching it in a formula

[IFERROR](/docs/logical/iferror) and [ISERROR](/docs/info/iserror)
both catch `#UNKNOWN!` the same as any other error value — useful for
giving a workbook shared outside the building team a graceful
fallback instead of a raw error. [ERROR.TYPE](/docs/info/error-type)
has no dedicated code for it, same as the other newer, non-classic
error types.

## Not the same as #BLOCKED!

[#BLOCKED!](/docs/errors/blocked) means the current version
*supports* the feature, but a security or privacy setting is
deliberately stopping it. `#UNKNOWN!` means the version itself has no
concept of the data type at all — there's no setting to change,
because the capability genuinely isn't there.
