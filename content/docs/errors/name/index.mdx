title: "#NAME?"

`#NAME?` means Excel ran into something in the formula it simply
doesn't recognize — not a wrong value, a reference to nothing. It's
one of the few errors that usually points at the formula's *text*
itself being malformed, rather than the data it's operating on.

## Common causes

**Text criteria written without quotes.** Excel reads an unquoted
word as a name it should look up, not literal text:

<ExcelCode>{`=SUMIF(A:A, West, B:B) → #NAME? (should be "West")`}</ExcelCode>

**An unquoted text comparison**, same underlying mistake:

<ExcelCode>{`=IF(A2=Yes, "OK", "No") → #NAME? (should be "Yes")`}</ExcelCode>

**A misspelled function name** — the single most literal cause,
easy to miss on a long formula:

<ExcelCode>{`=VLOOKPU(A2, B:D, 2, FALSE) → #NAME? (should be VLOOKUP)`}</ExcelCode>

**Using a newer function your Excel version doesn't have.**
[XLOOKUP](/docs/lookup/xlookup) and every dynamic-array or LAMBDA-
family function requires Excel 365 or 2021 — opening that same
workbook in Excel 2019 or 2016 shows `#NAME?` for the formula, even
though it's written correctly and worked fine for whoever built it.

**A named range that was deleted or renamed.** This is the one case
genuinely easy to confuse with `#REF!` — a formula referencing a cell
range directly shows `#REF!` when that range is deleted, but a
formula referencing a *named range* by its name shows `#NAME?`
instead, since the name itself no longer resolves to anything.

## How to fix it

1. **Check function spelling first** — it's the most literal and most
   common cause, and easy to eyeball-miss in a long nested formula.
2. **Wrap every text literal in quotes.** Any bare word in a formula
   that isn't a cell reference, a number, or a recognized function
   name needs quotes around it.
3. **If a named range is involved**, open Name Manager (Formulas tab)
   and confirm the name still exists and still points somewhere valid.
4. **If it's a newer function**, check which Excel version the
   workbook will actually be opened in — a formula that's correct in
   365 can still show `#NAME?` for a colleague on a perpetual license.

## Catching it in a formula

[IFERROR](/docs/logical/iferror) suppresses `#NAME?` along with every
other error type. [ERROR.TYPE](/docs/info/error-type) returns `5`
for it specifically, while [ISERROR](/docs/info/iserror) returns
`TRUE` for it along with every error type.

## Not the same as #REF! or #VALUE!

`#REF!` means a cell/range/sheet reference existed and then stopped
existing. `#NAME?` means Excel never recognized the name or function
in the first place — nothing was deleted, the formula itself
references something that was never valid, or isn't valid in this
specific Excel version. `#VALUE!` is different again: everything in
the formula is recognized, but an input's type is wrong.
