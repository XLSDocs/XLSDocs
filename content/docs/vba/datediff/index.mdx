Calculate how many complete time intervals separate two dates —
similar in spirit to the worksheet's `DATEDIF`, but with a
different argument order, different interval codes, and different
rules for counting boundaries, despite the near-identical name.

## Return value

The number of interval boundaries crossed between `date1` and
`date2`, as a whole number (negative if `date2` is earlier than
`date1`).

## Description

DateDiff counts how many times a given boundary (a new day, a new
month, a new year) is crossed between two dates — which is subtly
different from counting complete elapsed intervals. `DateDiff("yyyy",
"12/31/2026", "1/1/2027")` returns `1`, even though barely a day has
actually elapsed, because a year boundary (December 31 to January 1)
was crossed. Worksheet `DATEDIF`, by contrast, counts complete
elapsed years/months/days and would return `0` for that same pair.

<Callout type="warn">
  DateDiff and worksheet DATEDIF share a nearly identical name but
  use **different argument orders** (DateDiff takes `interval` first;
  DATEDIF takes the two dates first, then the unit) and **different
  counting rules** at period boundaries. Code or formulas ported
  between the two without adjusting for both differences will produce
  plausible-looking but wrong results.
</Callout>

## Common errors

### Assuming DateDiff counts complete elapsed intervals like DATEDIF

<ExcelCode>{`DateDiff("yyyy", #12/31/2026#, #1/1/2027#) → 1 (a boundary was crossed, not a full year)`}</ExcelCode>

DateDiff counts calendar boundary crossings, not whole elapsed
periods — worksheet `DATEDIF` is the one that counts full elapsed
units instead.

### Mixing up the argument order with DATEDIF

<ExcelCode>{`DateDiff(startDate, endDate, "d") → wrong argument order`}</ExcelCode>

DateDiff's `interval` comes **first**, unlike DATEDIF's unit
argument, which comes last:

<ExcelCode>{`DateDiff("d", startDate, endDate)`}</ExcelCode>

### Using the wrong interval code

<ExcelCode>{`DateDiff("y", date1, date2) → day-of-year difference, not years`}</ExcelCode>

`"y"` means day-of-year in DateDiff, not "years" — `"yyyy"` is the
code for a full year difference, an easy one to get backwards.

## In practice

```vb lineNumbers
Function DaysUntilDue(dueDate As Date) As Long
  DaysUntilDue = DateDiff("d", Date, dueDate)
End Function
```
