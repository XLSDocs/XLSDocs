## Return value

`True` if `expression` is an uninitialized Variant. `False` once the
variable has been assigned any value at all — including `0`, `""`,
or even `Null`.

## Description

Every `Variant` starts life as `Empty` the moment it's declared,
before any value has ever been assigned to it — `IsEmpty` is how
code checks for that specific starting state. It's commonly used to
detect whether an optional argument was actually supplied, or whether
a loop variable was ever set inside a conditional branch that might
have been skipped.

<Callout type="warn">
  `Empty` behaves like `0` in a numeric context and `""` in a string
  context, which means code that doesn't explicitly check `IsEmpty`
  often runs without erroring even when a variable was never actually
  set — silently masking what should have been a caught
  initialization bug.
</Callout>

## Common errors

### Assuming a variable that "worked" was actually assigned

<ExcelCode>{`total = total + neverSetValue → runs fine, adds 0`}</ExcelCode>

An uninitialized Variant behaves as `0` here with no error — the bug
(forgetting to assign `neverSetValue`) goes unnoticed unless code
explicitly checks `IsEmpty` first.

### Confusing Empty with Null

`IsEmpty` returns `False` for `Null` — a Variant that's been
explicitly assigned `Null` has been assigned *something*, even though
that something represents "no valid data." Use `IsNull` to test for
that case instead.

### Using IsEmpty on a non-Variant type

Declaring a variable `As String` or `As Long` instead of `As
Variant` means it can never be `Empty` — those types default to `""`
or `0` immediately, not the special Empty state, so `IsEmpty` on them
always returns `False`.

## In practice

```vb lineNumbers
Function DescribeVariant(v As Variant) As String
  If IsEmpty(v) Then
    DescribeVariant = "Never assigned"
  ElseIf IsNull(v) Then
    DescribeVariant = "Explicitly no data"
  Else
    DescribeVariant = "Has a value: " & CStr(v)
  End If
End Function
```
