Explicitly convert a value to a `String` — the standard way to
guarantee a variable is genuinely text before concatenating it,
displaying it, or passing it somewhere that expects a String type
specifically rather than a Variant that merely behaves like one.

## Return value

`expression` converted to a `String`. Numbers, dates, and Booleans
all get sensible default text representations (`True`/`False` for
Booleans, the system's short date format for dates).

## Description

CStr is one of several VBA type-conversion functions (alongside
`CInt`, `CDbl`, `CBool`, and others) that force a value into a
specific type instead of relying on VBA's automatic Variant
coercion. Using CStr explicitly — rather than just concatenating with
`&`, which coerces implicitly — makes the intent clear and catches
type problems (like a `Null`) at the exact line where they occur
instead of somewhere downstream.

<Callout type="warn">
  `CStr(Null)` raises a runtime error ("Invalid use of Null") — unlike
  the `&` operator, which silently treats `Null` as an empty string
  when concatenating. If a value might genuinely be `Null` (common
  with database fields), check `IsNull` first rather than wrapping it
  directly in `CStr`.
</Callout>

## Common errors

### Runtime error converting Null

<ExcelCode>{`CStr(Null) → runtime error 94: Invalid use of Null`}</ExcelCode>

Check for `Null` before converting:

<ExcelCode>{`If IsNull(v) Then result = "" Else result = CStr(v)`}</ExcelCode>

### Locale-dependent formatting surprises

<ExcelCode>{`CStr(1234.5) → "1234.5" or "1234,5" depending on the system's decimal separator`}</ExcelCode>

CStr uses the current locale's settings for numbers and dates, which
can produce a comma instead of a period on some systems — a real
concern for code shared across machines with different regional
settings. `Format` with an explicit pattern avoids this ambiguity.

### Expecting CStr to fail loudly on every bad input

CStr converts almost anything without error, including numbers,
dates, and Booleans — it only raises an error for genuinely
unconvertible values like `Null`. Don't rely on it to validate that
an input "makes sense" as text.

## In practice

```vb lineNumbers
Function DescribeCell(v As Variant) As String
  If IsNull(v) Then
    DescribeCell = "(no data)"
  Else
    DescribeCell = "Value: " & CStr(v)
  End If
End Function
```

## Related functions

- [IsNull](/docs/vba/isnull) — check for Null before converting,
  since CStr raises a runtime error on it directly.
- [Format](/docs/vba/format) — converts to a String with an explicit
  pattern, avoiding CStr's locale-dependent default formatting.
