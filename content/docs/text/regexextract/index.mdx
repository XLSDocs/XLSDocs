Pull the part of a text string that matches a regular expression,
instead of a fixed character position — the pattern-matching upgrade
to MID/FIND-based extraction formulas.

## Return value

The matching text as a string — REGEXEXTRACT always returns text,
even when the match looks numeric, so a result meant to be used in
arithmetic needs wrapping in `VALUE()`. Returns `#N/A` if `pattern`
never matches anywhere in `text`.

## Description

`return_mode` controls how much comes back:

- **0 (default):** just the first match, as a single value.
- **1:** every match in `text`, spilled as an array.
- **2:** the capturing groups — parts of the pattern wrapped in
  `()` — from the first match only, spilled as an array in the order
  the groups appear in `pattern`.

<Callout type="warn">
  A no-match result is `#N/A`, not an empty string. Wrap the formula
  in `IFERROR(REGEXEXTRACT(...), "")` (or a more specific fallback
  value) if a blank result is preferred over a visible error for text
  that might not match.
</Callout>

REGEXTEST is worth running first when building a REGEXEXTRACT
formula against messy or inconsistent data — confirming the pattern
matches at all is faster than debugging an `#N/A` after the fact.

## Common errors

### #N/A — no match found

<ExcelCode>{`REGEXEXTRACT("hello world", "[0-9]+") → #N/A`}</ExcelCode>

`text` doesn't contain anything matching `pattern` at all — there are
no digits in `"hello world"`. This is the expected result for a
genuine non-match, not a malfunction; wrap in `IFERROR` if a blank or
fallback value is preferred.

### #VALUE! — invalid pattern syntax

An unclosed bracket, unmatched parenthesis, or unsupported construct
in `pattern` produces `#VALUE!` regardless of what `text` contains.

### #NAME? — function not yet available

REGEXEXTRACT requires a current Microsoft 365 build — it returns
`#NAME?` on Excel 2021, 2019, 2016, or a 365 install that hasn't
received the update yet.

### Numbers extracted as text don't add up

<ExcelCode>{`=REGEXEXTRACT(A1,"[0-9]+")+5 → #VALUE!`}</ExcelCode>

REGEXEXTRACT's result is always text, even when it looks like a
number. Wrap it in `VALUE()` before using it in arithmetic:
<ExcelCode>{`=VALUE(REGEXEXTRACT(A1,"[0-9]+"))+5`}</ExcelCode>
