Locate text by byte position instead of character position — the
DBCS (double-byte character set) counterpart of
[FIND](/docs/text/find), kept for compatibility with older workbooks
built for Japanese, Chinese, or Korean editing environments.

<Callout type="warn">
  **Microsoft's current documentation marks FINDB as deprecated.**
  It still works in every current Excel version for backward
  compatibility with older DBCS-locale workbooks, but
  [FIND](/docs/text/find) is the function Microsoft now documents and
  recommends — use FINDB only if you're maintaining a workbook that
  already relies on it.
</Callout>

## Return value

The position of the first occurrence of `find_text` within
`within_text`, searching from `start_num` onward — counted in bytes
when a DBCS language is your default editing language, or in
characters otherwise. Returns `#VALUE!` if `find_text` doesn't
appear.

## Description

FIND and FINDB are the same function in every respect except how
they count position: FIND always counts one unit per character, no
matter what. FINDB counts a double-byte character (common in
Japanese, Chinese, and Korean text) as 2 units — but **only** when
your Windows/Excel default editing language is set to a language
that supports DBCS. Otherwise, FINDB counts one unit per character,
identically to FIND.

<Callout type="info">
  **The switch depends on your Excel language settings, not on the
  text itself.** A cell containing Japanese characters doesn't make
  FINDB start counting bytes — it only does that if Japanese, Chinese
  (Simplified), Chinese (Traditional), or Korean is enabled and set
  as your default editing language. On an English-default install,
  FINDB returns the exact same result as FIND even when searching
  CJK text.
</Callout>

Like FIND, FINDB is case-sensitive and doesn't support wildcards —
for a case-insensitive, wildcard-capable search, use
[SEARCHB](/docs/text/searchb) instead.

## Common errors

### #VALUE! — text not found

<ExcelCode>{`FINDB("x", A2) → #VALUE! (no "x" anywhere in A2)`}</ExcelCode>

Same behavior as FIND — wrap it in IFERROR if a missing match is a
valid, expected outcome.

### Expecting different results on an English-language install

<ExcelCode>{`FINDB("語", A2) → same result as FIND("語", A2), unless your default editing language is set to a DBCS language`}</ExcelCode>

If FINDB and FIND are returning identical results even against CJK
text, that's expected — the byte-counting behavior only activates
under a DBCS default editing language.

## Related functions

- [FIND](/docs/text/find) — the single-byte-set version of this
  function, and what Microsoft now recommends using instead.
- [SEARCHB](/docs/text/searchb) — the case-insensitive,
  wildcard-supporting DBCS counterpart, paralleling FIND/SEARCH.
- [LEFTB](/docs/text/leftb), [MIDB](/docs/text/midb) — commonly paired
  with FINDB's byte position to extract a DBCS substring.

## Examples

<ExampleCard number="01" label="Basic — locate a character by position" formula={`=FINDB("語", A2)`}>
  On an English-default install, returns the same character position
  FIND would. Under a DBCS default language, returns the byte
  position instead.
</ExampleCard>

<ExampleCard number="02" label="Confirming identical behavior to FIND" formula={`=FINDB(" ", A2)=FIND(" ", A2)`}>
  Returns TRUE on any non-DBCS-default install, since FINDB only
  diverges from FIND when a DBCS language is your default editing
  language.
</ExampleCard>

<ExampleCard number="03" label="Searching from a specific position" formula={`=FINDB("語", A2, 5)`}>
  Starts the search at position 5 instead of the beginning of the
  string, same as FIND's start_num argument.
</ExampleCard>
