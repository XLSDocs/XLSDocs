Find the position of one piece of text inside another — the
character number where a delimiter, a substring, or a specific
character first appears. Case-sensitive, and often nested inside
LEFT, RIGHT, or MID to locate a dynamic extraction point.

## Return value

The 1-based position of the first occurrence of `find_text` within
`within_text`, searching from `start_num` onward. Returns `#VALUE!`
if `find_text` doesn't appear.

## Description

FIND locates text by exact, case-sensitive matching, and doesn't
support wildcards. It's most often used nested inside LEFT, RIGHT, or
MID to find a dynamic split point — the position of a space, comma,
or other delimiter — rather than on its own.

<Callout type="warn">
  FIND is case-sensitive: `FIND("Excel", A2)` won't match a lowercase
  `"excel"` in A2. Use SEARCH instead if the match should ignore case.
</Callout>

## Common errors

### #VALUE! — text not found

<ExcelCode>{`FIND("x", A2) → #VALUE! (no "x" anywhere in A2)`}</ExcelCode>

Wrap it in IFERROR if a missing match is expected and shouldn't break
the formula:

<ExcelCode>{`IFERROR(FIND("x", A2), 0)`}</ExcelCode>

### #VALUE! — case doesn't match

<ExcelCode>{`FIND("Excel", A2) → #VALUE! (when A2 contains lowercase "excel")`}</ExcelCode>

FIND is case-sensitive. Use SEARCH for a case-insensitive match
instead.

## Related functions

- [SEARCH](/docs/text/search) — the case-insensitive, wildcard-
  supporting sibling of FIND.
- [MID](/docs/text/mid), [LEFT](/docs/text/left), and
  [RIGHT](/docs/text/right) — FIND's most common companions, using
  the position it finds as a dynamic extraction point.
- [SUBSTITUTE](/docs/text/substitute) — useful for locating the last
  occurrence of a delimiter, which FIND alone can't do directly.
