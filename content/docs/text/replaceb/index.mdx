Replace a chunk of text at a known byte position and byte length
instead of a character position and length — the DBCS (double-byte
character set) counterpart of [REPLACE](/docs/text/replace), kept for
compatibility with older workbooks built for Japanese, Chinese, or
Korean editing environments.

  **Microsoft's current documentation marks REPLACEB as deprecated.**
  It still works in every current Excel version for backward

  a workbook that already relies on it.

## Return value

`old_text` with the portion starting at `start_num` and sized by
`num_bytes` replaced by `new_text` — counted in bytes when a DBCS
language is your default editing language, or in characters (same as
REPLACE) otherwise.

## Description

REPLACE and REPLACEB replace the same thing in almost every
situation; the only difference is the unit `start_num`/`num_bytes` is
measured in. REPLACE always counts one unit per character. REPLACEB
counts a double-byte character (common in Japanese, Chinese, and
Korean text) as 2 units — but **only** when your Windows/Excel
default editing language is set to a language that supports DBCS.
Otherwise, REPLACEB counts one unit per character, identically to
REPLACE.

<Callout type="info">
  **The switch depends on your Excel language settings, not on the
  text itself.** A cell containing Japanese characters doesn't make
  REPLACEB start counting bytes — it only does that if Japanese,
  Chinese (Simplified), Chinese (Traditional), or Korean is enabled
  and set as your default editing language. On an English-default
  install, REPLACEB returns the exact same result as REPLACE even
  against CJK text.
</Callout>

## Common errors

### Cutting a double-byte character in half

<ExcelCode>{`REPLACEB("日本語です", 2, 3, "X") → an odd start position or byte count can split a double-byte character under a DBCS default language`}</ExcelCode>

Under a DBCS default editing language, each CJK character is 2 bytes.
A `start_num` or `num_bytes` that doesn't land on an even byte
boundary can split a character, producing a garbled result — use even
values, or work in characters with REPLACE instead.

### Confusing REPLACEB's arguments with SUBSTITUTE's

<ExcelCode>{`REPLACEB(A2, "abc", "xyz") → wrong — REPLACEB needs numeric position arguments, not text`}</ExcelCode>

Same confusion as REPLACE vs SUBSTITUTE — REPLACEB always needs a
numeric `start_num` and `num_bytes` in the middle.

## Related functions

- [REPLACE](/docs/text/replace) — the single-byte-set version of this
  function, and what Microsoft now recommends using instead.
- [SUBSTITUTE](/docs/text/substitute) — replaces based on matching
  text content instead of a fixed byte position and length.
- [FINDB](/docs/text/findb) and [SEARCHB](/docs/text/searchb) — often
  nested inside `start_num` to locate a dynamic byte-based replacement
  position.

## Examples

<ExampleCard number="01" label="Basic — replace a fixed segment" formula={`=REPLACEB(A2, 3, 4, "XXXX")`}>
  On an English-default install, replaces the same 4 characters
  starting at position 3 that REPLACE would. Under a DBCS default
  language, replaces 4 bytes starting at byte 3 instead.
</ExampleCard>

<ExampleCard number="02" label="Confirming identical behavior to REPLACE" formula={`=REPLACEB(A2, 3, 4, "X")=REPLACE(A2, 3, 4, "X")`}>
  Returns TRUE on any non-DBCS-default install, since REPLACEB only
  diverges from REPLACE when a DBCS language is your default editing
  language.
</ExampleCard>

<ExampleCard number="03" label="Dynamic position with FINDB" formula={`=REPLACEB(A2, FINDB("-", A2), 1, "/")`}>
  Locates the hyphen dynamically with FINDB, the same way REPLACE is
  commonly combined with FIND.
</ExampleCard>
