Identify which language a piece of text is written in, returning a
short language code (`en`, `es`, `fr`, `ja`, and so on) rather than a
full language name. DETECTLANGUAGE calls Microsoft Translator over
the internet to do the detection — it isn't a local, offline
calculation like most worksheet functions.

## Return value

A short language code as text — `"es"` for Spanish, `"ja"` for
Japanese, and so on. An empty `text` input returns an empty string
rather than an error.

## Description

DETECTLANGUAGE sends `text` to Microsoft Translator and returns
whichever language code the service judges most likely. It's most
useful as a building block for [TRANSLATE](/docs/text/translate),
which can auto-detect the source language on its own, or for
flagging rows in a mixed-language dataset before deciding how to
handle each one.

<ExcelCode>{`=DETECTLANGUAGE("Hola mundo!") → "es"`}</ExcelCode>

<Callout type="warn">
  DETECTLANGUAGE is a **service-backed function** — every call sends
  `text` to Microsoft Translator over the internet. It doesn't work
  offline, and Microsoft's own support page lists it as available in
  Excel for Microsoft 365 (Windows and Mac) and Excel Mobile only,
  with no confirmed support in Excel for the web as of this writing.
</Callout>

## Common errors

### #CONNECT! — no internet connection

<ExcelCode>{`DETECTLANGUAGE(A1) → #CONNECT! if the device is offline`}</ExcelCode>

DETECTLANGUAGE can't reach Microsoft Translator without a network
connection. Reconnect and recalculate (F9) to retry.

### Request throttled — daily quota exceeded

Microsoft Translator enforces a daily quota per user. Detecting the
language of a very large number of cells in a short period can hit
that limit — spread large batches out, or detect once and cache the
result in a helper column instead of recalculating repeatedly.

### #VALUE! — non-text input

<ExcelCode>{`DETECTLANGUAGE(A1) → #VALUE! if A1 is a number or error, not text`}</ExcelCode>

`text` needs to actually be text. Wrap a mixed-type reference in
`TEXT` or `T` first if it might contain numbers.

## Related functions

- [TRANSLATE](/docs/text/translate) — translates text into another
  language, and can auto-detect the source language the same way
  DETECTLANGUAGE does on its own.
- [TEXT](/docs/text/text) — general-purpose formatting, often used
  alongside DETECTLANGUAGE to clean up input before detection.
- [IFERROR](/docs/logical/iferror) — wraps DETECTLANGUAGE to catch
  `#CONNECT!` and return a fallback when offline.

## Examples

<ExampleCard number="01" label="Basic — detect a language from a cell" formula={`=DETECTLANGUAGE(A1)`}>
  Returns a short code like `"es"` or `"en"` for whatever language
  A1 is written in.
</ExampleCard>

<ExampleCard number="02" label="Flagging non-English rows" formula={`=IF(DETECTLANGUAGE(A1)="en", "English", "Review")`}>
  Useful for triaging a mixed-language feedback or support dataset —
  flag anything that isn't already in the expected language.
</ExampleCard>

<ExampleCard number="03" label="Feeding the result into TRANSLATE" formula={`=TRANSLATE(A1, DETECTLANGUAGE(A1), "en")`}>
  Explicitly passing DETECTLANGUAGE's result as TRANSLATE's source
  language — redundant most of the time, since TRANSLATE can
  auto-detect on its own, but useful when the source needs to be
  displayed separately too.
</ExampleCard>

<ExampleCard number="04" label="With a fallback for offline use" formula={`=IFERROR(DETECTLANGUAGE(A1), "Unknown")`}>
  Returns `"Unknown"` instead of `#CONNECT!` if the connection drops,
  so a larger formula depending on this result doesn't break.
</ExampleCard>

<ExampleCard number="05" label="#VALUE! from a non-text cell" formula={`=DETECTLANGUAGE(A1)`}>
  Returns `#VALUE!` if A1 contains a number, date, or error instead
  of text.
</ExampleCard>
