Convert a text string into a number, the same job as VALUE, but with
explicit control over which characters mean "decimal point" and
"thousands separator" — essential for data formatted with a
different country's number conventions than your own.

## Return value

The numeric value of `text`, parsed using `decimal_separator` and
`group_separator` instead of relying on the system's regional
settings. Returns `#VALUE!` if `text` can't be parsed that way.

## Description

VALUE relies on your system's regional settings to know whether a
period or a comma means "decimal point." NUMBERVALUE lets you state
that explicitly, which matters when working with data exported using
a different convention than your own — European-formatted numbers
like `"1.234,56"` (period as thousands separator, comma as decimal),
for example.

<Callout type="info">
  For `"1.234,56"` (the European convention, meaning 1234.56), the
  call is `NUMBERVALUE("1.234,56", ",", ".")` — comma as the decimal
  separator, period as the group separator, the reverse of the
  US/UK convention.
</Callout>

## Common errors

### #VALUE! — separators don't match the actual format

<ExcelCode>{`NUMBERVALUE("1.234,56", ".", ",") → #VALUE! (separators reversed)`}</ExcelCode>

Double-check which character is genuinely the decimal point in the
source data — it's easy to pass `decimal_separator` and
`group_separator` in the wrong order.

### #VALUE! — leftover non-numeric characters

<ExcelCode>{`NUMBERVALUE("1.234,56 kg", ",", ".") → #VALUE!`}</ExcelCode>

Trailing text like `" kg"` isn't part of any recognized number
format. Strip it out first with SUBSTITUTE or a text-extraction
formula.
