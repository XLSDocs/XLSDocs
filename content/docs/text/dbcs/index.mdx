Convert half-width characters to their full-width equivalents — the
reverse of [ASC](/docs/text/asc), used with double-byte character set
(DBCS) languages like Japanese, where letters and katakana can exist
in both a half-width and a full-width form.

## Return value

`text` with every half-width (single-byte) character converted to its
full-width (double-byte) equivalent. Characters that have no
full-width form pass through unchanged.

## Description

DBCS is the exact reverse of ASC: instead of normalizing full-width
characters down to half-width, it expands half-width characters up to
their full-width form. For Japanese specifically, this means
half-width English letters and half-width katakana become their
full-width equivalents.

<ExcelCode>{`=DBCS("EXCEL") → "ＥＸＣＥＬ" (half-width Latin letters converted to full-width)`}</ExcelCode>

<Callout type="info">
  **Both the function's name and the characters it converts depend on
  your Excel's language settings** — the "DBCS" name itself is the
  English version; in a Japanese build of Excel, the equivalent
  function is named differently. The underlying behavior is the same
  regardless of what the function is called.
</Callout>

## Common errors

### Expecting DBCS to change text with no half-width equivalent

<ExcelCode>{`=DBCS("Hello, World!") → may leave punctuation unchanged if it has no full-width equivalent being used`}</ExcelCode>

DBCS only affects characters that actually have a full-width form to
convert into. Text made up entirely of characters without one passes
through largely or entirely unmodified — this isn't an error, just a
no-op on those characters.

    # Unicode equivalent (Fullwidth Forms block)
    def to_fullwidth(text):
        return "".join(
            chr(ord(c) + 0xFEE0) if "!" <= c <= "~" else c
            for c in text
        )

## Related functions

- [ASC](/docs/text/asc) — the reverse conversion, from full-width to
  half-width characters.
- [PHONETIC](/docs/text/phonetic) — another Far-East-language text
  function, extracting furigana readings rather than converting
  character width.
- [UNICHAR](/docs/text/unichar) and [UNICODE](/docs/text/unicode) —
  work with Unicode code points directly, useful when a conversion
  needs more control than DBCS's fixed width-mapping.
