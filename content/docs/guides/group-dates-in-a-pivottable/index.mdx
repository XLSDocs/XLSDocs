A PivotTable built from raw daily dates shows one row per date by
default — hundreds of rows for a year of data. Grouping collapses
them into months, quarters, or years, directly inside the PivotTable,
with no change to the underlying source data.

## Grouping a date field

Right-click any date cell inside the PivotTable's row or column area,
choose **Group**, and a dialog lets you pick one or more units —
Years, Quarters, Months, Days, or a custom number of days.

<Callout type="warn">
  **Selecting only "Months" without also selecting "Years" merges
  every year together** — January 2026 and January 2027 both collapse
  into a single "January" row, combining data across years that may
  have been meant to stay separate. Select **both Months and Years**
  in the same dialog for a normal "month within each year" breakdown.
</Callout>

## A weekly grouping instead

The Group dialog's "Number of days" option only becomes available
once Months, Quarters, and Years are all deselected — leaving only
Days checked. Set **Number of days to 7** for weekly buckets instead
of calendar months.

## Removing a grouping

Right-click any grouped date cell and choose **Ungroup** — this
reverts to the original, ungrouped daily dates without affecting the
source data (which the grouping never touched in the first place).
Ctrl+Z also undoes a grouping immediately after applying it.

## If Group is greyed out

A date field sometimes can't be grouped — the most common cause is
that the column isn't actually stored as real dates. Any row where
that column holds text, a blank cell, or an error value anywhere in
the source range breaks Excel's ability to treat the whole column as
dates. Fix any non-date entries in the source data (an `=ISNUMBER()`
check column finds them quickly), then refresh the PivotTable and
try grouping again.
