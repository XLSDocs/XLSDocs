Remove a specific number of rows and/or columns from an array — skip
the header row, drop the last few blank rows, or both — the inverse
of TAKE.

## Return value

A spilled array with the requested rows and/or columns removed from
`array`, keeping everything else in its original order.

## Description

DROP is TAKE's mirror image: instead of specifying what to keep, it
specifies what to remove. The most common use is stripping a header
row before feeding a range into another array function
(`DROP(A1:C100, 1)` skips row 1), or trimming known blank/junk rows
off the end of an inconsistent export.

<Callout type="info">
  `DROP(array, -3)` removes the **last** 3 rows, not the first — same
  sign convention as TAKE. Combine both a row and column argument to
  drop from two directions in one call, e.g. `DROP(array, 1, -1)`
  removes the first row and the last column together.
</Callout>

## Common errors

### #CALC! — dropping more rows/columns than the array has

<ExcelCode>{`DROP(A1:A5, 10) → #CALC!`}</ExcelCode>

Unlike TAKE (which just returns what's available), DROP errors if
asked to remove more rows or columns than actually exist — there's
nothing left to return.

### The wrong end gets removed

<ExcelCode>{`DROP(A1:A20, 5) → removes the first 5 rows, not the last 5`}</ExcelCode>

A positive `rows` argument always removes from the top. For the last
5 rows instead, use a negative number:

<ExcelCode>{`DROP(A1:A20, -5)`}</ExcelCode>

### Forgetting DROP returns an array, not a modified range

DROP doesn't delete anything from the original range — it returns a
new spilled array with certain rows/columns excluded, leaving the
source data completely untouched.
