Pull out one or more specific rows from an array by number — the
first row, the last row, or any combination in any order — without
slicing a range by hand or nesting INDEX calls.

## Return value

A spilled array containing the requested rows from `array`, in the
exact order the row numbers were given — not necessarily their
original order.

## Description

CHOOSEROWS is a generalized, multi-row version of what INDEX does
for a single cell — instead of one row/column position, it takes a
whole list of row numbers and returns every column for each of them,
in whatever order they're listed. That makes it useful for pulling a
specific handful of rows (row 1 and the last row, say) or even
reordering rows deliberately, not just selecting a contiguous block
the way TAKE does.

<Callout type="idea">
  Row numbers don't have to be in order, and the **same row can be
  selected more than once** — `CHOOSEROWS(array, 3, 1, 3)` returns
  row 3, then row 1, then row 3 again. This makes CHOOSEROWS useful
  for reordering or duplicating rows, not just picking a subset.
</Callout>

## Common errors

### #VALUE! — a row number is out of range

<ExcelCode>{`CHOOSEROWS(A1:C10, 15) → #VALUE! (only 10 rows exist)`}</ExcelCode>

Every row number must fall within `array`'s actual row count —
unlike TAKE, CHOOSEROWS doesn't just return what's available.

### Expecting contiguous rows without listing each one

<ExcelCode>{`CHOOSEROWS(A1:C10, 1:5) → not valid syntax`}</ExcelCode>

CHOOSEROWS needs each row number listed individually (or generated
by another array, like `SEQUENCE(5)`) — for a simple contiguous block
from the start or end, `TAKE` is simpler.

### Forgetting that order in equals order out

<ExcelCode>{`CHOOSEROWS(A1:C10, 5, 1) → row 5 first, then row 1 — not sorted`}</ExcelCode>

The result follows the order the row numbers were given in, not
their original position in `array` — this is a feature for
reordering, but a surprise if ascending order was assumed.
