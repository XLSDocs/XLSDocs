Test whether a value is **not** text — the logical opposite of
[ISTEXT](/docs/info/istext), covering numbers, blanks, logical
values, and errors in one test.

## Return value

`TRUE` if `value` is anything other than text — a number, a blank
cell, a logical value, or an error. `FALSE` only when `value` is
genuinely text.

## Description

ISNONTEXT is the direct logical negation of
[ISTEXT](/docs/info/istext): `ISNONTEXT(x)` always equals
`NOT(ISTEXT(x))`. It exists as its own function mainly for
readability — `IF(ISNONTEXT(A2), ...)` reads slightly more directly
than `IF(NOT(ISTEXT(A2)), ...)` for the common case of "do something
unless this is text."

<Callout type="warn">
  **A blank cell counts as "not text," so ISNONTEXT returns TRUE for
  it** — the same gotcha ISTEXT has in reverse. If the goal is
  specifically "is this a number," use
  [ISNUMBER](/docs/info/isnumber) instead; ISNONTEXT only rules out
  text, it doesn't require any particular other type.
</Callout>

## Common errors

### Assuming ISNONTEXT means "is a number"

<ExcelCode>{`ISNONTEXT(blank cell) → TRUE (a blank is not text, but it's not a number either)`}</ExcelCode>

ISNONTEXT only rules out text — it says nothing about what the value
actually *is*. Use ISNUMBER for a more specific numeric test.

### Reaching for NOT(ISTEXT(...)) instead

<ExcelCode>{`NOT(ISTEXT(A2)) → the same result as ISNONTEXT(A2), just one function longer`}</ExcelCode>

Not wrong, just redundant — ISNONTEXT already does exactly this in
one call.
