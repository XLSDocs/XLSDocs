## Return value

A numeric code: `1` for a number, `2` for text, `4` for a logical
value (`TRUE`/`FALSE`), `16` for an error value, or `64` for an
array.

## Description

TYPE is one of the oldest ways to branch formula logic based on what
kind of data a cell actually contains — useful when a column might
hold a mix of numbers, text, and blanks, and a formula needs to
behave differently depending on which. Modern alternatives
(`ISNUMBER`, `ISTEXT`, `ISLOGICAL`) are usually more readable for a
single check, since they return `TRUE`/`FALSE` directly instead of a
numeric code to compare against.

<Callout type="warn">
  A reference to a genuinely **blank** cell returns `1`, the same code
  as a real number — Excel treats an empty cell as equivalent to `0`
  for this purpose. `TYPE` can't distinguish "this cell is blank" from
  "this cell contains the number 0"; use `ISBLANK` for that
  distinction instead.
</Callout>

## Common errors

### Expecting TYPE to distinguish blank from zero

<ExcelCode>{`TYPE(A2) → 1 (whether A2 is blank or contains 0)`}</ExcelCode>

TYPE can't tell these apart — both return `1`. Use `ISBLANK(A2)` if
the distinction between "empty" and "zero" actually matters.

### Comparing against the wrong code

<ExcelCode>{`IF(TYPE(A2)=1, "Text", "Number") → backwards`}</ExcelCode>

`1` means number, not text — double-check the code/meaning pairing
(1=number, 2=text, 4=logical, 16=error, 64=array) rather than
guessing from memory.

## Related functions

- [ISNUMBER](/docs/info/isnumber), [ISTEXT](/docs/info/istext), and
  [ISLOGICAL](/docs/info/islogical) — direct TRUE/FALSE checks for
  one specific type, usually clearer than comparing a TYPE code.
- [ISBLANK](/docs/info/isblank) — the correct way to test for a
  genuinely empty cell, which TYPE can't distinguish from zero.
- [CELL](/docs/info/cell) — returns other information about a cell
  (its formatting, address, or contents), not just its data type.
