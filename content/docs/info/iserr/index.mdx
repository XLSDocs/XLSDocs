Test whether a formula's result is an error — but unlike
[ISERROR](/docs/info/iserror), **not** `#N/A` specifically. Useful
when a missing-lookup `#N/A` should be handled separately from every
other kind of error.

## Return value

`TRUE` if `value` is any error **except** `#N/A` — `#VALUE!`,
`#REF!`, `#DIV/0!`, `#NAME?`, `#NUM!`, or `#NULL!`. `FALSE` for
everything else, including `#N/A` itself.

## Description

ISERR is ISERROR's narrower sibling: it catches every error type
*except* `#N/A`. The split exists because `#N/A` usually means
something different from the other six errors — it's the standard
signal for "no match found" from a lookup function, which is often
an expected, handleable outcome, not a broken formula the way
`#REF!` or `#DIV/0!` usually is.

<Callout type="warn">
  **ISERR(#N/A) is FALSE** — the one case it deliberately excludes.
  If the goal is to catch every error type without exception, use
  [ISERROR](/docs/info/iserror) instead; ISERR exists specifically
  for when `#N/A` needs different handling from everything else.
</Callout>

## Common errors

### Expecting ISERR to catch #N/A like ISERROR does

<ExcelCode>{`ISERR(NA()) → FALSE (ISERROR(NA()) would return TRUE instead)`}</ExcelCode>

This is ISERR's defining behavior, not a bug — it's built to treat
`#N/A` as a separate case from every other error type.

### Using ISERR when ISNA is what's actually needed

<ExcelCode>{`ISERR(VLOOKUP(...)) → FALSE even when the lookup genuinely fails with #N/A`}</ExcelCode>

If the goal is specifically to detect a failed lookup, use
[ISNA](/docs/info/isna) — ISERR will never flag it.
