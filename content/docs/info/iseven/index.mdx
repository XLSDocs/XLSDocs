Test whether a number is even — decimal values are truncated toward
zero first, so `2.9` and `2.1` both test as even, the same as plain
`2`.

## Return value

`TRUE` if `number` (after truncating any decimal portion) is even;
`FALSE` if odd.

## Description

ISEVEN truncates `number` toward zero before checking — it doesn't
round. `2.9` truncates to `2` (even, so `TRUE`), while `3.1` truncates
to `3` (odd, so `FALSE`) even though `3.1` is closer to an even number
than an odd one at a glance.

<Callout type="warn">
  Truncation, not rounding — `ISEVEN(2.9)` returns `TRUE` because
  `2.9` truncates to `2`, not because it rounds to a nearby even
  number. This matters most with values close to a whole number
  boundary, like `1.99` (truncates to `1`, odd) versus `2.01`
  (truncates to `2`, even).
</Callout>

## Common errors

### #VALUE! — a non-numeric argument

<ExcelCode>{`ISEVEN("four") → #VALUE!`}</ExcelCode>

`number` must be an actual number or a value that clearly converts to
one — text like `"four"` isn't recognized, even though it reads as a
number to a person.

### Expecting rounding instead of truncation

<ExcelCode>{`ISEVEN(1.99) → FALSE (truncates to 1, not rounded to 2)`}</ExcelCode>

If the intent is to check the *rounded* value's parity, wrap in
`ROUND` first: `ISEVEN(ROUND(1.99, 0))`.
