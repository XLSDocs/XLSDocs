Test whether a formula's result is an error — `#N/A`, `#VALUE!`,
`#REF!`, `#DIV/0!`, or any other error type. For a modern formula
that just needs a fallback value, IFERROR usually replaces this
pattern entirely.

## Return value

`TRUE` if `value` is any error — `#N/A`, `#VALUE!`, `#REF!`,
`#DIV/0!`, `#NAME?`, `#NUM!`, or `#NULL!`. `FALSE` for everything
else, including a genuinely blank cell.

## Description

ISERROR catches every error type in one test, unlike ISNA (which
only catches `#N/A` specifically). It predates IFERROR, and was
historically paired with IF to build a fallback-value pattern:
`IF(ISERROR(formula), fallback, formula)` — the same thing IFERROR
now does in one call, without evaluating `formula` twice.

<Callout type="warn">
  For the common "run a formula, show a fallback if it errors"
  pattern, [IFERROR](/docs/logical/iferror) is simpler and more
  efficient than `IF(ISERROR(...), ...)` — it evaluates the formula
  once instead of twice, and needs no separate ISERROR call. Reach
  for ISERROR directly mainly when the goal is a plain `TRUE`/`FALSE`
  flag, not a substitute value.
</Callout>

## Common errors

### Using ISERROR when IFERROR would be simpler

<ExcelCode>{`IF(ISERROR(VLOOKUP(...)), "Not found", VLOOKUP(...)) → works, but evaluates VLOOKUP twice`}</ExcelCode>

Not wrong, just inefficient — IFERROR does the same job in one call
and one evaluation:

<ExcelCode>{`IFERROR(VLOOKUP(...), "Not found")`}</ExcelCode>

### Catching every error when only #N/A should be handled

<ExcelCode>{`ISERROR(VLOOKUP(...)) → TRUE for #N/A, but also #REF!, #VALUE!, etc.`}</ExcelCode>

If only a missing-match `#N/A` should trigger the fallback (and a
genuine formula mistake like `#REF!` should stay visible instead of
being silently hidden), use ISNA instead of ISERROR.
