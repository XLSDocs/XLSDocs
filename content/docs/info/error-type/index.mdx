Return a number identifying **which specific error** `error_val` is
— `1` for `#NULL!`, `2` for `#DIV/0!`, and so on through `7` for
`#N/A`. Returns `#N/A` itself if `error_val` isn't actually an error.

## Return value

A number from `1` to `7` identifying which error `error_val` is:

| Error | Code |
| --- | --- |
| `#NULL!` | 1 |
| `#DIV/0!` | 2 |
| `#VALUE!` | 3 |
| `#REF!` | 4 |
| `#NAME?` | 5 |
| `#NUM!` | 6 |
| `#N/A` | 7 |

If `error_val` is not actually an error, ERROR.TYPE itself returns
`#N/A`.

## Description

Where [ISERROR](/docs/info/iserror) only answers "is this an error"
with `TRUE`/`FALSE`, ERROR.TYPE answers "*which* error is this"
with a specific code. It's most useful paired with
[CHOOSE](/docs/lookup/choose) to translate that numeric code into a
readable message:
`=CHOOSE(ERROR.TYPE(A2), "Null", "Divide by zero", "Wrong type", "Bad reference", "Unknown name", "Invalid number", "Not found")`.

<Callout type="warn">
  **ERROR.TYPE itself returns `#N/A` when given a non-error value**
  — it doesn't return `0` or `FALSE` the way a boolean test would.
  Wrap it in [IFERROR](/docs/logical/iferror) if `error_val` might
  not actually be an error, to avoid propagating a second,
  unrelated `#N/A`.
</Callout>

Each error type maps to its own fixed code — `#DIV/0!` is always
`2`, `#N/A` is always `7`, regardless of what formula produced the
error.

## Common errors

### Forgetting ERROR.TYPE itself errors on non-error input

<ExcelCode>{`ERROR.TYPE(42) → #N/A (42 isn't an error, so there's no code to return)`}</ExcelCode>

Check with ISERROR first, or wrap the whole thing in IFERROR, if
`error_val` isn't guaranteed to already be an error.

### Memorizing the codes instead of pairing with CHOOSE

<ExcelCode>{`ERROR.TYPE(A2) → 4 (meaningless on its own without looking up what "4" means)`}</ExcelCode>

The raw code by itself isn't useful to a formula's end reader — pair
it with CHOOSE to turn it into an actual message.
