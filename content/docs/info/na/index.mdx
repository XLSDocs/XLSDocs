Deliberately produce the `#N/A` error on purpose — not a mistake to
fix, but a placeholder that tells a chart to skip a point, or flags a
cell as "not yet available" in a way that flows correctly through
ISNA and IFNA elsewhere in the sheet.

## Syntax

<ExcelCode>{`=NA()`}</ExcelCode>

## Parameters

NA takes no parameters — it's always written as `NA()` with empty
parentheses.

## Return value

The `#N/A` error value, every time, unconditionally.

## Description

NA exists to make `#N/A` a deliberate, readable choice instead of an
accidental one. The most common use is in chart data: Excel charts
skip over a cell containing `#N/A` entirely, leaving a genuine gap in
the line or bars — unlike a blank cell (often plotted as zero) or a
`0` (which is a real data point, not a missing one). It's also used
as a "value not available yet" placeholder in a data table, one that
correctly triggers `ISNA`/`IFNA` checks in any formula that
references it.

<Callout type="warn">
  `#N/A` from `NA()` behaves exactly like `#N/A` from any other
  source — it **propagates** through most formulas that reference it
  (`SUM`, `AVERAGE`, a lookup, and so on all return `#N/A` too if any
  input is `#N/A`). Wrap dependent formulas in `IFERROR` or `IFNA` if
  they need to tolerate a deliberate placeholder without breaking.
</Callout>

## Common errors

### A downstream SUM or AVERAGE breaks

<ExcelCode>{`SUM(A1:A10) → #N/A (if any cell in the range is NA())`}</ExcelCode>

This is expected, not a bug — `#N/A` propagates through SUM just like
any other error. Use `AGGREGATE` with an error-ignoring option, or
wrap the calculation in `IFERROR`, if the placeholder shouldn't break
the total:

<ExcelCode>{`=AGGREGATE(9, 6, A1:A10)`}</ExcelCode>

### Confusing NA() with ISNA()

`NA()` **creates** the `#N/A` error. `ISNA()` **tests** for it. They
sound alike and are often used together (`NA()` to mark a placeholder,
`ISNA()` elsewhere to detect it) but do opposite jobs.

### Expecting a chart to plot #N/A as zero

Charts treat `#N/A` as "no data point here" and leave a gap — if a
zero value is actually wanted on the chart, use `0` instead of
`NA()`; they produce visibly different results.

## Related functions

- [ISNA](/docs/info/isna) — tests whether a value is specifically
  the #N/A error that NA() creates.
- [IFNA](/docs/logical/ifna) — replaces a #N/A result (including one
  from NA()) with a fallback value in one step.
- [IFERROR](/docs/logical/iferror) — catches any error, not just
  #N/A, replacing it with a fallback value.
