Test whether a number is odd — decimal values are truncated toward
zero first, so `3.9` and `3.1` both test as odd, the same as plain
`3`.

## Return value

`TRUE` if `number` (after truncating any decimal portion) is odd;
`FALSE` if even.

## Description

ISODD truncates `number` toward zero before checking — it doesn't
round. `3.9` truncates to `3` (odd, so `TRUE`), while `2.1` truncates
to `2` (even, so `FALSE`), regardless of which whole number the
decimal value is actually closer to.

<Callout type="warn">
  Truncation, not rounding — `ISODD(3.9)` returns `TRUE` because `3.9`
  truncates to `3`, not because it rounds to a nearby odd number. This
  matters most with values close to a whole number boundary, like
  `2.99` (truncates to `2`, even) versus `3.01` (truncates to `3`,
  odd).
</Callout>

## Common errors

### #VALUE! — a non-numeric argument

<ExcelCode>{`ISODD("three") → #VALUE!`}</ExcelCode>

`number` must be an actual number or a value that clearly converts to
one — text like `"three"` isn't recognized, even though it reads as a
number to a person.

### Expecting rounding instead of truncation

<ExcelCode>{`ISODD(2.99) → FALSE (truncates to 2, not rounded to 3)`}</ExcelCode>

If the intent is to check the *rounded* value's parity, wrap in
`ROUND` first: `ISODD(ROUND(2.99, 0))`.
