Return a single aggregated value from an OLAP cube — the most
commonly used cube function, since it's the one that actually
retrieves a number (a total, an average, a count) rather than a
member, set, or property.

## Return value

The aggregated value (using the cube's default measure, or a measure
named explicitly in one of the `member_expression` arguments) at the
intersection of every supplied member and set.

## Description

CUBEVALUE intersects however many members and sets are passed to it
and returns the aggregated number at that specific point in the
cube — most often a sum, but whatever the cube's own measure
definition specifies. Passing zero `member_expression` arguments
returns the cube's overall grand total, since an empty intersection
means "every member of every dimension."

<Callout type="warn">
  OLAP databases represent a blank/missing value as a zero-length
  text string (`""`), not a numeric zero — `SUM` handles this
  transparently, but a direct comparison like `CUBEVALUE(...) = 0`
  can behave unexpectedly on a cell that's actually empty rather than
  truly zero. Wrap the result in `N()` or test with `ISTEXT()` first
  if that distinction matters.
</Callout>

<ExcelCode>{`=CUBEVALUE("Sales", "[Measures].[Total Sales]") → the grand total across the whole cube`}</ExcelCode>

<ExcelCode>{`=CUBEVALUE("Sales", "[Measures].[Total Sales]", "[Product].[Category].[Bikes]", "[Geography].[Region].[Northwest]") → total bike sales in the Northwest region only`}</ExcelCode>

## Common errors

### #NAME? — the connection doesn't exist or the server is unreachable

`connection` must exactly match an existing workbook connection name
pointing to a reachable OLAP server.

### #N/A — a member doesn't exist, or the members come from incompatible dimensions

Every `member_expression` needs to identify a real member, and a set
passed as one of the arguments can't mix members from dimensions the
intersection can't reconcile.

### A result that looks like blank text instead of 0

OLAP nulls come back as zero-length strings, not numeric zeros — this
shows as visually blank rather than `0`, and can throw off formulas
expecting a real number rather than text.
