Return the nth member in a set, by position — the top sales
performer, the 3rd-highest product by revenue, or any other specific
rank, once the set has already been sorted the right way.

## Return value

The member at position `rank` within `set_expression`, in whatever
order that set is currently in.

## Description

CUBERANKEDMEMBER only understands **position**, not any concept of
"best" or "highest" on its own — `rank = 1` always means "whatever
is first in this set right now." Getting a genuinely meaningful
top-N or bottom-N result depends entirely on sorting the set
correctly first, which is `CUBESET`'s `sort_order` argument's job, not
something CUBERANKEDMEMBER controls.

<Callout type="warn">
  Passing an unsorted set (or one sorted the wrong direction) to
  CUBERANKEDMEMBER silently returns a real member — just not the one
  that was actually intended. There's no error to catch this, since
  "first in the set" is always a valid answer regardless of whether
  the set was meaningfully ordered beforehand.
</Callout>

<ExcelCode>{`=CUBERANKEDMEMBER("Sales", A1, 1) → the top item, if A1's CUBESET is sorted descending by the relevant measure`}</ExcelCode>

<ExcelCode>{`=CUBERANKEDMEMBER("Sales", A1, 3, "3rd Place") → the 3rd item, captioned "3rd Place"`}</ExcelCode>

## Common errors

### #NAME? — the connection doesn't exist or the server is unreachable

`connection` must exactly match an existing workbook connection name
pointing to a reachable OLAP server.

### #N/A — rank exceeds the set's actual size

Requesting `rank = 10` from a set that only has 6 members returns
`#N/A` — check the set's size with `CUBESETCOUNT` first if the
count isn't already known.

### A "top" result that isn't actually the top value

The set wasn't sorted the way assumed — `CUBERANKEDMEMBER` returns
whatever sits at that position in the set's *current* order, which
is only meaningful once `CUBESET`'s `sort_order` has been set up
correctly.
