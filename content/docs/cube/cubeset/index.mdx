Send a set expression to the cube server, which builds the set there
and returns it to Excel as a single reference — the multi-member
equivalent of what `CUBEMEMBER` does for one member at a time.

## Return value

A reference to the calculated set, displayed using `caption` if
supplied. The set itself is computed and held on the cube server, not
inside the workbook.

## Description

CUBESET is the set-building counterpart to `CUBEMEMBER` — instead of
identifying one member, it defines a whole collection (say, "every
product in the Bikes category") as a single reusable reference. That
reference can then be passed directly into `CUBEVALUE` to aggregate
across the whole set, into `CUBERANKEDMEMBER` to pull out a specific
ranked item from it, or into `CUBESETCOUNT` to just count how many
items it contains.

`sort_order` takes any integer from 0 to 6:

| Value | Constant | Effect |
|---|---|---|
| 0 | SortNone | Leaves the set in its existing order (default) |
| 1 | SortAscending | Sorts ascending by `sort_by` |
| 2 | SortDescending | Sorts descending by `sort_by` |
| 3 | SortAlphaAscending | Sorts alphabetically, ascending |
| 4 | SortAlphaDescending | Sorts alphabetically, descending |
| 5 | SortNaturalAscending | Sorts in the cube's natural hierarchy order, ascending |
| 6 | SortNaturalDescending | Sorts in the cube's natural hierarchy order, descending |

Only `sort_order` values 1 and 2 use `sort_by` — every other value
ignores it entirely, and supplying `sort_by` without `sort_order`
being 1 or 2 has no effect.

<ExcelCode>{`=CUBESET("Sales", "[Product].[Category].[Bikes].Children") → every individual bike product`}</ExcelCode>

<ExcelCode>{`=CUBESET("Sales", "[Geography].[Region].Members", "All Regions", 1, "[Measures].[Total Sales]") → every region, sorted ascending by total sales`}</ExcelCode>

## Common errors

### #NAME? — the connection doesn't exist or the server is unreachable

`connection` must exactly match an existing workbook connection name
pointing to a reachable OLAP server.

### #N/A — the set expression is invalid, or mixes incompatible dimensions

`set_expression` must be valid MDX, and every tuple in the resulting
set needs to come from dimensions the set can reconcile together.

### #VALUE! — sort_order is 1 or 2 with sort_by omitted

Ascending or descending sort (values 1 and 2) genuinely needs
something to sort by — supply `sort_by`, or use one of the other
sort_order values that don't require it.
