Return the value of a named property attached to a cube member —
pulling out an attribute like a product's color or a customer's
region, rather than an aggregated measure.

## Return value

The value of `property` for the member identified by
`member_expression` — the specific attribute's value, not a
measure or aggregation.

## Description

Cube members often carry attributes beyond their name and position in
a hierarchy — a Product member might have a Color, a Customer member
might have a Region, a Date member might have a Fiscal Quarter. These
attributes are exposed as **member properties**, and
CUBEMEMBERPROPERTY is the function that retrieves one by name for a
specific member.

<Callout type="warn">
  CUBEMEMBERPROPERTY specifically does not work against an Excel Data
  Model that's been edited in Power Pivot — Power Pivot models aren't
  structured as true multidimensional cubes, even though other cube
  functions can sometimes query them. A genuine SQL Server Analysis
  Services (or later) connection is needed for member properties to
  resolve correctly.
</Callout>

<ExcelCode>{`=CUBEMEMBERPROPERTY("Sales", "[Product].[Product Name].[Mountain-200]", "Color") → "Silver"`}</ExcelCode>

## Common errors

### #NAME? — the connection doesn't exist or the server is unreachable

`connection` must exactly match an existing workbook connection name
pointing to a reachable OLAP server.

### #N/A — the member doesn't exist, or property isn't a real property name

Both `member_expression` and `property` need to resolve to something
that genuinely exists in the cube — a mistyped property name returns
`#N/A` rather than a blank or default value.

### No result at all against a Power Pivot Data Model

CUBEMEMBERPROPERTY is documented as not working against Excel Data
Models edited in Power Pivot, since those aren't true multidimensional
cubes — a genuine OLAP/SSAS connection is required.
