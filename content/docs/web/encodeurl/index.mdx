Percent-encode a piece of text so it's safe to drop into a URL —
turning spaces, punctuation, and other characters a URL can't contain
literally into their `%XX` hexadecimal equivalents.

## Return value

The input text with non-alphanumeric characters replaced by a `%`
followed by their hexadecimal code — standard percent-encoding.
Letters, digits, and a small set of characters that are already safe
in a URL are left unchanged.

## Description

ENCODEURL exists almost entirely to be nested inside a
[WEBSERVICE](/docs/web/webservice) URL: any part of a URL built from
a cell value — a search term, a name, free-text input — can contain
spaces or symbols that would otherwise break the request or silently
change its meaning.

<Callout type="warn">
  ENCODEURL encodes a space as **`%20`**, standard URI encoding — not
  as a `+`, which is what form-encoded (`application/x-www-form-
  urlencoded`) query strings expect instead. Most modern web APIs
  accept `%20` for spaces in a query string, but a service that
  specifically expects `+` will need a manual `SUBSTITUTE(..., " ",
  "+")` instead of relying on ENCODEURL alone.
</Callout>

Excel has no built-in DECODEURL function — reversing percent-encoding
back to plain text isn't natively supported and would need a helper
formula or Power Query's `Uri.UnescapeDataString` equivalent.

## Common errors

ENCODEURL has no documented error conditions of its own — it always
returns a text value. Problems downstream are more often a sign that
encoding wasn't applied where it should have been (a raw, un-encoded
cell value breaking a WEBSERVICE URL), or that the target API expects
`+` instead of `%20` for spaces.
