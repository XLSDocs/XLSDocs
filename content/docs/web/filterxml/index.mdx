Pull a specific value, or set of values, out of an XML string by
matching an XPath expression against it. FILTERXML is XML's answer to
the question WEBSERVICE's raw text output raises: "which part of this
response do I actually need?"

## Return value

The text content of the node(s) matching `xpath`. Entered as a
single-cell formula, only the first matching node's value is
returned. In Excel 365, a formula that can match multiple nodes
automatically spills the full set as a dynamic array; in pre-365
Excel, the formula must be confirmed with **Ctrl+Shift+Enter** as a
legacy array formula to get more than the first match.

## Description

FILTERXML expects a genuinely well-formed XML string — not JSON, and
not loosely-formatted markup. It's most useful directly on
WEBSERVICE's output, turning a full XML API response into just the
one or two fields actually needed on the sheet.

<Callout type="warn">
  Like WEBSERVICE, FILTERXML **does not work in Excel for the web**,
  and it appears in the Excel for Mac function gallery without ever
  returning results there — both depend on Windows operating system
  features.
</Callout>

XML namespaces are supported, but only if the XPath expression uses a
matching, validly-formed prefix — many real-world feeds (RSS/Atom
feeds especially) declare a default namespace without a prefix at
all, which is a common source of an unmatched XPath that looks
correct but returns nothing.

## Common errors

### #VALUE! — xml isn't valid XML

<ExcelCode>{`FILTERXML("not xml", "//price") → #VALUE!`}</ExcelCode>

FILTERXML requires well-formed XML — a missing closing tag, an
unescaped `&`, or content that's actually JSON or HTML will all
produce this error.

### #VALUE! — an invalid namespace prefix

If the XML string contains a namespace declared with an invalid
prefix, FILTERXML returns `#VALUE!` rather than attempting to work
around it. Check the raw XML for how the namespace prefix is actually
declared before writing the XPath.

### The formula only returns the first match

If `xpath` matches multiple nodes but the formula was entered as an
ordinary single-cell formula (not confirmed with Ctrl+Shift+Enter in
pre-365 Excel, or in a range sized for the spill in 365), only the
first match comes back. This looks like a bug but is expected
behavior — resize the formula's output range or use dynamic arrays to
see every match.
