Convert a number from one unit of measurement to another — distances,
weights, temperatures, volumes, pressures, and dozens of other unit
families, all through a single function instead of memorizing
conversion factors.

## Return value

`number`, converted from `from_unit` to `to_unit`.

## Description

CONVERT covers around a dozen measurement categories — weight/mass,
distance, time, pressure, force, energy, power, magnetism,
temperature, volume, area, and speed — each with its own set of unit
abbreviations (`"kg"`, `"mi"`, `"hr"`, `"Pa"`, `"N"`, `"J"`, `"HP"`,
`"T"`, `"C"`, `"l"`, `"m2"`, `"mph"`, and many more). A conversion only
works between two units in the **same** category — converting a
distance into a weight, for instance, is meaningless and returns
`#N/A` rather than a number.

<Callout type="warn">
  Most metric unit abbreviations can be prefixed with a standard metric
  (or binary) scale prefix — `"k"` for kilo (`×1000`), `"c"` for centi
  (`×0.01`), `"M"` for mega (`×1,000,000`), and so on. **Temperature
  units and non-metric units can't take a prefix at all** — there's no
  such thing as `"kC"` (kilo-Celsius) or `"kmi"` (kilo-miles).
</Callout>

One mile converts to `1.609344` kilometers, `1609.344` meters, or
exactly `5280` feet — three different units, all within the same
"distance" category, so all three conversions succeed.

## Common errors

### #N/A — from_unit and to_unit are in different categories

<ExcelCode>{`CONVERT(2.5, "ft", "sec") → #N/A — feet (distance) and seconds (time) aren't compatible`}</ExcelCode>

A conversion only makes sense within a single measurement category.
Trying to convert a distance into a time (or any other mismatched
pairing) returns `#N/A`, the same error Excel uses for "this lookup
doesn't exist" elsewhere.

### #N/A — a mistyped or wrong-case unit abbreviation

<ExcelCode>{`CONVERT(1, "KG", "g") → #N/A — unit abbreviations are case-sensitive; "kg" works, "KG" doesn't`}</ExcelCode>

Every unit and prefix abbreviation has one specific, exact casing.
`"kg"` (kilogram) and `"KG"` are not the same thing as far as CONVERT
is concerned — the uppercase version simply isn't a recognized unit,
so it errors instead of guessing what was meant.

### Silently getting a wildly wrong answer from a case mix-up

<ExcelCode>{`CONVERT(1, "Mg", "g") → 1,000,000, but CONVERT(1, "mg", "g") → 0.001 — a billion-fold difference from one letter's case`}</ExcelCode>

Unlike a flat-out typo (which at least errors loudly), swapping the
case of a *valid* prefix doesn't error at all — it just silently
computes the wrong unit's conversion. `"M"` is the mega prefix
(`×1,000,000`); `"m"` is the milli prefix (`×0.001`) when used as a
prefix, or plain meters when used as a whole unit. Double-check
capitalization carefully, especially for one-letter prefixes.
