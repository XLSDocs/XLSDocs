Pull the real coefficient `x` out of a complex number written as text
in `x + yi` (or `x + yj`) form.

## Return value

The real coefficient `x` of `inumber`, as a plain number.

## Description

IMREAL parses `inumber`'s text and returns just the real part, discarding
the imaginary term entirely. A plain number with no imaginary suffix at
all — `IMREAL(4)` — still works, returning `4`, since a real number is
just a complex number with an imaginary coefficient of 0.

## Try it

<TryIt
  data={{ '3+4i': '3', '1-2i': '1', '5-12i': '5' }}
  defaultValue="3+4i"
  label={'Live preview — =IMREAL("{value}")'}
  fieldLabel="inumber"
/>

`IMREAL("3+4i")` returns `3` — just the real coefficient, with the
`+4i` term dropped entirely. The sign of the imaginary part doesn't
affect the real part at all: `IMREAL("1-2i")` still returns the plain
real coefficient, `1`.

## Common errors

### #NUM! — text that isn't a valid complex number

<ExcelCode>{`IMREAL("hello") → #NUM!`}</ExcelCode>

`inumber` has to be parseable as `x + yi`/`x + yj` text (or a plain
number). Text that doesn't match that pattern at all returns `#NUM!`.

### Expecting IMREAL to also validate the suffix

<ExcelCode>{`IMREAL("3+4i") and IMREAL("3+4j") both return 3 — IMREAL doesn't care which suffix was used`}</ExcelCode>

Unlike functions that combine two or more complex numbers (which
require matching suffixes), IMREAL only ever looks at a single
`inumber` — there's no second value to mismatch against, so it accepts
either suffix without complaint.
