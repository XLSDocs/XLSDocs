Compute the hyperbolic cosine of a complex number — closely related
to [IMCOS](/docs/engineering/imcos), but with the roles of ordinary
and hyperbolic trigonometry swapped between the real and imaginary
parts.

## Return value

The hyperbolic cosine of `inumber`, as text in `x + yi`/`x + yj` form.

## Description

For a complex number `x + yi`, IMCOSH computes `cosh(x)cos(y) +
i·sinh(x)sin(y)`. Compare this to
[IMCOS](/docs/engineering/imcos)'s formula, `cos(x)cosh(y) −
i·sin(x)sinh(y)` — the ordinary and hyperbolic trig functions swap
places between the two (and note the sign on the imaginary term also
flips). When `y` is `0` (a purely real input), the formula collapses
to exactly `cosh(x)`, so IMCOSH never disagrees with the ordinary
`COSH` function on a real input.

<TryIt

  fieldLabel="inumber"

`IMCOSH("3+4i")` returns `-6.5807-7.5816i`. The pure imaginary unit
`"i"` gives exactly `cos(1)` (`0.5403`) — a plain real number with no
imaginary component, following the identity `cosh(iy) = cos(y)`.

## Common errors

### #VALUE! — inumber is a logical value

<ExcelCode>{`IMCOSH(TRUE) → #VALUE!`}</ExcelCode>

Passing `TRUE` or `FALSE` directly (rather than complex-number text)
returns `#VALUE!`.

### #NUM! — text that isn't a valid complex number

<ExcelCode>{`IMCOSH("hello") → #NUM!`}</ExcelCode>

`inumber` has to be parseable as `x + yi`/`x + yj` text (or a plain
number). Text that doesn't match that pattern at all returns `#NUM!`.

### Mixing up which terms are hyperbolic vs. ordinary

<ExcelCode>{`IMCOSH(x + yi) = cosh(x)cos(y) + i·sinh(x)sin(y) — hyperbolic terms apply to x, ordinary terms apply to y`}</ExcelCode>

It's easy to expect IMCOSH's formula to just be "the hyperbolic
version" of IMCOS's straight across. In fact the two formulas use
cosh/sinh and cos/sin in exactly swapped positions (and IMCOSH's
imaginary term is positive, while IMCOS's is negative) — worth
double-checking against the formula directly rather than guessing by
pattern-matching against IMCOS.
