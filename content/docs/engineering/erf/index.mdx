## Return value

The error function integrated between `lower_limit` and `upper_limit`
(or between `0` and `lower_limit`, if `upper_limit` is omitted).

## Description

The error function, `erf(x)`, is defined as `(2/√π) ∫₀ˣ e^(-t²) dt` —
the integral of a (scaled) Gaussian bell curve from `0` out to `x`.
It's directly related to the normal distribution's cumulative
probability: the area under a standard normal curve between `-x` and
`x` is exactly `erf(x/√2)`. ERF's two-argument form additionally
allows integrating between **any** two bounds, not just from `0` —
`ERF(a, b)` is equivalent to `ERF(b) − ERF(a)`.

<Callout type="check">
  Erf is an **odd function**: `ERF(-x)` always equals `-ERF(x)`. This
  follows directly from `e^(-t²)` being symmetric around `0` — the
  area accumulated going right from `0` exactly mirrors the area
  accumulated going left.
</Callout>

## Try it

<TryIt
  data={{ '0.5': '0.5205', '1': '0.8427', '1.5': '0.9661' }}
  defaultValue="1"
  label={'Live preview — =ERF({value})'}
  fieldLabel="lower_limit"
/>

`ERF(1)` returns `0.8427` — about 84% of the total area under the
curve has accumulated by `x=1`. Calling `ERF(0.5, 1)` instead (the
two-argument form) returns `0.3222` — exactly `ERF(1) − ERF(0.5)`
(`0.8427 − 0.5205`), the area between those two points rather than
from `0`.

## Common errors

### #VALUE! — lower_limit or upper_limit is nonnumeric

<ExcelCode>{`ERF("x") → #VALUE!`}</ExcelCode>

Both arguments must be actual numbers — text that can't be interpreted
as one returns `#VALUE!`.

### Forgetting ERF(a, b) means "from a to b," not "from 0 to b minus from 0 to a stated separately"

<ExcelCode>{`ERF(0.5, 1) → 0.3222, the SAME as ERF(1)-ERF(0.5) — a single call already does the subtraction`}</ExcelCode>

It's easy to reach for `ERF(1) - ERF(0.5)` out of habit, not realizing
the two-argument form already does exactly that in one call. Both
produce the identical result — the two-argument form is just more
direct.

### Expecting an error from a negative input

<ExcelCode>{`ERF(-1) → -0.8427, a valid result — not an error`}</ExcelCode>

Since erf is mathematically defined for every real number (and is an
odd function), a negative `lower_limit` or `upper_limit` returns a
valid, correctly-signed result rather than erroring.
