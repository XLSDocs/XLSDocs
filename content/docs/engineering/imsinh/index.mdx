Compute the hyperbolic sine of a complex number — closely related to
[IMSIN](/docs/engineering/imsin), but with the roles of ordinary and
hyperbolic trigonometry swapped between the real and imaginary parts.

## Return value

The hyperbolic sine of `inumber`, as text in `x + yi`/`x + yj` form.

## Description

For a complex number `x + yi`, IMSINH computes `sinh(x)cos(y) +
i·cosh(x)sin(y)`. Compare this to
[IMSIN](/docs/engineering/imsin)'s formula, `sin(x)cosh(y) +
i·cos(x)sinh(y)` — the ordinary and hyperbolic trig functions swap
places between the two. This mirrors the identity `sinh(iz) = i·sin(z)`
that connects hyperbolic and ordinary sine in general. When `y` is `0`
(a purely real input), the formula collapses to exactly `sinh(x)`, so
IMSINH never disagrees with the ordinary `SINH` function on a real
input.

`IMSINH("3+4i")` returns `-6.5481-7.6192i`. The pure imaginary unit
`"i"` gives exactly `sin(1)i` (`0.8415i`) — a clean illustration of
the identity `sinh(iy) = i·sin(y)`, the mirror image of
[IMSIN](/docs/engineering/imsin)'s own `sin(iy) = i·sinh(y)`.

## Common errors

### #VALUE! — inumber is a logical value

<ExcelCode>{`IMSINH(TRUE) → #VALUE!`}</ExcelCode>

Passing `TRUE` or `FALSE` directly (rather than complex-number text)
returns `#VALUE!`.

### #NUM! — text that isn't a valid complex number

<ExcelCode>{`IMSINH("hello") → #NUM!`}</ExcelCode>

`inumber` has to be parseable as `x + yi`/`x + yj` text (or a plain
number). Text that doesn't match that pattern at all returns `#NUM!`.

### Mixing up which terms are hyperbolic vs. ordinary

<ExcelCode>{`IMSINH(x + yi) = sinh(x)cos(y) + i·cosh(x)sin(y) — hyperbolic terms apply to x, ordinary terms apply to y`}</ExcelCode>

It's easy to expect IMSINH's formula to just be "the hyperbolic
version" of IMSIN's straight across. In fact the two formulas use
sinh/cosh and sin/cos in exactly swapped positions — worth
double-checking against the formula directly rather than guessing by
pattern-matching against IMSIN.
