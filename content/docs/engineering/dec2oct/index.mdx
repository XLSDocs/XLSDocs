Convert a decimal number to octal — the reverse of `OCT2DEC`, covering
a 30-bit signed range, wider than binary but narrower than
hexadecimal.

## Return value

The octal equivalent of `number`, as text — padded to `places`
characters if supplied and `number` is positive.

## Description

DEC2OCT supports a 30-bit signed range — each of its 10 possible octal
characters represents 3 binary bits, so 10 octal digits cover 30 bits
total, one of which is the two's-complement sign bit. That puts its
range between `DEC2BIN`'s narrow 10-bit limit and `DEC2HEX`'s much
wider 40-bit limit.

<Callout type="idea">
  Octal sees far less everyday use than hex in modern spreadsheet
  work — it mostly comes up in legacy contexts, like older Unix-style
  file-permission notation (`755`, `644`), where DEC2OCT can still be
  the right tool.
</Callout>

## Try it

<TryIt
  data={{ '8': '10', '26': '32', '255': '377', '-5': '7777777773' }}

`DEC2OCT(26)` returns `32`. `DEC2OCT(-5)` returns the full
10-character `7777777773`, the two's-complement octal representation
of -5 across the full 30-bit width.

## Common errors

### #NUM! — number is outside the valid 30-bit range

<ExcelCode>{`DEC2OCT(600000000) → #NUM!`}</ExcelCode>

`number` must fall between -536,870,912 and 536,870,911.

### #NUM! — places is too small for the result

<ExcelCode>{`DEC2OCT(255, 2) → #NUM!, since "377" needs 3 characters`}</ExcelCode>

`places` must be large enough to hold every digit of the actual
result — it can only pad with extra leading zeros, never truncate.
