## Return value

The imaginary coefficient `y` of `inumber`, as a plain number (without
the `i`/`j` suffix).

## Description

IMAGINARY parses `inumber`'s text and returns just the imaginary
coefficient, discarding the real term and the suffix letter itself. A
plain real number with no imaginary part — `IMAGINARY(4)` — returns
`0`, since a real number is just a complex number whose imaginary
coefficient happens to be zero.

<Callout type="warn">
  The result is a bare number, not `"4i"` or similar — `IMAGINARY("0-j")`
  returns the number `-1`, not the text `"-j"` or `"-1j"`. It's easy to
  expect the suffix to carry through, but IMAGINARY strips it entirely.
</Callout>

`IMAGINARY("3+4i")` returns `4` — just the imaginary coefficient, with
the `3+` real term and the `i` suffix both dropped. A negative
imaginary term, like in `"1-2i"`, comes back as a genuinely negative
number (`-2`), not as `2` with the sign discarded.

## Common errors

### #NUM! — text that isn't a valid complex number

<ExcelCode>{`IMAGINARY("hello") → #NUM!`}</ExcelCode>

`inumber` has to be parseable as `x + yi`/`x + yj` text (or a plain
number). Text that doesn't match that pattern at all returns `#NUM!`.

### Expecting the suffix to carry through into the result

<ExcelCode>{`IMAGINARY("3+4i") → 4, not "4i" — the suffix is stripped from the returned number`}</ExcelCode>

IMAGINARY always returns a plain number. If the result needs to be
displayed back as part of a complex number (with its `i`/`j` suffix
restored), rebuild it with [COMPLEX](/docs/engineering/complex).
