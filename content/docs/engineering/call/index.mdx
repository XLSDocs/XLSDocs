Call a procedure in a dynamic link library (DLL) or code resource
directly from a formula. CALL predates VBA and COM add-ins by years,
and comes with a hard restriction most functions on this site don't
have: **it only works on an Excel 4.0 (XLM) macro sheet, not an
ordinary worksheet.**

## Syntax

CALL has two forms. With a code resource already registered (its ID
came from [REGISTER.ID](/docs/engineering/register-id)):

<ExcelCode>{`=CALL(register_id, [argument1], ...)`}</ExcelCode>

Registering and calling in one step:

<ExcelCode>{`=CALL(module_text, procedure, type_text, [argument1], ...)`}</ExcelCode>

## Return value

Whatever the called DLL procedure returns, interpreted according to
the return-type code in `type_text`.

## Description

CALL is a bridge from a formula into compiled DLL code — the same
underlying mechanism VBA's `Declare` statement uses, but exposed as a
worksheet-style function from the Excel 4.0 macro era. It's almost
never written by hand today; where it survives, it's usually in a
workbook built before VBA existed, calling into a Windows API
function or a custom add-in DLL.

<Callout type="warn">
  **CALL only works on an Excel 4.0 (XLM) macro sheet** — a legacy
  sheet type, distinct from an ordinary worksheet, that still ships
  hidden inside modern Excel for backward compatibility. Typing
  `=CALL(...)` into a regular worksheet cell does not work the way
  it does on an XLM macro sheet. Microsoft's own documentation also
  warns that calling the wrong procedure, or passing mismatched
  argument types, can crash Excel — this is a function for advanced,
  deliberate use, not everyday formulas.
</Callout>

## Common errors

### Formula entered on a normal worksheet, not an XLM macro sheet

CALL is designed for Excel 4.0 macro sheets. On an ordinary worksheet
it won't behave the way Microsoft's own CALL documentation describes
— this is the most common source of confusion with the function.

### Excel crashes or behaves unpredictably

Mismatched argument types against `type_text`, or calling a
procedure that wasn't designed to be invoked this way, can corrupt
memory and crash Excel. Only call a DLL procedure specifically
documented for use with CALL.
