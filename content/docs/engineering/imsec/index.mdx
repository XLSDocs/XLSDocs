## Return value

The secant of `inumber`, as text in `x + yi`/`x + yj` form.

## Description

IMSEC is the reciprocal of [IMCOS](/docs/engineering/imcos) — `1 /
IMCOS(inumber)` — the same relationship real secant has to real
cosine. Since IMCOS reduces to ordinary `COS` on a purely real input,
IMSEC reduces to ordinary `SEC` there too.

## Try it

<TryIt
  data={{ '3+4i': '-0.0363+0.0052i', 'i': '0.6481', '1+i': '0.4983+0.5911i' }}
  defaultValue="3+4i"
  label={'Live preview — =IMSEC("{value}")'}
  fieldLabel="inumber"
/>

`IMSEC("3+4i")` returns `-0.0363+0.0052i`. The pure imaginary unit
`"i"` gives exactly `1/cosh(1)` (`0.6481`) — a plain real number, with
no imaginary component at all, since IMCOS itself returns a purely
real value for a purely imaginary input.

## Common errors

### #VALUE! — inumber is a logical value

<ExcelCode>{`IMSEC(TRUE) → #VALUE!`}</ExcelCode>

Passing `TRUE` or `FALSE` directly (rather than complex-number text)
returns `#VALUE!`.

### #NUM! — text that isn't a valid complex number

<ExcelCode>{`IMSEC("hello") → #NUM!`}</ExcelCode>

`inumber` has to be parseable as `x + yi`/`x + yj` text (or a plain
number). Text that doesn't match that pattern at all returns `#NUM!`.

### Confusing IMSEC with IMCSC

<ExcelCode>{`IMSEC(z) = 1/IMCOS(z), NOT 1/IMSIN(z) — that reciprocal is IMCSC instead`}</ExcelCode>

Secant is the reciprocal of *cosine*, not sine — a common mix-up given
how similar the names "secant" and "cosecant" look at a glance. The
reciprocal of [IMSIN](/docs/engineering/imsin) is
[IMCSC](/docs/engineering/imcsc), a different function entirely.
