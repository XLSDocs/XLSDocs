Compute the complementary error function integrated from `x` to
infinity — simply `1 - ERF(x)`, useful for working directly with the
"tail" probability beyond a point instead of the area up to it.

## Return value

The complementary error function integrated between `x` and infinity.

## Description

ERFC is defined as `1 - ERF(x)` — where
[ERF](/docs/engineering/erf) measures the area under the Gaussian
curve from `0` out to `x`, ERFC measures everything **left over**,
from `x` all the way out to infinity. The two functions are two ways
of describing the same underlying curve: whatever fraction ERF hasn't
yet accumulated by `x`, ERFC reports directly, without needing a
separate subtraction step.

## Try it

<TryIt
  data={{ '0.5': '0.4795', '1': '0.1573', '1.5': '0.0339' }}
  defaultValue="1"
  label={'Live preview — =ERFC({value})'}
  fieldLabel="x"
/>

`ERFC(1)` returns `0.1573` — exactly `1 - ERF(1)` (`1 - 0.8427`). As
`x` increases, ERFC shrinks toward `0` (`0.0339` at `x=1.5`), since
there's less and less of the curve left beyond an ever-larger cutoff
point.

## Common errors

### #VALUE! — x is nonnumeric

<ExcelCode>{`ERFC("x") → #VALUE!`}</ExcelCode>

`x` must be an actual number — text that can't be interpreted as one
returns `#VALUE!`.

### Computing 1-ERF(x) manually instead of using ERFC

<ExcelCode>{`ERFC(1) and 1-ERF(1) both return 0.1573 — ERFC just saves writing the subtraction`}</ExcelCode>

There's nothing wrong with `1-ERF(x)` directly — it gives the identical
answer — but `ERFC(x)` reads more clearly wherever the "tail past x"
framing is the natural way to think about the calculation.

### Expecting ERFC to approach 2, not 1, for a very negative x

<ExcelCode>{`ERFC(-3) is close to 2, not close to 1 — since ERF(-3) is close to -1`}</ExcelCode>

Because `ERF(x)` ranges from `-1` to `1` (not `0` to `1`), `ERFC(x) =
1 - ERF(x)` actually ranges from `0` to `2` — a very negative `x`
pushes `ERF(x)` close to `-1`, which makes `ERFC(x)` close to `2`, not
`1`.
