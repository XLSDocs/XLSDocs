Build a complex number out of separate real and imaginary
coefficients, returned as text in `x + yi` (or `x + yj`) form — the
starting point for every other complex-number function on this site,
which all expect their input already in this text format.

## Return value

A text string representing the complex number, in `x + yi` (or `x + yj`)
form.

## Description

Every other complex-number function on this site — IMSUM, IMABS,
IMARGUMENT, and the rest — expects its complex-number arguments as
text in this exact `x + yi` format, since Excel has no dedicated
complex-number data type. COMPLEX is how that text gets built in the
first place: it takes two plain numbers and stitches them into the
string those other functions can read. A zero coefficient drops out of
the result entirely rather than printing as `0` — `COMPLEX(3, 0)`
returns `3`, not `3+0i`, and `COMPLEX(0, 1)` returns `i`, not `0+1i`.

<Callout type="warn">
  The `suffix` argument only accepts lowercase `"i"` or `"j"` — typing
  `"I"` or `"J"` returns `#VALUE!`, not a case-insensitive match. This
  matters beyond COMPLEX itself: every function that takes two or more
  complex numbers requires all of them to use the *same* suffix, so a
  stray uppercase or mismatched suffix anywhere in a calculation chain
  can break a later IMSUM or IMPRODUCT call downstream.
</Callout>

## Try it

<TryIt
  data={{ '4': '3+4i', '-4': '3-4i', '0': '3' }}
  defaultValue="4"
  label={'Live preview — =COMPLEX(3, {value})'}
  fieldLabel="i_num"

`COMPLEX(3, 4)` returns `3+4i` — the pairing used as the running
example across every other complex-number function on this site. A
negative `i_num` flips the sign shown (`3-4i`); an `i_num` of exactly
`0` drops the imaginary term entirely, returning the plain real number
`3`.

## Common errors

### #VALUE! — a non-numeric real_num or i_num

<ExcelCode>{`COMPLEX("abc", 4) → #VALUE!`}</ExcelCode>

Both `real_num` and `i_num` must be numbers. Text that can't be
interpreted as a number returns `#VALUE!`.

### #VALUE! — an invalid or uppercase suffix

<ExcelCode>{`COMPLEX(3, 4, "I") → #VALUE! — must be lowercase "i", not uppercase "I"`}</ExcelCode>

`suffix` only accepts the exact lowercase characters `"i"` or `"j"`.
Any other text, including the correctly-spelled letter in the wrong
case, returns `#VALUE!` rather than being auto-corrected.

### Mixing suffixes across a later calculation

<ExcelCode>{`IMSUM(COMPLEX(3,4,"j"), "1-2i") → #VALUE! — one number uses "j", the other uses "i"`}</ExcelCode>

COMPLEX itself won't catch this — the mismatch only surfaces once a
downstream function like IMSUM or IMPRODUCT tries to combine two
complex numbers built with different suffixes. Pick one suffix per
calculation and use it consistently throughout.
