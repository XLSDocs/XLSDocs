Evaluate the Bessel function of the first kind, order `N`, at `X` — a
family of oscillating functions that show up naturally whenever a
physical problem (vibration, heat, waves) has circular or cylindrical
symmetry, the way sine and cosine show up for problems with straight-line
symmetry.

## Return value

The value of the order-`N` Bessel function of the first kind, evaluated
at `X`.

## Description

BESSELJ solves a specific second-order differential equation (Bessel's
equation) that turns up repeatedly in physics and engineering problems
with cylindrical or circular symmetry — the vibration modes of a
circular drumhead, heat flow through a cylindrical rod, and signal
propagation in a circular waveguide all involve Bessel functions of
the first kind. Like sine and cosine, `J_n(x)` oscillates as `x`
increases — but unlike sine and cosine, its amplitude gradually decays
rather than staying constant.

<Callout type="check">
  Bessel functions of different orders aren't independent — they
  satisfy the recurrence `J_{n-1}(x) + J_{n+1}(x) = (2n/x)·J_n(x)`. At
  `x=1.9, n=1`: `J_0(1.9) + J_2(1.9) = 0.2818 + 0.3299 = 0.6117`, and
  `(2/1.9)·J_1(1.9) = (2/1.9)×0.5812 = 0.6117` — the same value either
  way, a genuine mathematical identity rather than a coincidence.
</Callout>

At a fixed `X` of `1.9`, the three lowest orders give noticeably
different values — `0.2818`, `0.5812`, and `0.3299` — since each order
solves a different version of Bessel's equation, not just a scaled
copy of the others.

## Common errors

### #NUM! — N is negative

<ExcelCode>{`BESSELJ(1.9, -1) → #NUM!`}</ExcelCode>

The order `N` must be `0` or greater. A negative order returns
`#NUM!`.

### #VALUE! — X or N is nonnumeric

<ExcelCode>{`BESSELJ("x", 2) → #VALUE!`}</ExcelCode>

Both arguments must be actual numbers — text that can't be interpreted
as one returns `#VALUE!`.

### Expecting N to round instead of truncate

<ExcelCode>{`BESSELJ(1.9, 2.7) → 0.3299, using order 2 — NOT rounded up to order 3`}</ExcelCode>

A fractional `N` is **truncated** toward zero, the same way `INT`
would handle it, not rounded to the nearest whole number. `2.7`
becomes order `2`, not order `3` — using order `3` instead would give
a noticeably different result (`0.1134` rather than `0.3299`).
