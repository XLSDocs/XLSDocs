Compute the sine of a complex number — the same trigonometric sine
function used everywhere else in Excel, extended so it also accepts
(and returns) complex numbers instead of just real ones.

## Return value

The sine of `inumber`, as text in `x + yi`/`x + yj` form.

## Description

For a complex number `x + yi`, IMSIN computes `sin(x)cosh(y) +
i·cos(x)sinh(y)` — the ordinary sine and cosine of the real part `x`,
combined with the hyperbolic cosine and sine of the imaginary part
`y`. This formula falls directly out of Euler's identity, the same
relationship [IMEXP](/docs/engineering/imexp) is built on. When `y` is
`0` (a purely real input), `cosh(0)=1` and `sinh(0)=0`, so the formula
collapses to exactly `sin(x)` — IMSIN never disagrees with the
ordinary `SIN` function on a real input.

<TryIt

  defaultValue="3+4i"

  fieldLabel="inumber"

`IMSIN("3+4i")` returns `3.8537-27.0168i` — a much larger magnitude
than any real sine could produce, since the imaginary part grows with
`sinh`, which isn't bounded like the real sine wave is. The pure
imaginary unit `"i"` gives exactly `sinh(1)i` (`1.1752i`), a clean
illustration of the identity `sin(iy) = i·sinh(y)`.

## Common errors

### #VALUE! — inumber is a logical value

<ExcelCode>{`IMSIN(TRUE) → #VALUE!`}</ExcelCode>

Passing `TRUE` or `FALSE` directly (rather than complex-number text)
returns `#VALUE!`.

### #NUM! — text that isn't a valid complex number

<ExcelCode>{`IMSIN("hello") → #NUM!`}</ExcelCode>

`inumber` has to be parseable as `x + yi`/`x + yj` text (or a plain
number). Text that doesn't match that pattern at all returns `#NUM!`.

### Expecting the result to stay bounded like real SIN does

<ExcelCode>{`IMSIN("3+4i") → 3.8537-27.0168i, nowhere near the [-1, 1] range real SIN is limited to`}</ExcelCode>

Ordinary `SIN` always returns a value between -1 and 1. IMSIN has no
such ceiling — the `sinh`/`cosh` terms grow rapidly with the size of
the imaginary part, so a complex sine can be an arbitrarily large
number.
