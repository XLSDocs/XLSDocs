Register a DLL or code resource that's already loaded and return its
register ID — a number that [CALL](/docs/engineering/call) can reuse
to invoke the same procedure repeatedly without re-specifying the
module and procedure each time. Unlike CALL, REGISTER.ID works on an
ordinary worksheet, not just an XLM macro sheet — though it's still a
legacy function with very narrow modern use.

## Return value

A number — the register ID for the specified procedure, which can be
passed as [CALL](/docs/engineering/call)'s first argument instead of
repeating `module_text`, `procedure`, and `type_text` on every call.

## Description

REGISTER.ID is the worksheet-callable half of the CALL/REGISTER
pair: it registers a DLL procedure once and hands back an ID, so a
workbook that calls the same external function many times doesn't
need to re-specify the module, procedure, and type code on every
single CALL. It's narrower than the standalone REGISTER macro
function — REGISTER.ID can't assign a custom function name or
argument names, only return the raw ID.

<ExcelCode>{`=REGISTER.ID("Kernel32", "GetTickCount", "J!") → a register ID for the GetTickCount DLL procedure`}</ExcelCode>

<Callout type="info">
  Excel for Windows and Excel for Mac use different kinds of code
  resources, so REGISTER.ID's exact arguments differ slightly by
  platform — on Mac, the equivalent form takes a file name, a
  resource name, and a type code rather than a Windows DLL name.
</Callout>

## Common errors

### #VALUE! — the DLL or procedure can't be found

<ExcelCode>{`REGISTER.ID("NotARealDll", "SomeFunction", "J") → #VALUE!`}</ExcelCode>

`module_text` and `procedure` need to match a DLL and exported
function that actually exist and are loadable on the current system.
