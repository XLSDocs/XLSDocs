Convert a hexadecimal number to binary — the reverse of `BIN2HEX`,
constrained by binary's much narrower 10-bit range even though
`number` itself can be a full 10-character hex value.

## Return value

The binary equivalent of `number`, as text — padded to `places`
characters if supplied and the result is positive.

## Description

HEX2BIN is more restrictive than `HEX2DEC` — while HEX2DEC accepts
any valid 10-character hex value (spanning the full 40-bit signed
range), HEX2BIN's *result* still has to fit inside binary's 10-bit
range, so `number` can only run from `FFFFFFFE00` (the hex form of
-512) up through `1FF` (511 in decimal).

<Callout type="warn">
  Passing a hex value that's perfectly valid for `HEX2DEC` but too
  large for 10-bit binary — say, `200` (decimal 512) — returns
  `#NUM!` here even though `HEX2DEC("200")` would happily return 512.
  The two functions don't share the same valid input range.
</Callout>

## Try it

<TryIt

  fieldLabel="number"
/>

`HEX2BIN(1A)` returns `11010` — the same value `DEC2BIN(26)` would
give. `HEX2BIN(FFFFFFFFFB)`, the 10-character two's-complement hex
form of -5, returns the full 10-character `1111111011`.

## Common errors

### #NUM! — number isn't valid hexadecimal, or is outside binary's range

<ExcelCode>{`HEX2BIN(200) → #NUM!, since 200 in hex is 512, outside binary's -512 to 511 range`}</ExcelCode>

`number` must be valid hex, at most 10 characters, and must resolve to
a value binary's own narrower range can actually hold.

### #NUM! — places is too small for the result

`places` must be large enough to hold every digit of the actual
result — it can only pad with extra leading zeros, never truncate.
