Convert a hexadecimal number to octal — the reverse of `OCT2HEX`,
constrained by octal's narrower 30-bit range even though `number`
itself can be a full 10-character hex value.

## Return value

The octal equivalent of `number`, as text — padded to `places`
characters if supplied and the result is positive.

## Description

Like `HEX2BIN`, HEX2OCT is more restrictive than `HEX2DEC` on its
input — even though a 10-character hex value can represent the full
40-bit signed range, HEX2OCT's *result* still has to fit inside
octal's narrower 30-bit range, limiting valid input to `FFE0000000`
(the hex form of -536,870,912) through `1FFFFFFF` (536,870,911 in
decimal).

<Callout type="idea">
  HEX2OCT is functionally identical to chaining `HEX2DEC` into
  `DEC2OCT` — it exists purely as a convenience so the intermediate
  decimal value never needs its own cell.
</Callout>

## Try it

<TryIt

`HEX2OCT(1A)` returns `32` — the same value `DEC2OCT(26)` would give.
`HEX2OCT(FFFFFFFFFB)`, the 10-character two's-complement hex form of
-5, returns the full 10-character `7777777773`.

## Common errors

### #NUM! — number isn't valid hexadecimal, or is outside octal's range

`number` must be valid hex, at most 10 characters, and must resolve to
a value octal's own narrower range can actually hold.

### #NUM! — places is too small for the result

`places` must be large enough to hold every digit of the actual
result — it can only pad with extra leading zeros, never truncate.
