Compute the base-10 (common) logarithm of a complex number — the same
value as [IMLN](/docs/engineering/imln), rescaled by a constant

## Return value

The base-10 logarithm of `inumber`, as text in `x + yi`/`x + yj` form.

## Description

IMLOG10 is [IMLN](/docs/engineering/imln)'s result divided by
`ln(10)` (about `2.302585`) — the standard change-of-base relationship
between natural and common logarithms, applied to both the real and
imaginary parts at once. For a **positive real** input, this matches
the ordinary `LOG10` function exactly.

## Try it

<TryIt

  defaultValue="3+4i"
  label={'Live preview — =IMLOG10("{value}")'}
  fieldLabel="inumber"

`IMLOG10("3+4i")` returns `0.699+0.4027i` — exactly
[IMLN](/docs/engineering/imln)'s `1.6094+0.9273i` divided by
`ln(10) ≈ 2.302585` in both the real and imaginary parts. The real
part, `0.699`, is recognizable as `log₁₀(5)`, since `5` is
[IMABS](/docs/engineering/imabs)'s value for the same input.

## Common errors

### #NUM! — inumber is exactly zero

<ExcelCode>{`IMLOG10("0") → #NUM!`}</ExcelCode>

The logarithm of `0` is undefined in any base — the same reason plain
`LOG10(0)` also returns `#NUM!`.

### #NUM! — text that isn't a valid complex number

<ExcelCode>{`IMLOG10("hello") → #NUM!`}</ExcelCode>

`inumber` has to be parseable as `x + yi`/`x + yj` text (or a plain
number). Text that doesn't match that pattern at all returns `#NUM!`.

### Expecting a negative real input to error, the way LOG10 does

<ExcelCode>{`IMLOG10(-4) → 0.6021+1.3644i, NOT #NUM! — unlike ordinary LOG10(-4)`}</ExcelCode>

Ordinary `LOG10` can't handle negative numbers and errors instead.
IMLOG10 inherits IMLN's ability to handle a negative real as a complex
number with an argument of `π`, so it returns a genuine complex answer
instead of erroring.
