Convert an octal number to binary — the reverse of `BIN2OCT`,
constrained by binary's narrower 10-bit range even though `number`
itself can be a full 10-character octal value.

## Return value

The binary equivalent of `number`, as text — padded to `places`
characters if supplied and the result is positive.

## Description

OCT2BIN is more restrictive than `OCT2DEC` on its input — while
OCT2DEC accepts any valid 10-character octal value (spanning the full
30-bit signed range), OCT2BIN's *result* still has to fit inside
binary's much narrower 10-bit range, so `number` can only run from
`7777777000` (the octal form of -512) up through `777` (511 in
decimal).

<Callout type="idea">
  Because 8 is 2 cubed, converting octal to binary is really just
  expanding each octal digit into its own 3-bit binary group —
  `OCT2BIN` does that expansion (and the two's-complement handling for
  negative values) in one step.
</Callout>

## Try it

<TryIt

  defaultValue="32"
  label={'Live preview — =OCT2BIN({number})'}
  fieldLabel="number"
/>

`OCT2BIN(32)` returns `11010` — the same value `DEC2BIN(26)` would
give. `OCT2BIN(7777777773)`, the 10-character two's-complement octal
form of -5, returns the full 10-character `1111111011`.

## Common errors

### #NUM! — number isn't valid octal, or is outside binary's range

`number` must be valid octal (digits 0-7 only), at most 10 characters,
and must resolve to a value binary's own narrower range can actually
hold.

### #NUM! — places is too small for the result

`places` must be large enough to hold every digit of the actual
result — it can only pad with extra leading zeros, never truncate.
