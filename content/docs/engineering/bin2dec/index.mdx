## Return value

The decimal equivalent of `number`.

## Description

BIN2DEC reads `number` as a base-2 (binary) value and returns the
equivalent base-10 (decimal) number. Binary numbers up to 9 digits are
always positive; a **full 10-digit** binary number is interpreted
using two's-complement notation, where the leftmost digit is a sign
bit — `1` means negative, `0` means positive.

<Callout type="warn">
  Two's complement means a 10-digit binary number that starts with `1`
  doesn't mean "make this number negative" the way a minus sign
  would — the whole 10-digit pattern together encodes the negative
  value. `1111111011` isn't "positive 111111011 with a negative
  flag" — it's the bit pattern for **-5**, and only resolves to that
  value as a complete 10-digit binary number.
</Callout>

## Try it

<TryIt
  data={{ '1000': '8', '11010': '26', '11111111': '255', '1111111011': '-5' }}
  defaultValue="11010"
  label={'Live preview — =BIN2DEC({number})'}
  fieldLabel="number"
/>

`BIN2DEC(11010)` returns 26 — an ordinary positive conversion.
`BIN2DEC(1111111011)`, a full 10-digit binary number starting with
`1`, returns **-5**, not a huge positive number — the two's-complement
sign bit changes how the whole pattern is read.

## Common errors

### #NUM! — number isn't valid binary, or has more than 10 digits

<ExcelCode>{`BIN2DEC(102) → #NUM!`}</ExcelCode>

`number` can only contain the digits `0` and `1`, and can be at most
10 digits long.

### Expecting a negative result from a leading 1 that isn't in a full 10-digit number

<ExcelCode>{`BIN2DEC(1010) → 10, not negative — only a FULL 10-digit binary number triggers two's-complement`}</ExcelCode>

A short binary number starting with `1` is still just an ordinary
positive value — the two's-complement sign-bit rule only applies once
the number reaches its full 10-digit width.
