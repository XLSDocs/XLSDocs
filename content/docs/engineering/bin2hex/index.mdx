Convert a binary number (up to 10 digits) directly to hexadecimal —
skipping a manual trip through decimal in between.

## Return value

The hexadecimal equivalent of `number`, as text — padded to `places`
characters if supplied and the result is positive.

## Description

BIN2HEX converts directly between two bases that don't naturally
align (base 2 and base 16), without needing a separate decimal step.
Like every function in this conversion family, a full 10-digit binary
input starting with `1` is read as a negative two's-complement value
— and in that case, `places` is ignored entirely, always returning a
fixed 10-character hexadecimal result.

<Callout type="idea">
  `BIN2HEX` is functionally identical to chaining `BIN2DEC` into
  `DEC2HEX` — it exists as a convenience so the intermediate decimal
  value never needs its own cell.
</Callout>

## Try it

<TryIt
  data={{ '1000': '8', '11010': '1A', '11111111': 'FF', '1111111011': 'FFFFFFFFFB' }}
  defaultValue="11010"
  label={'Live preview — =BIN2HEX({number})'}
  fieldLabel="number"
/>

`BIN2HEX(11010)` returns `1A` — the same value `DEC2HEX(26)` would
give, since `11010` in binary is 26 in decimal. `BIN2HEX(1111111011)`
returns a full 10-character `FFFFFFFFFB`, the two's-complement hex
representation of -5.

## Common errors

### #NUM! — number isn't valid binary, or has more than 10 digits

`number` can only contain the digits `0` and `1`, and can be at most
10 digits long.

### #NUM! — places is too small for the result

<ExcelCode>{`BIN2HEX(11111111, 1) → #NUM!, since "FF" needs 2 characters`}</ExcelCode>

`places` must be large enough to hold every digit of the actual
result — it can only pad with extra leading zeros, never truncate.
