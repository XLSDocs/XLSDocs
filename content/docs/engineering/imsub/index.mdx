## Return value

`inumber1` minus `inumber2`, as text in `x + yi`/`x + yj` form.

## Description

IMSUB subtracts complex numbers the way complex subtraction actually
works: real parts subtract from real parts, and imaginary parts
subtract from imaginary parts, independently — `(a + bi) - (c + di) =
(a-c) + (b-d)i`. Unlike [IMSUM](/docs/engineering/imsum), which
accepts up to 255 arguments, IMSUB only ever takes exactly two — order
matters here (`inumber1 - inumber2`), so there's no ambiguous way to
extend it to more terms.

<Callout type="warn">
  Both arguments must use the **same** suffix. `IMSUB("3+4i", "1-2j")`
  — one `i`, one `j` — returns `#VALUE!` rather than silently picking
  one convention.
</Callout>

`IMSUB("3+4i", "1-2i")` returns `2+6i` — the real parts `3` and `1`
subtract to `2`, and the imaginary parts `4` and `-2` subtract to `6`
(since subtracting a negative adds). Subtracting the pure imaginary
unit `"i"` only affects the imaginary side, giving `3+3i`.

## Common errors

### #VALUE! — mismatched suffixes across arguments

<ExcelCode>{`IMSUB("3+4i", "1-2j") → #VALUE! — one argument uses "i", the other uses "j"`}</ExcelCode>

Both complex numbers passed to IMSUB have to use the same suffix. Pick
one convention and stick with it throughout the calculation.

### #NUM! — an argument that isn't a valid complex number

<ExcelCode>{`IMSUB("3+4i", "hello") → #NUM!`}</ExcelCode>

Both arguments have to be parseable as `x + yi`/`x + yj` text (or a
plain number). Text that doesn't match that pattern at all returns
`#NUM!`.

### Getting the argument order backwards

<ExcelCode>{`IMSUB("1-2i", "3+4i") → -2-6i, the exact negative of IMSUB("3+4i", "1-2i")`}</ExcelCode>

Unlike addition, subtraction isn't order-independent — `inumber1 -
inumber2` and `inumber2 - inumber1` give exactly opposite results.
Double-check which complex number is meant to be the starting point.
