text in `x + yi` (or `x + yj`) form.

## Return value

`inumber1` divided by `inumber2`, as text in `x + yi`/`x + yj` form.

## Description

Dividing directly by a complex denominator isn't straightforward, so
IMDIV uses the standard trick: multiply both the numerator and
denominator by the denominator's
[complex conjugate](/docs/engineering/imconjugate). That turns the
denominator into a purely real number (`c² + d²`), leaving an ordinary
division to finish the job — `(a+bi)/(c+di) = [(ac+bd) + (bc-ad)i] /
(c²+d²)`.

<Callout type="warn">
  Dividing by **zero** (`"0"` or `"0+0i"`) returns `#NUM!`, the same
  way ordinary division by zero would — a zero denominator makes the
  `c² + d²` term in the conjugate trick zero too, which is exactly the
  undefined division the error is protecting against.
</Callout>

## Try it

<TryIt
  data={{ '1-2i': '-1+2i', '4-3i': 'i', '3+4i': '1' }}
  defaultValue="1-2i"
  label={'Live preview — =IMDIV("3+4i", "{value}")'}
  fieldLabel="inumber2"
/>

`IMDIV("3+4i", "1-2i")` returns `-1+2i`. Dividing `3+4i` by `4-3i`
lands on exactly `i` — since `i × (4-3i) = 4i - 3i² = 3+4i`, the
division undoes that multiplication cleanly. Dividing any complex
number by itself, unsurprisingly, always returns `1`.

## Common errors

### #NUM! — dividing by zero

<ExcelCode>{`IMDIV("3+4i", "0") → #NUM!`}</ExcelCode>

A zero divisor is undefined for complex division the same way it is
for ordinary division — Excel returns `#NUM!` instead of a value.

### #VALUE! — mismatched suffixes across arguments

<ExcelCode>{`IMDIV("3+4i", "1-2j") → #VALUE! — one argument uses "i", the other uses "j"`}</ExcelCode>

Both complex numbers passed to IMDIV have to use the same suffix.

### #NUM! — an argument that isn't a valid complex number

<ExcelCode>{`IMDIV("3+4i", "hello") → #NUM!`}</ExcelCode>

Both arguments have to be parseable as `x + yi`/`x + yj` text (or a
plain number). Text that doesn't match that pattern at all returns
`#NUM!`.

### Getting the argument order backwards

<ExcelCode>{`IMDIV("1-2i", "3+4i") is NOT the same as IMDIV("3+4i", "1-2i") — division isn't commutative`}</ExcelCode>

`inumber1` is always the numerator and `inumber2` is always the
denominator — swapping them gives the reciprocal-ish result, not the
same answer, just as with ordinary division.
