Compute the hyperbolic secant of a complex number — the reciprocal of
its [complex hyperbolic cosine](/docs/engineering/imcosh), the same
relationship that defines ordinary hyperbolic secant for real numbers.

## Return value

The hyperbolic secant of `inumber`, as text in `x + yi`/`x + yj` form.

## Description

IMSECH is the reciprocal of [IMCOSH](/docs/engineering/imcosh) — `1 /
IMCOSH(inumber)` — the same relationship real hyperbolic secant has to
real hyperbolic cosine. Since IMCOSH reduces to ordinary `COSH` on a
purely real input, IMSECH reduces to ordinary `SECH` there too.

## Try it

<TryIt
  data={{ '3+4i': '-0.0653+0.0752i', 'i': '1.8508', '1+i': '0.4983-0.5911i' }}
  defaultValue="3+4i"
  label={'Live preview — =IMSECH("{value}")'}
  fieldLabel="inumber"
/>

`IMSECH("3+4i")` returns `-0.0653+0.0752i`. The pure imaginary unit
`"i"` gives exactly `1/cos(1)` (`1.8508`) — a plain real number, since
IMCOSH itself returns a purely real value for a purely imaginary
input.

## Common errors

### #VALUE! — inumber is a logical value

<ExcelCode>{`IMSECH(TRUE) → #VALUE!`}</ExcelCode>

Passing `TRUE` or `FALSE` directly (rather than complex-number text)
returns `#VALUE!`.

### #NUM! — text that isn't a valid complex number

<ExcelCode>{`IMSECH("hello") → #NUM!`}</ExcelCode>

`inumber` has to be parseable as `x + yi`/`x + yj` text (or a plain
number). Text that doesn't match that pattern at all returns `#NUM!`.

### Confusing IMSECH with IMCSCH

<ExcelCode>{`IMSECH(z) = 1/IMCOSH(z), NOT 1/IMSINH(z) — that reciprocal is IMCSCH instead`}</ExcelCode>

Hyperbolic secant is the reciprocal of *hyperbolic cosine*, not
hyperbolic sine — the same naming mix-up that trips people up with
[IMSEC](/docs/engineering/imsec) and
[IMCSC](/docs/engineering/imcsc). The reciprocal of
[IMSINH](/docs/engineering/imsinh) is
[IMCSCH](/docs/engineering/imcsch), a different function entirely.
