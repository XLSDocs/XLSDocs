Convert a decimal number to binary — the reverse of `BIN2DEC`, limited
to the range a 10-digit binary number can actually represent.

## Return value

The binary equivalent of `number`, as text — padded to `places`
characters if supplied and `number` is positive.

## Description

DEC2BIN's valid range (-512 to 511) is deliberately narrow — it's
exactly what fits in a 10-bit two's-complement representation, the
same fixed width every function in this conversion family shares.
`places` lets a positive result be padded with leading zeros to a
consistent width (useful for lining up a column of binary values),
but it's silently ignored for a negative number, which always occupies
the full 10 characters regardless.

<Callout type="warn">
  DEC2BIN's range is asymmetric — it goes down to **-512** but only up
  to **511**, not -511 to 511. That's a direct consequence of two's
  complement: with 10 bits total and one reserved for sign, there are
  512 possible negative values (-512 through -1) but only 511 nonzero
  positive ones (1 through 511), plus zero.
</Callout>

## Try it

<TryIt
  data={{ '8': '1000', '26': '11010', '255': '11111111', '-5': '1111111011' }}

`DEC2BIN(26)` returns `11010`. `DEC2BIN(-5)` returns the full
10-character `1111111011` — the two's-complement binary
representation, not a minus sign followed by the binary form of 5.

## Common errors

### #NUM! — number is outside the -512 to 511 range

<ExcelCode>{`DEC2BIN(600) → #NUM!`}</ExcelCode>

`number` must fall within DEC2BIN's fixed 10-bit range.

### #NUM! — places is too small for the result

<ExcelCode>{`DEC2BIN(26, 3) → #NUM!, since "11010" already needs 5 characters`}</ExcelCode>

`places` must be large enough to hold every digit of the actual
result — it can only pad with extra leading zeros, never truncate.
