Compute the cosine of a complex number — the same trigonometric
cosine function used everywhere else in Excel, extended so it also
accepts (and returns) complex numbers instead of just real ones.

## Return value

The cosine of `inumber`, as text in `x + yi`/`x + yj` form.

## Description

For a complex number `x + yi`, IMCOS computes `cos(x)cosh(y) −
i·sin(x)sinh(y)` — the ordinary cosine and sine of the real part `x`,
combined with the hyperbolic cosine and sine of the imaginary part
`y`. When `y` is `0` (a purely real input), the formula collapses to
exactly `cos(x)`, so IMCOS never disagrees with the ordinary `COS`
function on a real input. Interestingly, feeding IMCOS a **purely
imaginary** number gives a purely real result: `cos(iy) = cosh(y)`,
with no imaginary part at all.

`IMCOS("3+4i")` returns `-27.0349-3.8512i`. The pure imaginary unit
`"i"` gives exactly `cosh(1)` — `1.5431`, with **no** imaginary
component at all, since `cos(iy) = cosh(y)` is always a real number
regardless of `y`.

## Common errors

### #VALUE! — inumber is a logical value

<ExcelCode>{`IMCOS(TRUE) → #VALUE!`}</ExcelCode>

Passing `TRUE` or `FALSE` directly (rather than complex-number text)
returns `#VALUE!`.

### #NUM! — text that isn't a valid complex number

<ExcelCode>{`IMCOS("hello") → #NUM!`}</ExcelCode>

`inumber` has to be parseable as `x + yi`/`x + yj` text (or a plain
number). Text that doesn't match that pattern at all returns `#NUM!`.

### Expecting a complex result from a purely imaginary input

<ExcelCode>{`IMCOS("i") → 1.5431, a plain real number with no "i" at all`}</ExcelCode>

It's easy to assume any complex-function call on an imaginary input
produces another complex number. `cos(iy)` is a special case that
always lands back on the real axis (`cosh(y)`) — the displayed result
correctly omits the imaginary term entirely rather than showing a
redundant `+0i`.
