Shift `number`'s binary digits left by `shift_amount` positions,
filling the vacated positions on the right with zeros — the same
operation as appending `shift_amount` zeros to the end of `number`'s
binary representation.

## Return value

`number` with its bits shifted left by `shift_amount` positions.

## Description

Shifting left is the same as appending `shift_amount` zeros to the
right of `number`'s binary form: `4` (`100` in binary) shifted left
by 2 becomes `10000`, which is 16 — the same result as multiplying by
`2^shift_amount`. A **negative** `shift_amount` reverses direction and
shifts right instead, producing the exact same result as calling
[BITRSHIFT](/docs/engineering/bitrshift) with the equivalent positive
amount.

<Callout type="warn">
  A shift can push the result **past** the 2^48-1 ceiling even when
  `number` and `shift_amount` are each individually valid on their
  own — Excel checks the *result*, not just the inputs. `BITLSHIFT(2^40,
  10)` would produce `2^50`, which exceeds 2^48-1, so it returns
  `#NUM!` even though `2^40` and `10` both pass their own individual
  range checks.
</Callout>

## Try it

<TryIt
  data={{ '1': '90', '2': '180', '-2': '11' }}
  defaultValue="2"
  label={'Live preview — =BITLSHIFT(45, {value})'}
  fieldLabel="shift_amount"
/>

45 is `101101` in binary. Shifting left by 1 appends a single zero
(`1011010` = **90**); shifting left by 2 appends two (`10110100` =
**180**). A shift_amount of **-2** reverses direction, stripping the
rightmost 2 digits instead (`1011` = **11**) — the exact same result
[BITRSHIFT](/docs/engineering/bitrshift) gives for a *positive*
shift of 2 on the same number.

## Common errors

### #NUM! — the shifted result exceeds 2^48-1

<ExcelCode>{`BITLSHIFT(2^40, 10) → #NUM! (the result would be 2^50, past the 2^48-1 ceiling)`}</ExcelCode>

Even a `number` and `shift_amount` that are each independently valid
can produce a result too large to represent — Excel returns `#NUM!`
in that case rather than a wrapped-around or truncated value.

### #NUM! — number negative/non-integer, or shift_amount's absolute value over 53

<ExcelCode>{`BITLSHIFT(45, 60) → #NUM! (60 exceeds the maximum shift_amount of 53)`}</ExcelCode>

`number` must be a non-negative integer, and `shift_amount`'s absolute
value can't exceed 53 — either violation returns `#NUM!`, independent
of the result-overflow check above.

### Forgetting a negative shift_amount reverses direction

<ExcelCode>{`BITLSHIFT(45, -2) → 11, not an error — a negative shift_amount shifts RIGHT`}</ExcelCode>

A negative `shift_amount` isn't invalid — it flips BITLSHIFT into a
right shift, identical to calling BITRSHIFT with the positive
equivalent. Don't assume a negative shift_amount is a mistake to
guard against.
