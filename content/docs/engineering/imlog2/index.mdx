## Return value

The base-2 logarithm of `inumber`, as text in `x + yi`/`x + yj` form.

## Description

IMLOG2 is [IMLN](/docs/engineering/imln)'s result divided by `ln(2)`
(about `0.693147`) — the standard change-of-base relationship between
natural and base-2 logarithms, applied to both the real and imaginary
parts at once. For a **positive real** input, this matches Excel's
general `LOG` function called with base `2` (`LOG(x, 2)`) exactly.

## Try it

<TryIt

  defaultValue="3+4i"
  label={'Live preview — =IMLOG2("{value}")'}
  fieldLabel="inumber"

`IMLOG2("3+4i")` returns `2.3219+1.3378i` — exactly
[IMLN](/docs/engineering/imln)'s `1.6094+0.9273i` divided by
`ln(2) ≈ 0.693147` in both the real and imaginary parts. The real
part, `2.3219`, is recognizable as `log₂(5)`, since `5` is
[IMABS](/docs/engineering/imabs)'s value for the same input.

## Common errors

### #NUM! — inumber is exactly zero

<ExcelCode>{`IMLOG2("0") → #NUM!`}</ExcelCode>

The logarithm of `0` is undefined in any base — the same reason
`LOG(0, 2)` also returns `#NUM!`.

### #NUM! — text that isn't a valid complex number

<ExcelCode>{`IMLOG2("hello") → #NUM!`}</ExcelCode>

`inumber` has to be parseable as `x + yi`/`x + yj` text (or a plain
number). Text that doesn't match that pattern at all returns `#NUM!`.

### Expecting a negative real input to error, the way LOG does

<ExcelCode>{`IMLOG2(-4) → 2+4.5324i, NOT #NUM! — unlike ordinary LOG(-4, 2)`}</ExcelCode>

Ordinary `LOG` can't handle negative numbers and errors instead.
IMLOG2 inherits IMLN's ability to handle a negative real as a complex
number with an argument of `π`, so it returns a genuine complex answer
instead of erroring — notice the real part, `2`, is exactly `log₂(4)`,
confirming the magnitude side of the calculation still works normally.
