Compute the cosecant of a complex number — the reciprocal of its
[complex sine](/docs/engineering/imsin), the same relationship that
defines ordinary cosecant for real numbers.

## Return value

The cosecant of `inumber`, as text in `x + yi`/`x + yj` form.

## Description

IMCSC is the reciprocal of [IMSIN](/docs/engineering/imsin) — `1 /
IMSIN(inumber)` — the same relationship real cosecant has to real
sine. Since IMSIN reduces to ordinary `SIN` on a purely real input,
IMCSC reduces to ordinary `CSC` there too.

## Try it

<TryIt
  data={{ '3+4i': '0.0052+0.0363i', 'i': '-0.8509i', '1+i': '0.6215-0.3039i' }}
  defaultValue="3+4i"
  label={'Live preview — =IMCSC("{value}")'}
  fieldLabel="inumber"
/>

`IMCSC("3+4i")` returns `0.0052+0.0363i`. The pure imaginary unit
`"i"` gives exactly `-1/sinh(1)` in the imaginary slot (`-0.8509i`),
since IMSIN itself returns a purely imaginary value for a purely
imaginary input, and dividing `1` by a purely imaginary number gives
another purely imaginary result.

## Common errors

### #NUM! — inumber is exactly zero

<ExcelCode>{`IMCSC("0") → #NUM!`}</ExcelCode>

At `0`, the complex sine (IMCSC's denominator) is exactly `0`, making
the reciprocal undefined — the same way ordinary `CSC(0)` also returns
`#DIV/0!`. Since `0` can be entered exactly, this case genuinely comes
up in practice.

### #VALUE! — inumber is a logical value

<ExcelCode>{`IMCSC(TRUE) → #VALUE!`}</ExcelCode>

Passing `TRUE` or `FALSE` directly (rather than complex-number text)
returns `#VALUE!`.

### Confusing IMCSC with IMSEC

<ExcelCode>{`IMCSC(z) = 1/IMSIN(z), NOT 1/IMCOS(z) — that reciprocal is IMSEC instead`}</ExcelCode>

Cosecant is the reciprocal of *sine*, not cosine — a common mix-up
given how similar the names "cosecant" and "secant" look at a glance.
The reciprocal of [IMCOS](/docs/engineering/imcos) is
[IMSEC](/docs/engineering/imsec), a different function entirely.
