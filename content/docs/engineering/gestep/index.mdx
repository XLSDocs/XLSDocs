Test whether `number` is greater than or equal to `step`, returning
`1` if so and `0` if not — a plain numeric 1-or-0 flag, rather than
the `TRUE`/`FALSE` an ordinary `>=` comparison would give.

## Return value

`1` if `number` is greater than or equal to `step`; `0` otherwise.

## Description

GESTEP does exactly what the ordinary `>=` comparison operator does,
except it returns a genuine **number** (`1` or `0`) instead of a
boolean (`TRUE`/`FALSE`) — the same relationship
[DELTA](/docs/engineering/delta) has to a plain `=` comparison. That
makes it directly usable in arithmetic: summing `GESTEP` across a
range counts how many values clear a given threshold, without an
extra step to coerce `TRUE`/`FALSE` into addable numbers.

## Try it

<TryIt
  data={{ '4': '1', '5': '1', '6': '0' }}
  defaultValue="4"
  label={'Live preview — =GESTEP(5, {value})'}
  fieldLabel="step"
/>

`GESTEP(5, 4)` returns `1` — `5` clears the threshold of `4`.
`GESTEP(5, 5)` also returns `1`, since "greater than or **equal to**"
includes an exact match. Only `GESTEP(5, 6)` returns `0`, since `5`
falls short of `6`.

## Common errors

### #VALUE! — number or step is nonnumeric

<ExcelCode>{`GESTEP("x", 5) → #VALUE!`}</ExcelCode>

Both arguments must be actual numbers — text that can't be interpreted
as one returns `#VALUE!`.

### Forgetting step defaults to 0, not to number

<ExcelCode>{`GESTEP(-1) → 0, the same as GESTEP(-1, 0) — testing against zero, not against itself`}</ExcelCode>

Omitting `step` doesn't skip the comparison — it compares `number`
against `0`. `GESTEP(-1)` checks whether `-1` is non-negative, which
it isn't, so the result is `0`.

### Expecting a strict "greater than," not "greater than or equal to"

<ExcelCode>{`GESTEP(5, 5) → 1, not 0 — an exact match still counts`}</ExcelCode>

The "GE" in GESTEP stands for "greater than or **equal to**" — a value
exactly at the threshold still returns `1`, not `0`. A strict
greater-than test would need an extra adjustment, like comparing
against a step value nudged slightly higher.
