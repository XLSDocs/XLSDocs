Compute the hyperbolic cosecant of a complex number — the reciprocal
of its [complex hyperbolic sine](/docs/engineering/imsinh), the same
relationship that defines ordinary hyperbolic cosecant for real
numbers.

## Return value

The hyperbolic cosecant of `inumber`, as text in `x + yi`/`x + yj`
form.

## Description

IMCSCH is the reciprocal of [IMSINH](/docs/engineering/imsinh) — `1 /
IMSINH(inumber)` — the same relationship real hyperbolic cosecant has
to real hyperbolic sine. Since IMSINH reduces to ordinary `SINH` on a
purely real input, IMCSCH reduces to ordinary `CSCH` there too.

## Try it

<TryIt
  data={{ '3+4i': '-0.0649+0.0755i', 'i': '-1.1884i', '1+i': '0.3039-0.6215i' }}
  defaultValue="3+4i"
  label={'Live preview — =IMCSCH("{value}")'}
  fieldLabel="inumber"
/>

`IMCSCH("3+4i")` returns `-0.0649+0.0755i`. The pure imaginary unit
`"i"` gives exactly `-1/sin(1)` in the imaginary slot (`-1.1884i`),
since IMSINH itself returns a purely imaginary value for a purely
imaginary input.

## Common errors

### #NUM! — inumber is exactly zero

<ExcelCode>{`IMCSCH("0") → #NUM!`}</ExcelCode>

At `0`, the complex hyperbolic sine (IMCSCH's denominator) is exactly
`0`, making the reciprocal undefined — the same way ordinary
`CSCH(0)` also returns `#DIV/0!`. Since `0` can be entered exactly,
this case genuinely comes up in practice.

### #VALUE! — inumber is a logical value

<ExcelCode>{`IMCSCH(TRUE) → #VALUE!`}</ExcelCode>

Passing `TRUE` or `FALSE` directly (rather than complex-number text)
returns `#VALUE!`.

### Confusing IMCSCH with IMSECH

<ExcelCode>{`IMCSCH(z) = 1/IMSINH(z), NOT 1/IMCOSH(z) — that reciprocal is IMSECH instead`}</ExcelCode>

Hyperbolic cosecant is the reciprocal of *hyperbolic sine*, not
hyperbolic cosine — the same naming mix-up that trips people up with
[IMCSC](/docs/engineering/imcsc) and
[IMSEC](/docs/engineering/imsec). The reciprocal of
[IMCOSH](/docs/engineering/imcosh) is
[IMSECH](/docs/engineering/imsech), a different function entirely.
