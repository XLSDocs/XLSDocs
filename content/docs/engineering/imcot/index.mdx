Compute the cotangent of a complex number — the ratio of its
[complex cosine](/docs/engineering/imcos) to its
[complex sine](/docs/engineering/imsin), the reciprocal of
[IMTAN](/docs/engineering/imtan).

## Return value

The cotangent of `inumber`, as text in `x + yi`/`x + yj` form.

## Description

IMCOT divides the complex cosine of `inumber` by its complex sine —
equivalently, `1 / IMTAN(inumber)`. Since both
[IMCOS](/docs/engineering/imcos) and
[IMSIN](/docs/engineering/imsin) reduce to their ordinary real
versions on a purely real input, IMCOT does too — `IMCOT(1)` and
`COT(1)` agree exactly.

`IMCOT("3+4i")` returns `-0.0002-1.0006i` — the reciprocal-ish
relationship with `IMTAN("3+4i")` (`-0.0002+0.9994i`) is visible in
how close both values sit to `±i`. The pure imaginary unit `"i"` gives
exactly `-coth(1)i` (`-1.313i`).

## Common errors

### #NUM! — inumber is exactly zero

<ExcelCode>{`IMCOT("0") → #NUM!`}</ExcelCode>

At `0`, the complex sine (IMCOT's denominator) is exactly `0`, making
the division undefined — the same way ordinary `COT(0)` also returns
`#DIV/0!`. Since `0` (unlike an irrational value such as `π`) can be
entered exactly, this case genuinely comes up in practice, unlike the
similar-sounding undefined point for [IMTAN](/docs/engineering/imtan).

### #VALUE! — inumber is a logical value

<ExcelCode>{`IMCOT(TRUE) → #VALUE!`}</ExcelCode>

Passing `TRUE` or `FALSE` directly (rather than complex-number text)
returns `#VALUE!`.

### #NUM! — text that isn't a valid complex number

<ExcelCode>{`IMCOT("hello") → #NUM!`}</ExcelCode>

`inumber` has to be parseable as `x + yi`/`x + yj` text (or a plain
number). Text that doesn't match that pattern at all returns `#NUM!`.
